# 案例 01：空泛闭环句改成可操作步骤

来源：`docs/maintenance/WRITING-STANDARD.md` 的「不采用的写法」与「采用的写法」对照。

## 粗稿

依据技术栈核对部署边界，联结Web配置、后端运行时和数据层，形成环境恢复与证据验证闭环。

## 考点清单

1. 网站打不开时，先判断源码是什么项目。
2. 看到 `index.php`，继续确认 PHP 版本和框架。
3. 看到 JAR，先读原启动命令，不配置 PHP。
4. `package.json` 只说明用了 Node 相关工具，还要确认它是后端服务还是只用于构建静态页面。
5. 读原 Web 配置，看域名、监听端口、网站目录和代理目标。
6. 先访问恢复副本的 IP 与实际端口。
7. 能打开正确站点就继续；进了欢迎页或其他站点，再检查域名匹配，不先改 hosts。
8. 保留分支前提：只有确认是 PHP 网站才写“恢复 PHP”。

## 参考定稿

**网站打不开，先看源码是什么项目。**

打开网站目录，先找入口和依赖文件。看到`index.php`，继续确认PHP版本和框架；看到JAR，先读原启动命令，不去配置PHP。`package.json`只说明用了Node相关工具，还要确认它是后端服务，还是只用于构建静态页面。

接着读原Web配置，看域名、监听端口、网站目录和代理目标。先尝试访问恢复副本的IP与实际端口：能打开正确站点就继续；进了欢迎页或其他站点，再检查域名匹配，不一上来就要求改hosts。
