# 写作能力回归集

用来验证"改写能力有没有变好"，而不是验证站点能不能构建。每次改动 persona、写作技能、术语表或 lint 规则后，用同一批粗稿重跑一次，比较三项人工指标。

## 用法

1. 从 `cases/` 取一篇，只把 `## 粗稿` 一节交给维护代理，附一句：按 `ctf-atlas-writing` 技能改写，保留考点清单里的全部内容。
2. 不看 `## 参考定稿`，让代理独立产出。
3. 按下面的评分表人工核对，把结果追加到该案例的 `## 评分记录`。

## 三项指标

| 指标 | 怎么算 | 目标 |
|---|---|---|
| 考点保留率 | 定稿覆盖的考点数 ÷ 清单考点数 | 100%，少一个就算退回 |
| 空话数 | 出现"进行检查、相关操作、形成闭环"等空转表达的句子数 | 0 |
| 命令完整率 | 可直接复制执行的命令块数 ÷ 命令块总数 | 100%，出现 `...`、`<payload>`、"略"即扣分 |

## 辅助检查

```powershell
py -V:3.12 -X utf8 scripts/lint_writing.py --paths tests/writing-regression --wide
```

粗稿不一定命中 lint：规则只覆盖可机器判定的部分，案例 02 的粗稿只有一句空泛结论，不含规则词。参考定稿段落应当不命中高置信规则（文件标题的 `h1` 除外）。命中数只作参考，最终以三项人工指标为准。

## 新增案例

- 每个案例一个文件，包含 `## 粗稿`、`## 考点清单`、`## 参考定稿`、`## 评分记录` 四节。
- 粗稿必须来自真实材料：被退回的旧稿、`WRITING-STANDARD.md` 的反例，或现有文章的早期版本。不要凭空编造。
- 参考定稿必须是用户已认可或项目规范明确采用的写法。
- 案例覆盖不同文体：概念解释、操作步骤、排错分支、工具页各至少一篇。
