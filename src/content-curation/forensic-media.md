## 01 分离容器、编码流与元数据层

图像、音频与视频取证先记录原件、缩略图、预览图与转码件各自的 SHA-256、字节大小及来源路径，结合文件头魔数、容器结构与解码输出判断真实格式：

| 检查层次 | 图像文件（PNG/JPEG/GIF/WEBP/HEIC） | 音频与视频（MP4/MKV/AVI/WAV/MP3） |
| --- | --- | --- |
| 容器与块结构 | 文件头、块/段边界（如 `IHDR`/`IDAT`/`IEND`、`SOI`/`EOI`）、宽高尺寸与文件尾附加数据 | 顶层 box/chunk（如 `ftyp`/`moov`/`mdat`）、轨道索引、采样偏移与时长 |
| 编码与数据流 | 像素矩阵、颜色通道、调色板、帧序列与压缩参数 | 视频帧率、关键帧（GOP）、音频采样率、声道、频谱与帧间连续性 |
| 内嵌元数据 | EXIF 拍摄时间、相机型号、方向、GPS 坐标、缩略图与软件标记 | 容器创建时间（如 `mvhd`）、音视频流编码器标记、地理位置与章节 |
| 外部关联证据 | 相册数据库、聊天附件表、缓存目录与文件系统时间戳 | 录制日志、播放器缓存、消息发送时间与服务端上传记录 |

在工作副本上同时使用 `exiftool` 与 `ffprobe` 分别提取元数据分组和容器流信息（单方报错时记录具体字节偏移与错误提示）：

```bash
sha256sum media.bin
file media.bin
xxd -l 64 media.bin
exiftool -a -G1 -s media.bin
ffprobe -v error -show_format -show_streams media.bin
```

`exiftool -a -G1` 显示所有重复标签及其所属元数据组（文件系统、EXIF、QuickTime 等），`ffprobe` 则校验容器与编码流。必须把“文件内嵌某项 EXIF/容器时间或 GPS 坐标”与“真实拍摄时刻或地点”分开表述——内嵌元数据可被手工修改，而社交平台自动压缩转码也会重写容器时间与编码参数。

## 02 实战：核对媒体时间与文件完整性

**场景与材料：** 获得一个视频文件及相关聊天附件记录，需要判断视频结构是否完整、其时间字段能否用于还原发送过程。

1. 对原件、聊天导出件和预览/转码件分别记录路径、大小、哈希，建立生成关系；相同文件名不能替代内容比对。
2. 用本页 `ffprobe` 保存容器、流、索引、时长与编码信息；用 `exiftool` 分组读取时间和软件标记。分别注明字段位于文件系统、容器还是媒体元数据层。
3. 对无法完整解码或有异常帧序列的范围，保存流号、帧号、时间点和报错。播放器能播放开头不能证明所有帧完整。
4. 将时间字段与设备时区、聊天记录时间和上传记录关联。软件标记或分辨率变化可提示处理过程，但平台自动转码同样可能形成这些变化。

**示例判读：** 视频容器记录的创建时间早于聊天发送时间，这并不矛盾；一个描述文件内部元数据，另一个描述通信事件。只有时间字段来源与时区均核对后，才能把它们放入同一时间表。

**验证结果：** 同时记录结构可读性、解码覆盖范围、元数据含义、内容匹配与活动印证。EXIF GPS、创建时间或编辑软件标签不能独立证明拍摄地点、人物活动或人为剪辑意图。
