NTFS 用一张主文件表描述文件。可移动介质上的主机接入痕迹仍在[U盘取证](/knowledge/forensic-usb-evidence/)。这里只处理卷内的记录、时间、数据流和删除。分区起点和扇区单位见[卷与引导扇区](/knowledge/forensic-fs-volume/)。下面的记录号都要换成 `fls` 的实际输出。原始镜像只读。

## 01 从引导扇区找到主文件表

引导扇区在卷的第 0 扇区。多字节整数都是小端。

| 偏移 | 长度 | 字段 |
| --- | ---: | --- |
| `0x0B` | 2 | 每扇区字节数 |
| `0x0D` | 1 | 每簇扇区数 |
| `0x28` | 8 | 卷总扇区数 |
| `0x30` | 8 | `$MFT` 起始簇号 LCN |
| `0x38` | 8 | `$MFTMirr` 起始簇号 |
| `0x40` | 1 | 文件记录大小，有符号单字节 |
| `0x44` | 1 | 索引块大小，有符号单字节 |
| `0x48` | 8 | 卷序列号 |
| `0x1FE` | 2 | `55 AA` |

簇大小等于每扇区字节乘以每簇扇区。`$MFT` 在卷内的字节起点等于它的 LCN 乘以簇大小。整盘镜像还要加上分区字节起点。

偏移 `0x40` 和 `0x44` 都是一个有符号单字节。最高位为 1 时，它是负数，实际字节数是 2 的绝对值次方。`0xF6` 等于 -10，字节数是 1024。最高位为 0 时，它是正数，实际字节数等于该值乘以每簇字节数。4KB 簇的卷上，偏移 `0x44` 处常见 `0x01`，索引块是 1 乘 4096，也就是 4096 字节。把这个 `0x01` 当成 2 的 1 次方，目录索引会全部错位。

卷序列号是 8 字节。快捷方式里的盘序列号只有低 32 位，对照时取前 4 个小端字节。它不是 U 盘硬件序列号。`$MFTMirr` 通常只保存前 4 条记录，以它自己的逻辑长度为准。它不是整张表的备份。

引导扇区被抹掉时，按卷与引导扇区那一页用连续的 `FILE` 条数区分主表和镜像，再用记录 0 的 runlist 核对 LCN。

## 02 读一条 FILE 记录

第 n 条记录在 `$MFT` 这个文件的逻辑流里，偏移是 n 乘以记录大小。`$MFT` 自己的 `$DATA` 可能有多段 run。只有确认第 n 条落在连续的那一段里，才能把这个偏移换成卷起点加第一段物理起点。`icat -o "$start" disk.dd 0` 会按 runlist 导出整张表。

| 偏移 | 长度 | 含义 |
| --- | ---: | --- |
| `0x00` | 4 | `FILE`，字节 `46 49 4C 45`。损坏时可能是 `BAAD` |
| `0x04` | 2 | 更新序列数组的起点 |
| `0x06` | 2 | 数组里有多少个 16 位字，包含第一个更新序列值 |
| `0x08` | 8 | `$LogFile` 序列号，不是时间，也不是文件序列号 |
| `0x10` | 2 | 本记录的序列号 |
| `0x12` | 2 | 硬链接计数 |
| `0x14` | 2 | 第一条属性的偏移，不要假设总是 `0x38` |
| `0x16` | 2 | `0x0001` 正在使用；`0x0002` 表示这是目录 |
| `0x18` | 4 | 本记录已用字节。这是槽里的用量，不是文件大小 |
| `0x1C` | 4 | 记录槽分配长度，应等于记录大小 |
| `0x20` | 8 | 基础记录引用。0 表示自己就是基础记录 |
| `0x2C` | 4 | NTFS 3.1 的记录号 |

文件引用是 8 字节：低 48 位是记录号，高 16 位是序列号。字节 `2A 00 00 00 00 00 07 00` 是记录 42、序列 7。目录里留着这个引用，而槽 42 现在的序列号已经是 8，当前槽里的内容属于新文件。这个连字符只写在笔记里。Sleuth Kit 地址里的连字符是另一套，见第 07 节。

读属性之前，在副本上做 fixup。1024 字节记录、512 字节扇区时，数组个数常见是 3。检查偏移 `0x1FE` 和 `0x3FE` 都等于更新序列值，再把后两个保存字放回去。对不上就先停。工具若已经修复过，不要再修一次。更新序列值不是 `$UsnJrnl` 里的 USN。

| 记录 | 名字 | 用途 |
| ---: | --- | --- |
| 0 | `$MFT` | 整张表 |
| 1 | `$MFTMirr` | 开头几条的副本 |
| 2 | `$LogFile` | 元数据事务日志，不是用户操作流水 |
| 5 | 根目录 | 目录树起点 |
| 6 | `$Bitmap` | 哪些簇当前已分配 |
| 8 | `$BadClus` | 坏簇 |
| 11 | `$Extend` | `$UsnJrnl` 等扩展对象的父目录 |

12 到 15 不要猜成用户文件。`$UsnJrnl` 的记录号每卷不同。三张位图不能混：`$MFT` 自己的 `$BITMAP` 标记记录槽，记录 6 标记簇，目录上的 `$BITMAP` 标记索引块。

## 03 属性头

属性一条接一条存放。下一条的起点等于当前属性起点加上偏移 `0x04` 的总长度。总长度含头部、名字、值和 8 字节对齐填充。类型 `FF FF FF FF` 是结束标记。下面的偏移都相对当前这条属性的起点。

| 偏移 | 长度 | 适用范围 | 字段 |
| --- | ---: | --- | --- |
| `0x00` | 4 | 公共 | 类型。`10 00 00 00` 是 `$STANDARD_INFORMATION`，`30 00 00 00` 是 `$FILE_NAME`，`80 00 00 00` 是 `$DATA` |
| `0x04` | 4 | 公共 | 本属性总字节数 |
| `0x08` | 1 | 公共 | `0x00` 常驻，`0x01` 非驻留 |
| `0x09` | 1 | 公共 | 属性名的 UTF-16 字符数。0 表示无名默认流；在 `$DATA` 上大于 0 就是备用数据流 |
| `0x0A` | 2 | 公共 | 属性名相对本属性头的偏移 |
| `0x0C` | 2 | 公共 | `01 00` 表示压缩，`00 40` 表示加密，`00 80` 表示稀疏 |
| `0x0E` | 2 | 公共 | 属性 ID |
| `0x10` | 4 | 仅常驻 | 常驻内容的字节长度 |
| `0x14` | 2 | 仅常驻 | 内容相对本属性头的偏移 |
| `0x10` | 8 | 仅非驻留 | 起始 VCN |
| `0x18` | 8 | 仅非驻留 | 结束 VCN，包含本号 |
| `0x20` | 2 | 仅非驻留 | runlist 相对本属性头的偏移。无名流常见是 `0x40` |
| `0x22` | 1 | 仅非驻留 | 压缩单元的 2 的指数。后面 5 字节是填充 |
| `0x28` | 8 | 仅非驻留 | 分配大小，按簇对齐 |
| `0x30` | 8 | 仅非驻留 | 逻辑大小。文件导出到这个字节为止 |
| `0x38` | 8 | 仅非驻留 | 初始化大小。从这里到逻辑大小之间，按文件系统读出来是 0 |

常驻内容就在记录里面。小文本经常整份躺在 `$MFT` 中，对未分配簇雕刻会漏掉。没有外部簇，只说明它是常驻，不说明内容丢失。

一条常驻 `$DATA` 的例子，只看属性自己的字节：

```text
80 00 00 00
20 00 00 00
00 00 18 00 00 00 01 00
04 00 00 00
18 00 00 00
66 6C 61 67
```

总长度是 `0x20`。偏移 `0x08` 为 0，所以是常驻。内容长度 4，内容偏移 `0x18`，4 字节是 `66 6C 61 67`。总长度比内容末尾多出的字节是对齐填充，不要收进文件。

无名 `$DATA` 是默认内容。属性头里另有名字的 `$DATA` 是备用数据流。`Zone.Identifier` 记录从网络下载的区域。多个 `$DATA` 仍然是同一个文件。逻辑大小是要导出的文件。分配大小多出来的簇尾是 slack，可以另存，不能拼到文件后面。

## 04 runlist 的手算和拼接

VCN 是这条流内部的簇序号。LCN 是当前 NTFS 卷的簇号，卷首是 0。run 的第一个字节，低 4 位是“簇个数”的字节数，高 4 位是“LCN 位移”的字节数。簇个数是无符号小端。位移是有符号小端。第一段有物理位置的位移就是它的起始 LCN；后面的位移加上前一段的起始 LCN，不是加上前一段的结束簇。高 4 位为 0 表示这段没有物理簇，读出来是 0。首字节 `00` 结束。

镜像上的字节等于卷在镜像中的字节起点，加上 LCN 乘以每簇字节数。按 VCN 从小到大输出，不要按 LCN 排序。

例子：逻辑大小 10000 字节，每簇 4096 字节，分区字节起点 1048576（扇区 2048）。已经做完 fixup 的无名 `$DATA` 里，偏移 `0x30` 是 `10 27 00 00 00 00 00 00`，偏移 `0x20` 指向下面 8 字节：

```text
21 02 00 05 11 01 F0 00
```

第 1 段 `21 02 00 05`：低 4 位是 1，簇数 `0x02` 是 2 簇，共 8192 字节。高 4 位是 2，位移 `00 05` 是 `0x0500`，也就是 1280。这是第一段，LCN 就是 1280。

第 2 段 `11 01 F0`：簇数 `0x01` 是 1 簇，共 4096 字节。位移 `0xF0` 是有符号数，240 减 256 等于 -16。LCN 等于 1280 加 -16，也就是 1264。若误加到前一段的结束簇，会得到 1266，整段就错了。最后的 `00` 结束。两段一共 12288 字节，逻辑大小只要前 10000 字节。

分区起点换算成 4096 字节块是 1048576 除以 4096，等于 256。按 VCN 顺序先读 1280，再读 1264：

```bash
{
  dd if=disk.dd bs=4096 skip=$((256 + 1280)) count=2 status=none
  dd if=disk.dd bs=4096 skip=$((256 + 1264)) count=1 status=none
} | head -c 10000 > ./work/reassembled.bin
wc -c ./work/reassembled.bin
file ./work/reassembled.bin
```

`wc -c` 应是 10000。`head` 提前关掉管道时，`dd` 可能报写入中断，只要输出长度正确就继续核验文件格式。压缩和加密要按偏移 `0x0C` 的标志还原，不能把没有物理簇的那段补零当成解压结果。

## 05 两套时间

`$STANDARD_INFORMATION` 和 `$FILE_NAME` 都有四个 8 字节 FILETIME：从 `1601-01-01 00:00:00 UTC` 起的 100 纳秒计数。先找到常驻属性的值起点，再加下表的偏移。

| 含义 | `$STANDARD_INFORMATION` | `$FILE_NAME` |
| --- | --- | --- |
| 创建 | `0x00` | `0x08` |
| 内容修改 | `0x08` | `0x10` |
| 元数据修改 | `0x10` | `0x18` |
| 访问 | `0x18` | `0x20` |

字节 `00 C0 89 76 45 3C DA 01` 是 `2024-01-01 00:00:00 UTC`。换算时用整数除以 10000000，余数保留。显示北京时间时标明 UTC+8。前一组是资源管理器显示的时间。后一组挂在文件名上，改名和创建会更新它。两组都保留。访问时间可能延迟写回，不能单独当成最后一次打开。

`$FILE_NAME` 值的其余字段：偏移 0 是父目录的 8 字节文件引用；偏移 `0x28` 和 `0x30` 是当时抄下的大小，不能代替 `$DATA` 的逻辑大小；偏移 `0x40` 是名字字符数；偏移 `0x41` 是名字空间；偏移 `0x42` 起是 UTF-16LE 名字。Win32 长名和 DOS 短名是两个 `$FILE_NAME`，仍然是同一个文件。硬链接是多个名字共用同一条数据流，链接计数大于 1，并且必须在同一卷。

## 06 删除和回收站

目录用名为 `$I30` 的索引保存子项。小目录只在 `$INDEX_ROOT`；大目录还有签名 `INDX` 的索引块，同样有 fixup。删除后，当前索引项去掉，旧名字可能留在索引块空隙里。空隙里的名字是残留，不要直接并进当前目录。

删除时，记录头的在用位清零，`$MFT` 的位图把槽标成空闲，卷位图把数据簇标成空闲。槽里的名字和 runlist 经常还在。簇内容要等重新分配，或闪存执行了 TRIM，才会消失。快速格式化会新建引导区和一份新的 `$MFT`。旧记录若还在，必须用格式化之前的簇大小和旧的 MFT 位置来读。

回收站在 `$Recycle.Bin` 的用户 SID 目录下。同一组随机名的 `$I` 是元数据，`$R` 是内容。可移动介质上的删除经常不进回收站。`$I` 里的时间是丢进回收站的时间。更早的系统用 `RECYCLER` 里的 `INFO2`，不是下面这张表。版本号是偏移 0 的 8 字节小端整数。

| 偏移 | 长度 | 版本 1 | 版本 2 |
| --- | ---: | --- | --- |
| `0x00` | 8 | `01 00 00 00 00 00 00 00` | `02 00 00 00 00 00 00 00` |
| `0x08` | 8 | 原文件逻辑大小 | 原文件逻辑大小 |
| `0x10` | 8 | 删除时间，FILETIME，UTC | 删除时间，FILETIME，UTC |
| `0x18` | 520 或 4 | 固定 520 字节 UTF-16LE 路径 | 4 字节路径字符数 |
| `0x1C` | 字符数的两倍 | 仍属于上面的 520 字节 | 变长 UTF-16LE 路径 |

版本 2 的例子：版本号 2，原大小 120，删除时间是上一节那 8 字节，路径 `D:\notes.txt` 共 12 个 UTF-16 字符。从偏移 `0x1C` 取 24 字节。若路径断在半个字符上，回到镜像确认长度字段的单位；当前这份布局按字符数解释。

## 07 实战：导出数据流、主文件表和 USN

`fls` 行首的 `r/r` 表示普通文件且名字仍在使用，`r/*` 表示这个名字已删除。NTFS 的地址是三段：记录号、属性类型、属性 ID。`128` 是 `0x80`，也就是 `$DATA`。`49-128-2` 表示记录 49 的某个数据流。它不是记录 49、序列号 128。

```bash
start=2048
fsstat -o "$start" disk.dd
fls -r -p -o "$start" disk.dd
fls -r -d -p -o "$start" disk.dd
istat -o "$start" disk.dd 49
icat -o "$start" disk.dd '49-128-2' > ./work/stream.bin
ffind -o "$start" disk.dd 49
file ./work/stream.bin && sha256sum ./work/stream.bin
```

`istat 49` 的输出里核对序列号、在用位、两套时间和 run。序列号是 7，就在笔记里写记录 49、序列 7，不要把命令改成把 7 放在第二段。导出长度要等于逻辑大小。带冒号的名字是备用流，把 `fls` 给出的整段地址交给 `icat`。

```bash
icat -o "$start" disk.dd 0 > ./work/MFT.raw
fls -o "$start" disk.dd 11
icat -o "$start" disk.dd '68-128-3' > ./work/UsnJrnl_J.raw
sha256sum ./work/MFT.raw ./work/UsnJrnl_J.raw
```

第二行的 `68-128-3` 只是占位，必须换成 `fls` 在记录 11 下面打印的 `$UsnJrnl` 数据流地址。记录 11 下面没有这项，说明这个卷没启用或日志已经空了，不要编一份。`icat 0` 走的是记录 0 的 runlist，不要只切第一个簇。

MFTECmd 在 Windows 上运行。`--at` 让文件名属性的四列时间始终写出来。`--dr` 把常驻内容导出到输出目录下的 `Resident`。

```powershell
& .\MFTECmd.exe -f '.\work\MFT.raw' --csv '.\work\mft_out' --csvf mft.csv --at --dr
& .\MFTECmd.exe -f '.\work\UsnJrnl_J.raw' -m '.\work\MFT.raw' --csv '.\work\mft_out' --csvf usn.csv
```

| CSV 列 | 怎么读 |
| --- | --- |
| `EntryNumber` 和 `SequenceNumber` | 记录号和序列号，两个一起才能对应文件引用 |
| `InUse` | 真表示仍在使用；假是已删除候选，不表示内容一定还在 |
| `ParentPath` 和 `FileName` | 由还能连上的父记录重建的路径 |
| `FileSize` | 逻辑大小 |
| `IsAds` | 这一行是不是备用流 |
| 带 `0x10` 的时间列 | `$STANDARD_INFORMATION`，UTC |
| 带 `0x30` 的时间列 | `$FILE_NAME`，UTC |
| `ZoneIdContents` | 有下载区域流时，这里能看到来源 |

USN 能帮助看创建、覆盖、扩展、改名、删除和关闭。它不记录复制来源路径，也不直接记录操作者。先看 `Resident` 目录和 CSV 是否非空；这个程序有时退出码仍是 0。

若配合图形界面复核，可按以下入口对照：在 X-Ways 中通过 `File -> Open Image` 加载镜像，未见已删除文件时执行 `Specialist -> Refine Volume Snapshot`；目录列表中带冒号的名称即备用数据流（ADS），而 `First cluster` 为空但大小非 0 的条目则是常驻小文件，可右键跳转到对应的 `FILE` 记录并套用 `NTFS FILE Record` 模板核对 fixup 与各段 run；常规恢复导出逻辑大小，簇尾残留则单独通过 `File Slack` 导出。DiskGenius 可在扇区编辑中按 MFT 记录号直接跳转到 `FILE` 记录头；R-Studio 则可在属性面板中按每条 `$DATA` 属性分别导出。三款工具的完整操作详见[文件系统图形工具](/knowledge/forensic-fs-gui/)。
