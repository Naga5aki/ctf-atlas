Linux 镜像、容器导出和服务器盘用 ext2、ext3 或 ext4。这里处理超级块、inode、extent，以及日志里还没被清掉的旧块指针。分区提取见[卷与引导扇区](/knowledge/forensic-fs-volume/)。`part.img` 表示已经按起始扇区和长度提取出来的分区副本。原始镜像只读，不要对它加 `-w`。

## 01 超级块、块组和 inode

主超级块在分区内偏移 1024。魔数 `53 EF` 在超级块内偏移 `0x38`，所以分区文件上是字节 1080。

| 超级块内偏移 | 长度 | 字段 |
| --- | ---: | --- |
| `0x18` | 4 | 块大小等于 1024 左移该值 |
| `0x28` | 4 | 每组 inode 数 |
| `0x38` | 2 | 魔数 `0xEF53` |
| `0x58` | 2 | inode 大小。ext4 常见 256，ext2 常见 128 |
| `0x60` | 4 | 不兼容特性。其中 `0x80` 表示 64 位块号 |
| `0xFE` | 2 | 仅在 64 位特性打开时有效：块组描述符大小，常见 64 |

块组描述符紧跟超级块所在的块。块大小 1024 时，描述符从块 2、字节 2048 开始。块大小 2048 或 4096 时，描述符从块 1 开始。传统描述符 32 字节；64 位卷改用偏移 `0xFE` 的大小。

| 描述符内偏移 | 长度 | 含义 |
| --- | ---: | --- |
| `0x00` | 4 | 本组块位图的物理块号。64 位时高 32 位在偏移 `0x20` |
| `0x04` | 4 | 本组 inode 位图。高 32 位在偏移 `0x24` |
| `0x08` | 4 | 本组 inode 表的起始物理块号。高 32 位在偏移 `0x28` |

组号等于 inode 号减 1，再除以每组 inode 数。组内序号是这个除法的余数。inode 的字节偏移等于 inode 表起始块号乘以块大小，加上组内序号乘以 inode 大小。64 位特性打开时，物理块号要拼上高 32 位。

例子：块大小 4096，描述符在字节 4096，每组 8192 个 inode，inode 大小 256。描述符开头 `0A 00 00 00 0B 00 00 00 0C 00 00 00` 表示块位图在块 10，inode 位图在块 11，inode 表从块 12 开始。inode 15 在第 0 组、组内序号 14。偏移等于 12 乘 4096 加 14 乘 256，也就是 52736。

| inode 内偏移 | 长度 | 字段 |
| --- | ---: | --- |
| `0x00` | 2 | mode |
| `0x04` | 4 | 文件大小的低 32 位 |
| `0x08` | 4 | 访问时间，Unix 秒，UTC |
| `0x0C` | 4 | 元数据改变时间 |
| `0x10` | 4 | 内容修改时间 |
| `0x14` | 4 | 删除时间。非 0 是删除线索 |
| `0x18` | 2 | 组号 |
| `0x1A` | 2 | 硬链接数 |
| `0x28` | 60 | 传统块指针，或一棵 extent 树 |
| `0x64` | 4 | generation。这里不是文件大小 |
| `0x6C` | 4 | 文件大小的高 32 位 |

大文件的字节数等于低 32 位加上高 32 位左移 32 位。inode 大于 128 字节时，偏移 128 以后还有纳秒。没有读到这部分，就先按秒报告。

目录项在启用文件类型的 ext4 上是：4 字节 inode、2 字节本项总长度、1 字节名字长度、1 字节文件类型，然后是名字。下一项从总长度之后开始。很老的 ext2 没有单独的类型字节，名字长度占 2 字节。先看超级块特性再选布局。删除后，前一项的总长度会被拉长，把被删项盖住；名字常常还留在这段空隙里。

## 02 解读 extent 树与物理块寻址

ext4 默认采用 extent 树代替传统的 12 个直接块指针。当 inode 偏移 `0x28` 处的前 2 字节出现魔数 `0A F3`（小端 `0xF30A`）时，说明该文件使用 extent 树寻址，应按“12 字节头 + 12 字节索引/叶子项”的结构解析，不能再按 4 字节块号数组直接读取。

| 头内偏移 | 长度 | 字段 |
| --- | ---: | --- |
| `0x00` | 2 | 魔数 `0A F3`，小端值 `0xF30A` |
| `0x02` | 2 | 后面的有效条目数 |
| `0x04` | 2 | 最多能放几条。inode 内部这 60 字节固定是 4 |
| `0x06` | 2 | 深度。0 表示后面就是叶子；大于 0 表示后面是索引 |
| `0x08` | 4 | generation，不参与寻址 |

深度为 0 时，每条叶子 12 字节：

| 偏移 | 长度 | 字段 |
| --- | ---: | --- |
| `0x00` | 4 | 文件内部的逻辑起始块号，从 0 起 |
| `0x04` | 2 | 连续块数。大于 32768 时，这是未初始化预留，实际块数等于该值减 32768 |
| `0x06` | 2 | 物理起始块号的高 16 位 |
| `0x08` | 4 | 物理起始块号的低 32 位 |

物理块号等于高 16 位左移 32 位，再与低 32 位合并。深度大于 0 时，每条索引也是 12 字节：逻辑块号 4 字节，下一层物理块的低 32 位在偏移 `0x04`，高 16 位在偏移 `0x08`。跳到那个物理块，块首又是一个 extent 头。

手算例子，深度 0，一条叶子，逻辑块 0，连续 1 块，物理块 34816：

```text
0A F3 01 00 04 00 00 00 00 00 00 00
00 00 00 00 01 00 00 00 00 88 00 00
```

`00 88 00 00` 是 `0x8800`，也就是 34816。块大小 4096 时，这一块的字节偏移是 34816 乘 4096。文件逻辑大小若是 2850，只取这块的前 2850 字节。

## 03 实战：从日志找回块号再截断

删除时，inode 位图清位，链接数变为 0，删除时间写入偏移 `0x14`。ext2 往往保留块指针。ext3 和 ext4 经常把 inode 里的块指针或 extent 清掉。日志里可能留着删除前的那一版 inode。日志保存的是事务中的元数据，不保证每一块文件内容都在日志里。

```bash
debugfs -R 'stats' part.img
debugfs -R 'ls -d /' part.img
debugfs -R 'stat <15>' part.img
debugfs -R 'logdump -i <15>' part.img
```

尖括号里的 15 换成被删文件的 inode，不是日志自己的 inode。日志的 inode 常见是 8，只说明日志存在哪里。若这版 debugfs 不接受尖括号，改成 `logdump -i 15`。

在 logdump 的输出里找还没被清成 0 的那一版。能看到原来的大小，以及块指针或 extent。文本可能写成块范围 34816。拿到物理块号和原大小以后再提取。下面假设块大小 4096、物理块 34816、原大小 2850，并且 `part.img` 本身就是分区：

```bash
blkcat -f ext4 part.img 34816 | head -c 2850 > ./work/from_journal.bin
dd if=part.img bs=4096 skip=34816 count=1 status=none \
  | head -c 2850 > ./work/from_journal.bin
file ./work/from_journal.bin && sha256sum ./work/from_journal.bin
```

块大小不是 4096 时，`dd` 的块大小和跳过块数都要改。叶子有多段时，按逻辑块号从小到大拼接，再按文件大小截断。`file` 和哈希用来核验这一块的开头和长度，不能代替对多段 extent 的拼接。

`extundelete` 只接受文件系统从 0 开始的分区镜像。它默认把文件写到当前目录的 `RECOVERED_FILES`。先建目录再不指定输出位置，目标目录会是空的。

```bash
mkdir -p ./work/ext-recovery
extundelete ./work/ext4-partition.img --restore-all --output-dir ./work/ext-recovery/
find ./work/ext-recovery -type f -print
```

有的版本会再套一层 `RECOVERED_FILES`。外层看起来是空的时候，先看子目录。新卷上的 extent 和元数据校验和会让这个工具漏文件。它的输出是恢复件，不是修好的原分区。每个文件还要核对大小、文件头和哈希。

X-Ways 的编号列在 ext 上是 inode。右键跳到 inode，模板看删除时间和 `0xF30A`。DiskGenius 打开含 LVM 的镜像后，从逻辑卷进入 ext4，不要去物理卷成员的中间找超级块。挂载只用于浏览副本：

```bash
sudo mount -o ro,noload /dev/loop0 /mnt/evidence
```

ext4 只写 `ro` 仍可能回放日志。跳过回放后的目录视图可能和完整回放不一致。唯一检材上不要做文件系统检查。完整菜单在[文件系统图形工具](/knowledge/forensic-fs-gui/)。
