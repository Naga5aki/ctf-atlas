## 01 固定检材，先识别真实格式

记录原文件路径、大小、哈希、取得方式和文件系统时间；在工作副本中解析或修复。扩展名和桌面图标都不能证明实际格式。先看魔数与容器结构，再让格式解析器打开；若两者冲突，记录具体偏移和报错，不急于“修复”。

```bash
sha256sum specimen.bin
file specimen.bin
xxd -l 64 specimen.bin
```

一个文件可能是容器、嵌入文件、尾部附加数据或拼接文件。对每个提取件继续记哈希、原始偏移、提取方法和与父文件的关系，避免把“可见缩略图”当成原始照片。

## 02 有文件系统时优先恢复上下文

磁盘镜像先确认分区偏移与文件系统类型。已删除文件优先查目录项、回收站、快照和文件系统日志，因为这些位置可能保留**原路径、元数据地址与时间**；再考虑对未分配空间按签名雕刻。雕刻得到的通常是字节片段，遇到碎片化或重用空间可能拼接错误。

```bash
mmls disk.dd
start_sector=2048   # 替换为 mmls 显示的实际起始扇区
metadata_addr=12345 # 替换为 fls 显示的完整元数据地址
fls -r -d -p -o "$start_sector" disk.dd
icat -o "$start_sector" disk.dd "$metadata_addr" > recovered.bin
file recovered.bin
sha256sum recovered.bin
```

`fls` 和 `icat` 的 `-o` 使用扇区数，不是字节数。若只给了单个损坏文件而非磁盘镜像，就跳过这一层，直接检查文件内部结构。不要在原镜像上运行自动修复或写入文件系统。

## 03 按格式验证完整性

| 类型 | 优先检查 | 常见误判 |
|---|---|---|
| ZIP / Office 新格式 | 中央目录、成员列表、CRC、关系文件 | 有 `PK` 头就认为整包完整 |
| PNG / JPEG | 块或段边界、尺寸、解码结果、尾部字节 | 文件能预览就认为没有截断或夹带 |
| PDF | 对象、交叉引用、增量更新、嵌入附件 | 只看当前可见页面，漏掉旧对象 |
| SQLite | 页大小、表结构、WAL/日志、完整性检查 | 只复制主库，漏掉未合并记录 |
| 音视频 | 容器、流、索引、时长、帧序列 | 播放器显示时长就认为所有帧完整 |

```bash
7z l specimen.bin
7z t specimen.bin
ffprobe -v error -show_format -show_streams specimen.bin
```

命令应按**真实格式**选择；`7z t` 的成功只验证归档工具能检查的内容，不能证明原始路径或采集过程。对损坏文件，每次修复都记下修改的偏移、旧值、新值及修复后哈希，并用另一个解析器复核。

## 04 文档与媒体的隐藏线索

Office 文档可检查压缩包成员、修订、批注、宏、嵌入对象和外部关系；PDF 看增量更新、附件和注释；邮件要保留 MIME 头、路由和附件关系。宏存在不等于执行，外部链接存在不等于连接成功，需要终端和网络痕迹印证。

图像检查 EXIF、方向、缩略图、颜色通道、文件尾与异常块；音视频检查轨道、编码、频谱、帧间不连续及转码痕迹。元数据的创建时间、GPS 和软件标记可以被复制或修改，报告中只写“文件记录显示”，再与聊天、设备和文件系统证据比对。

## 05 输出恢复评价

每个恢复件给出 `来源偏移/元数据地址、恢复方式、输出哈希、格式检查结果、缺失字节或未知范围`。把结论分为**完整可验证、部分可解析、仅命中签名**。需要提取字符串时，也要说明字符串来自哪个块、对象、帧或数据库记录；没有上下文的单一文本命中容易误判。

## 06 实战：评价一份恢复出来的 Office 文档

**场景与材料：** 从删除目录项或未分配空间取得一份疑似 Office 文档，需要确定它是否完整、是否保留原路径，以及是否包含隐藏或旧内容。

1. 保留恢复路径：元数据恢复要记录分区偏移、地址与原目录项；签名雕刻要记录物理区间和工具参数。两种方法的上下文能力不同。
2. 计算恢复件哈希，用 `file`、文件头和 `7z l` 检查它是否确为 ZIP 型 Office 包。若识别成 OLE 或其他格式，则换对应解析流程，不继续硬套 ZIP 命令。
3. 用 `7z t` 检查成员是否可验证，查看正文、关系、媒体、批注及宏等成员。保存成员清单、错误和缺失范围；测试成功仍不能证明恢复件与原文档在历史上完全一致。
4. 对未引用对象、外部关系或隐藏工作表形成独立记录。若导出嵌入文件，保存父文件哈希、成员路径和提取件哈希。
5. 与目录项、邮件附件、聊天记录或历史版本核对，解释文件的路径与活动背景；文档属性中的作者和时间只作为字段线索。

| 结果 | 建议表述 |
| --- | --- |
| 结构和成员校验通过，另有内容哈希或历史副本印证 | 恢复件结构可验证，并说明与哪份内容对应 |
| 正文可读但成员缺失或 CRC 失败 | 部分可解析，列出缺失或损坏成员 |
| 只命中文件签名或少量可读文本 | 候选片段，尚不足以认定完整文档 |

修复只在副本中进行，逐次记录旧值、新值、修改偏移、输出哈希和复核结果；不把“能打开”当成完整性的唯一标准。
