## 01 从界面追到校验函数

先记录输入框、按钮和结果提示之间的事件关系：点击后由哪个回调取值，是否在提交前去空格、转小写或拼接固定前缀。再从成功/失败提示的交叉引用倒追比较点，核对输入实际经过的函数链。若程序还读取文件、注册表或时间，这些都是校验条件的一部分，不能只看界面输入。

## 02 按执行顺序写出各层

把链路写成 `输入字节 → 长度/字符约束 → 逐字节变换 → 加密或哈希 → 比较值`。每层记录输入长度、输出长度、常量、字节序和是否有填充。对“先 XOR，再 AES 加密后比较”的结构，逆推是**先按相同模式解密比较值，再反向 XOR**；但前提是密钥、模式、IV 和填充均已确认。仅凭看到 `AES` 字样不能确定这些条件。

| 易错点 | 核对方法 |
|---|---|
| `char` 符号扩展 | 与汇编中的加载指令对照，比较 `0x80` 以上字节 |
| 32/64 位常量字节序 | 查看内存中的实际字节，不按反编译整数直接拼字符 |
| 字符串终止符 | 区分比较函数的显式长度与 NUL 终止 |
| 输入编码 | 确认界面 API 返回 UTF-8、UTF-16 还是单字节文本 |

## 03 用两次验证结束分析

先在小脚本里正向运行“候选输入 → 全部变换”，确认每层结果与程序中间值一致；再把候选输入送回原程序，记录成功分支或输出。若脚本与程序不一致，定位**第一处**发生分歧的字节和函数，而不是继续猜最终 flag。静态推导本身不等于运行结果。

## 04 用原有题例核对参数

该题例的调用链为 `winmain → sub_1400024A0 → sub_140002200`。输入先经过 **16 字节长度与 `0x20–0x7E` 字符范围**约束，接着第 `i` 个字节与 `(3*i + 127) & 0xff` 异或；变换结果进入 AES-128-ECB，与程序内保存的密文比较。逆向时按相反顺序处理：先依据真实密钥解出比较目标，再用同一掩码还原输入。断点应分别放在约束、异或结束和比较前，记录每层的 16 个原始字节。

题例中的四个 32 位常量按**小端**拼成 16 字节密钥。下例只复核字节表示与异或可逆性，不执行 AES，也不宣称单凭这些常量就能识别加密算法：

```python
from struct import pack

key = pack("<4I", 0x67452301, 0xEFCDAB89, 0x67452301, 0xEFCDAB89)
mask = bytes((3 * i + 127) & 0xFF for i in range(16))
sample = b"PleaseRunAsAdmin"
assert len(sample) == len(key) == len(mask) == 16

after_xor = bytes(value ^ mask[i] for i, value in enumerate(sample))
restored = bytes(value ^ mask[i] for i, value in enumerate(after_xor))
assert restored == sample
print("key:", key.hex())
print("mask:", mask.hex())
print("after XOR:", after_xor.hex())
```

运行时密钥应显示 `0123456789abcdef0123456789abcdef`，掩码应显示 `7f8285888b8e9194979a9da0a3a6a9ac`。若程序内密文以有符号 32 位整数存储，先按实际小端内存布局恢复字节，再解密；不要直接把负数的十进制字符串拼进密文。最终仍需把候选输入送回原程序，观察它是否真正进入成功分支。
