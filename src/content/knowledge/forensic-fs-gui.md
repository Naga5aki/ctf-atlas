命令行工具擅长精确计算扇区偏移与批量脚本处理，而 X-Ways Forensics、DiskGenius 和 R-Studio 则适合在同一份只读镜像上直观浏览目录树、比对多套时间戳、套用十六进制模板及重组虚拟 RAID。操作时应将案件目录与导出目录统一放在 `./work/` 下，严禁向原始镜像写回分区表或引导扇区。不同软件版本的菜单译名可能略有差异，找不到同名菜单时按功能位置查找，切勿点击会直接修复原盘的选项。底层字节结构与偏移定义见 NTFS、FAT、exFAT 和 ext 各专页。

## 01 三套工具各看什么

| 工具 | 优先用来做 | 限制 |
| --- | --- | --- |
| X-Ways | 十六进制和模板对账，NTFS 的两套时间、备用流和簇尾 | 复杂 LVM、Btrfs 子卷不如专用命令直观。搜 Unicode 名字时要选对 UTF-8 或 UTF-16 |
| DiskGenius | 快速看目录、虚拟磁盘、LVM 和 BitLocker，并按扇区、簇或记录号跳转 | 它不把两套 NTFS 时间并排列出。按文件类型自动拼接会把碎片接错。免费版对单个大文件的恢复可能有限制 |
| R-Studio | 引导扇区或文件表损坏后的扫描，以及 RAID | 深度扫描很慢。小镜像要限制范围，并且只勾目标文件系统和目标文件类型 |

三个程序都只打开镜像、只把文件复制到外部目录。修复引导扇区、保存分区表，只在工作副本上进行。

## 02 X-Ways 按文件系统看记录

`File -> Open Image` 或 `Add Image` 加载 `.dd`、`.E01`、`.vmdk`。快照写到案件目录。双击目标分区。已删除文件没有出现时，打开 `Specialist -> Refine Volume Snapshot`。勾选特别彻底的文件系统结构搜索，以及文件头签名搜索。签名搜索的结果按雕刻处理，不自动继承某个已删除目录项的名字。

NTFS 在目录列里勾上创建、修改，以及文件名属性对应的日期列。或选中文件后看详情里的八个时间，以及有没有 `Zone.Identifier`。备用流显示为带冒号的名字。`First cluster` 为空且大小不是 0，是常驻小文件，跳到 FILE 记录后按常驻属性的内容长度截取。模板选 `NTFS FILE Record`，核对修复序列之后的 run。复制恢复导出逻辑大小；File Slack 单独导出。

FAT 和 exFAT 看 `First cluster`，跳到目录项，模板用 FAT 或 exFAT 的目录项。核对长名校验和、FAT32 的高 16 位簇、exFAT 的连续标志和时区字节。分区第 0 扇区被抹掉、只显示未识别区域时，在整盘视图框住分区起止扇区，用 `Specialist -> Interpret Image File As...` 指定类型。或者在副本上把确认含有 `FAT32   ` 的备份引导扇区抄回第 0 扇区后再打开。

ext 的编号列是 inode。跳到 inode，模板看删除时间和 extent 魔数 `0xF30A`。字符串搜索之前先选编码。UTF-16LE 的名字搜不到时，不要得出盘上没有这个词。

## 03 DiskGenius 按簇和逻辑卷跳转

`磁盘 -> 打开虚拟磁盘文件` 可以加载 `.dd`、`.img`、`.E01`、`.vmdk`、`.vhdx`。含 LVM 的镜像，左侧设备树底部会出现卷组和逻辑卷。点逻辑卷，再看里面的 ext4 或 XFS。不要把物理卷当成已经拼好的文件系统。

BitLocker 分区在右键里选解锁，输入 48 位恢复密钥、口令，或加载 bek 文件。菜单里没有这一项，就是这版不支持，换一个能解密的工具。没有密钥时，不要对密文分区做文件雕刻后声称已经解密。

恢复已删除文件时，只勾选恢复误删除的文件，再复制到指定文件夹。这个模式走的是主文件表、FAT 目录项或 ext inode。碎片是否正确，用文件尾再核验一次。扇区编辑里可以转到整盘绝对扇区、转到簇，或在 NTFS 上转到 MFT 记录。转到记录后应看到 `FILE`。

分区表被毁时，用搜索已丢失分区。每找到一个候选，先预览文件是否正常。把分区表写回去的操作只点在副本镜像上。原镜像到此为止，只从预览里把文件复制出来。免费版若拒绝恢复某个大文件，就改用已经算好的 `icat` 或 `dd`。

## 04 实战：用 R-Studio 重建损坏卷和 RAID

引导扇区、主文件表或超级块损坏，或者 NTFS 被快速格式化成 exFAT 时，右键目标分区或整盘，开始扫描。起点和大小限定在目标分区的扇区范围内。文件系统只勾实际可能涉及的一到两种。原盘是 NTFS、后来被格式化成 FAT32，就只勾这两类。Linux 盘只勾 ext。需要补雕刻时，已知文件类型里只留 png、jpg、zip、sqlite、pcap 这类目标。

结果颜色以这版界面的图例为准，可以按这个顺序用。绿色表示引导记录和文件表都在，目录和文件名最完整，先打开它。黄色或橙色表示引导扇区没了，但残留的记录或目录项还在，进去以后仍可能有路径、两套时间和备用流。按扩展名分的原始文件只有文件头，没有原名，前两类都没有目标时才用。

选中文件后，在属性里看记录号和分配。NTFS 会列出标准信息、每一条文件名和每一条数据流，以及每段 run 的起始扇区和长度。右键一条属性，单独导出，再用文件尾和哈希核验。

多块 RAID 成员这样重组：

1. 建立虚拟块 RAID，把各成员镜像拖进去。先在偏移 `0x1000` 找 `FC 4E 2B A9`。读出级别、总盘数、当前盘序号、条带大小和左右、对称与不对称的布局。魔数不在 `0x1000`，就到成员尾部找 0.9 或 1.0 超级块。
2. 填 RAID 类型、块大小和块顺序。改一个参数就看左侧目录是否出现。
3. 缺一块盘时，把空位放在超级块所缺的那一号，不要把空位随便拖到列表末尾。
4. 左侧要出现分区表，并且分区能展开成正常目录。再导出一个大于两个条带的文件，核对文件尾、内部结构和哈希。这一步通过，盘序和条带才算对。

虚拟 RAID 建在案件里，不写回成员镜像。也不要拿会创建阵列的命令对检材试参数。
