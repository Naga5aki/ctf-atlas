APNG（Animated PNG）是标准PNG的动画扩展格式，完全兼容PNG基础结构，通过新增动画控制块实现多帧动画，隐写方式覆盖「帧画面、帧参数、结构扩展、原生PNG通用隐写」四个层级。

## 一、基础认知与格式定位

### 1.核心定义

APNG是支持多帧动画的PNG变种，不是独立的全新格式，所有结构均基于标准PNG的Chunk体系扩展而来。

文件头与普通PNG完全一致：89 50 4E 47 0D 0A 1A 0A

仅靠文件头无法区分普通PNG与APNG，必须通过专属动画块判断

**最核心的识别标志：** 存在acTL动画控制块

### 2.与普通PNG的核心差异

| 项目 | 普通PNG | APNG |
| --- | --- | --- |
| 文件头 | 一致 | 一致 |
| 基础块（IHDR/IDAT/IEND） | 有 | 有 |
| 动画专属块（acTL/fcTL/fdAT） | 无 | 有 |
| 画面数量 | 单帧 | 多帧 |
| 控制参数 | 无 | 帧延时、坐标偏移、混合/清除模式 |

### 3.快速识别方法

**十六进制搜索：** 010 Editor中搜索61 63 54 4C（acTL），命中即可判定为APNG

**结构校验：** 配合fcTL、fdAT块进一步确认

**工具识别：** pngcheck-v可输出全部Chunk信息，出现动画块即为APNG

**后缀伪装：** 后缀名不决定格式，只要PNG文件头+acTL块存在，本质就是APNG

## 二、核心结构与关键Chunk

### 1.Chunk通用规则

所有PNG/APNG块均遵循统一结构，多字节整数为大端序：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| Length | 4字节 | Data区的长度，不含Type、Length、CRC |
| Type | 4字节 | 块类型标识，如acTL、fcTL |
| Data | N字节 | 块具体数据 |
| CRC | 4字节 | Type+Data的CRC32校验值，不含Length |

### 2.三大专属动画块详解

| 块名称 | 十六进制标识 | 核心作用 | 内部结构 |
| --- | --- | --- | --- |
| acTL动画总控制块 | 61 63 54 4C | 全局动画控制，是APNG的核心判定标志 | 1.num_frames（4字节）：总帧数<br>2.num_plays（4字节）：循环次数，0代表无限循环 |
| fcTL单帧控制块 | 66 63 54 4C | 每一帧的属性控制，每帧对应一个，共26字节Data区 | 1.序号（4字节）<br>2.帧宽度（4字节）<br>3.帧高度（4字节）<br>4.X偏移（4字节）<br>5.Y偏移（4字节）<br>6.延时分子（2字节）<br>7.延时分母（2字节）<br>8.清除模式（1字节）<br>9.混合模式（1字节） |
| fdAT帧数据块 | 66 64 41 54 | 存储第2帧及之后的图像压缩数据 | 1.序号（4字节）<br>2.zlib压缩图像数据 |

**补充：** APNG第一帧复用普通PNG的IDAT块存储数据，不需要fdAT；从第二帧开始使用「fcTL+fdAT」的组合。

### 3.两层宽高的关键区别

**IHDR宽高：** 整个动画的画布尺寸，是完整画面的最大边界

fcTL宽高+偏移：单帧实际占用的矩形区域，可能远小于画布，通过X/Y偏移定位在画布中的位置

**核心结论：** APNG不是「多张完整PNG拼接」，单帧可能只是极小的矩形碎片，依靠偏移与合成规则形成完整画面。

### 4.帧合成规则

Dispose（清除模式）：当前帧播放完后如何处理画布

0：不处理

1：恢复为背景

2：恢复为上一帧状态

Blend（混合模式）：当前帧与画布的叠加方式

0：直接覆盖

1：按Alpha透明度混合

**实战意义：** 单独查看某一帧原始数据，和动画播放时合成的画面可能完全不同，两类结果都需要检查。

## 三、高频核心考点

### 1.隐藏帧藏Flag

**隐藏方式：** 仅第一帧为正常画面，Flag、二维码、提示信息完整藏在后续某一帧，普通看图软件只显示第一帧。

**典型特征：** acTL显示总帧数远大于肉眼感知，文件体积与单帧画面不匹配。

**解题方法：** 拆分全部帧，逐帧检查，重点关注第一帧、最后一帧和异常尺寸帧。

### 2.多帧碎片拼接

**隐藏方式：** 完整的Flag、二维码、图片被切割为多个碎片，分散藏在不同帧中，单帧只有局部内容。

**典型特征：** 每帧只有局部图案/字符，单独看无意义；总帧数较多。

**解题方法：** 按帧序排列碎片，尝试横向拼接、纵向拼接、坐标对位拼接。

### 3.透明帧叠加隐写

**隐藏方式：** 利用Alpha透明通道，每帧只有少量像素点、线条、字符片段，单独看接近空白；多帧叠加后形成完整内容。

**典型特征：** 多数帧画面接近全透明，肉眼看似无内容。

**解题方法：** 多帧像素叠加（OR运算、最大值合成、Alpha合成）、帧差分对比。

### 4.帧参数编码类

数据不藏在画面里，而是藏在fcTL的控制参数中，画面完全正常，隐蔽性极强。

（1）坐标偏移隐写

**原理：** 利用每帧的X Offset、Y Offset数值编码ASCII或二进制

**特征：** 画面无异常，但每帧偏移量呈规律变化

**解法：** 提取所有帧的X/Y偏移值，转换为ASCII或二进制流

（2）帧延时隐写

**原理：** 通过帧延时大小编码数据，如短延时=0、长延时=1，或延时值直接对应ASCII码

**特征：** 播放节奏忽快忽慢，延时数值有明显规律

**解法：** 提取每帧delay_num/delay_den计算实际延时，映射为对应数据

（3）序号异常隐写

**原理：** fcTL、fdAT的Sequence Number正常应连续递增，异常跳跃的数值本身携带数据

**特征：** 块序号不连续，出现突兀的大数值

**解法：** 提取序号序列，分析数值规律，转换为字符或二进制

### 5.动画结构损坏修复

**原理：** acTL、fcTL、fdAT的长度、序号、CRC被篡改，导致无法正常播放动画，但第一帧可正常显示。

**特征：** PNG能打开，但无法播放动画；pngcheck报Chunk错误。

**解法：** 通过pngcheck定位错误块，对照APNG规范修复长度、序号，重新计算CRC。

## 四、常用工具与操作

### 1.结构识别与校验

#详细输出所有Chunk信息，识别APNG、检查结构错误

pngcheck-v animation.png

**作用：** 确认APNG结构，统计帧数，定位Chunk错误、CRC异常。

### 2.拆帧工具

（1）apngdis（首选）

apngdis animation.png

**作用：** 直接分离所有原始帧，输出独立PNG文件，保留帧原始属性。

（2）FFmpeg

ffmpeg-i animation.png frame_%03d.png

**作用：** 输出动画合成后的完整帧，适合查看实际播放效果。

### 3.拆帧后分析清单

逐帧肉眼查看，重点检查首尾帧

帧差分运算，定位细微差异

Alpha通道单独提取分析

全帧像素叠加，还原碎片内容

提取所有fcTL参数，检查数值规律

**常规PNG隐写排查：** 文本块、尾部追加、IDAT隐写

## 五、高频易错点

**两层宽高混淆：** 误以为fcTL宽高就是画布宽高，忽略单帧只是小碎片。

**忽略合成规则：** 只看原始帧数据，不考虑Dispose/Blend合成后的实际画面。

**fdAT直接复用：** 误以为把fdAT改名为IDAT就能独立成PNG，忽略开头4字节序号。

**参数层遗漏：** 画面找不到内容就放弃，忽略帧坐标、延时、序号等参数编码。

**忘记通用考点：** 只盯着动画分析，漏掉尾部追加、文本块等普通PNG隐写。

**修复不同步CRC：** 修改Chunk数据后不更新CRC，导致解析器识别失败。
