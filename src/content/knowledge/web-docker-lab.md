题目附件是源码时，复现环境决定你能不能看到“真实解析链”。容器适合单服务、可随时销毁；虚拟机适合多网卡、多网段、需要真实路由的场景。两者不替代，按题目形态选。

> 只复现你拥有或明确授权的题目；端口绑 `127.0.0.1`，不要把漏洞环境暴露到局域网或公网。

## 00 30 秒速查

| 我要… | 选… | 备注 |
|---|---|---|
| 单文件 PHP/Python | 本机/容器 | 最快 |
| 有 Dockerfile/compose | 容器 | 版本固定 |
| 多服务 | compose | 服务名互访 |
| Nday | vulhub | 对齐 tag |
| 多网段/域 | 虚拟机 | 快照 |
| 只让宿主访问 | `127.0.0.1:映射` | 回环 |
| 容器互访 | compose 网络 | 服务名 |
| 清理 | `down -v`/快照 | 确认卷名 |

## 01 原理与成立条件

```text
附件 → 启动材料 → 容器/虚拟机 → 端口映射 → 浏览器/Burp
容器：镜像 → 容器 → 网络/卷
虚拟机：虚拟网卡 → 网段 → 路由
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 有启动材料 | Dockerfile/compose | 自写/按入口判 |
| 依赖可得 | 镜像/离线包 | 记录失败 |
| 网络隔离 | 回环/内部 | 不启动 |
| 可销毁 | 容器/快照 | 不污染宿主 |

| 方式 | 适合 | 代价 |
|---|---|---|
| 本机 | 单文件无依赖 | 污染/版本不可控 |
| 容器 | 单服务/Nday | 网络/内核受限 |
| 虚拟机 | 多网段/域 | 资源重 |

## 02 判断与分型

```text
附件有 compose 吗？
 ├─ 有 → 多服务/容器
 └─ 无
     ├─ 有 Dockerfile → 单容器
     ├─ 只有源码 → 自写最小 Dockerfile
     └─ 镜像/OVA → 导入/虚拟机
需要多网段吗？
 ├─ 是 → 虚拟机 + 内部网络
 └─ 否 → 回环映射
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| `docker-compose.yml` | 多服务 | 副本构建 |
| `Dockerfile` | 单服务 | 版本对齐 |
| `requirements.txt`/`pom.xml` | 语言/依赖 | 选基础镜像 |
| 端口冲突 | 本机占用 | 换端口 |
| 镜像 tag `latest` | 版本漂移 | 固定版本 |
| 数据卷 | 旧数据 | 清卷 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 容器起不来 | 端口/依赖 | 看日志 |
| 502 | 上游未起 | 看 compose |
| 页面像旧题 | 旧卷 | 清卷 |
| vulhub 打不通 | tag/payload | 对齐版本 |

## 03 利用阶梯

### L0 选型

**前提**：有附件/源码/镜像。

**步骤**：
1. 看 `Dockerfile`/compose/依赖/README。
2. 单服务→容器；多网段→虚拟机。
3. 确认端口/账号/初始化。
4. 记录镜像 tag/版本。

**成功标志**：选定方式与版本。

**失败分支**：材料不全→自写最小环境；版本不明→按报错对齐。

### L1 单容器

**前提**：单服务。

**步骤**：
1. `docker run -d --name t -p 127.0.0.1:8080:80 -v "$PWD/src:/var/www/html" php:8.1-apache`。
2. `docker logs -f t` 看启动。
3. `docker exec -it t sh` 进容器核对扩展/配置。
4. `docker cp` 取回文件；结束 `stop/rm`。

**成功标志**：本机可访问，配置与题目一致。

**失败分支**：端口占用→换；扩展缺→装；版本不符→换 tag。

### L2 compose 与源码构建

**前提**：多服务/只有源码。

**步骤**：
1. compose 字段：`image/build`、`ports`、`volumes`、`environment`、`depends_on`。
2. 端口写 `127.0.0.1:8080:80`，服务名互访。
3. 源码构建：基础镜像贴近题目，扩展/`php.ini` 对齐，`COPY` 到 docroot。
4. `up -d`/`logs -f`；改配置先 `down` 再 `up`。
5. vulhub：进目录看 README，版本/端口/初始化对齐。

**成功标志**：多服务互通，页面/漏洞可复现。

**失败分支**：镜像拉取失败→离线包；依赖顺序→healthcheck；版本差异→改 tag。

### L3 虚拟机网络

**前提**：多网段/域。

**步骤**：
1. 选模式：NAT（出网）、桥接（同 LAN）、仅主机（宿主↔VM）、内部（VM↔VM）。
2. 攻击机/边界机/内网机按“双网卡边界”布置。
3. 实验前打快照。
4. 验证：`ip a`/`ip route`/`ping`/`tcpdump`。

**成功标志**：网段可达关系符合设计。

**失败分支**：网段重叠→改；网关错→修路由；不通→抓包。

### L4 多网段与清理

**前提**：两层/三层拓扑。

**步骤**：
1. 边界机开转发或起 SOCKS（二选一）。
2. 攻击机加路由或 proxychains。
3. 每层记录入口/出口/网段。
4. 结束停容器/`down -v`/恢复快照。
5. 移除代理/路由，避免影响后续。

**成功标志**：拓扑可复现，环境干净。

**失败分支**：回路/混用→只留一种；残留→按卷名删。

## 04 绕过与边界

| 场景 | 边界 | 处理 |
|---|---|---|
| 端口映射 | 左边宿主 | 写回环 |
| `--network host` | 共享宿主网络 | 不用 |
| `--privileged` | 能力过大 | 仅题目需要 |
| 数据卷 | 跨题残留 | 清卷 |
| 镜像来源 | 不明镜像风险 | 官方/题目 |
| 快照 | 实验前 | 先打 |

边界：容器内 `127.0.0.1` 是自己；`docker save` 不含卷；`compose down -v` 删卷；VM 网段不要与宿主重叠。

## 06 差异速查

| 网络模式 | 出网 | 宿主访问 | 用途 |
|---|---|---|---|
| NAT | 能 | 需转发 | 单机 |
| 桥接 | 能 | 能 | 同 LAN |
| 仅主机 | 否 | 能 | 攻击机↔靶机 |
| 内部 | 否 | 否 | 内网深处 |

| 命令 | 作用 | 注意 |
|---|---|---|
| `run -p 127.0.0.1:8080:80` | 回环 | 左宿主 |
| `ps` | 运行中 | 实际端口 |
| `exec` | 进容器 | 非宿主 |
| `save/load` | 镜像 | 不含卷 |
| `down -v` | 删卷 | 确认 |
