请求走私的前提是**代理链上至少有两台服务器，对请求边界的理解不一致**。只要能让后端把“剩余字节”当成下一个请求，就能越过前端鉴权、污染缓存，或拿到别人的响应。

> 只对本地题目或授权环境测试；走私会影响同连接上的其他请求，先在隔离环境验证。

## 00 30 秒速查

| 我要… | 先看… | 备注 |
|---|---|---|
| 有没有代理链 | `Server`/`Via`/CDN 头 | 至少两跳 |
| 边界头 | `Content-Length`/`Transfer-Encoding` | 冲突点 |
| CL.TE | 前端 CL、后端 TE | 0 块结束 |
| TE.CL | 前端 TE、后端 CL | 小 CL |
| TE.TE | 混淆 TE 值 | 一方不认 |
| 判定 | 时间差/差分响应 | 连接挂起 |
| 绕鉴权 | 走私 `GET /admin` | 前端只查原路径 |
| 缓存 | 走私响应写入正常 URL | 见缓存页 |
| H2 | `:path`/`content-length` 降级 | 看前端 |

## 01 原理与成立条件

```text
客户端 → 前端代理（按一种规则切边界）
             ↓ 转发字节
         后端（按另一种规则切边界）
             └─ 剩余字节 = 下一个请求
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 至少两跳 | 代理/网关/后端 | 单机无走私 |
| 边界规则不同 | CL vs TE/混淆 | 找解析差异 |
| 连接可复用 | keep-alive | 关闭则失效 |
| 可控原始字节 | 能改 CL/TE/正文 | 用工具 |

| 头 | 含义 | 冲突 |
|---|---|---|
| `Content-Length: N` | 正文 N 字节 | 与 TE 同时 |
| `Transfer-Encoding: chunked` | 分块，`0\r\n\r\n` 结束 | 前端忽略/后端认 |
| 两者都有 | RFC 要求 TE 优先并移除 CL | 实现不一致 |

## 02 判断与分型

```text
响应头有 Via/Server/CDN 吗？
 ├─ 有 → 可能两跳
 └─ 无 → 也可能是反代（看行为）
发缺结尾的 chunked：
 ├─ 超时/挂起 → 后端用 TE
 └─ 立即响应 → 后端用 CL/前端处理
再发 CL.TE/TE.CL：
 ├─ 多出一个响应 → 走私成立
 └─ 400/连接关 → 该形态不行
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| 请求挂起 | 后端等 chunk | TE |
| 多出响应 | 被藏请求执行 | 记录 |
| 400/502 | 解析拒绝 | 换混淆 |
| 下一个请求异常 | 缓冲区污染 | 缓存/响应 |
| H2 伪头重复 | 降级差异 | 试 H2.CL/TE |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 单次超时 | 网络/后端慢 | 多次测 |
| 多出响应 | 前端重试 | 看连接 |
| 400 | 代理严格 | 换形态 |
| 连接关闭 | keep-alive 关 | 无法复用 |

## 03 利用阶梯

### L0 确认代理链与复用

**前提**：目标前面有反代/CDN。

**步骤**：
1. 看 `Server`/`Via`/`X-Cache`/CDN 头。
2. 确认连接复用（keep-alive）。
3. 用 Burp 关闭 “Update Content-Length”。
4. 记录前端/后端可能的软件与版本。

**成功标志**：确认两跳且连接可复用。

**失败分支**：单机→无走私；连接关闭→换目标。

### L1 CL.TE

**前提**：前端看 CL，后端看 TE。

**步骤**：
1. 发 `CL` 等于“0 块+剩余”的长度，`TE: chunked`。
2. body：`0\r\n\r\nSMUGGLED`。
3. 后端读到 `0` 结束，剩余字节留在缓冲区。
4. 立即发第二个请求，看是否被拼接/多出响应。

**成功标志**：第二个请求被当作走私内容/多出响应。

**失败分支**：400→换 TE.CL；无多出→前端也认 TE。

### L2 TE.CL / TE.TE

**前提**：前端认 TE、后端认 CL，或两端对 TE 混淆写法不同。

**步骤**：
1. TE.CL：`CL` 很小（如 3），body 先放 `8\r\nSMUGGLED\r\n0\r\n\r\n`。
2. 后端只读 CL 字节，剩余成为下一个请求。
3. TE.TE：试 `xchunked`、`Transfer-Encoding :`、Tab、双写、逗号、大小写。
4. 用时间差/差分响应确认。

**成功标志**：走私请求被执行/连接挂起符合预期。

**失败分支**：都严格→换 H2；混淆被规范化→换写法。

### L3 绕鉴权 / 缓存 / 响应

**前提**：走私成立。

**步骤**：
1. 绕鉴权：走私 `GET /admin`，前端只检查原始路径。
2. 缓存：让走私响应落到正常 URL，见缓存投毒页。
3. 响应错位：把受害者请求排在自己后面，读别人响应（需精细流水线）。
4. 只验证到固定回显/自己的会话。

**成功标志**：访问到受保护路径/读到他人响应/缓存被污染。

**失败分支**：前端按路径拒绝→换目标；缓存不存→换 URL。

### L4 HTTP/2 降级

**前提**：前端 H2、后端 H1。

**步骤**：
1. H2.CL：带 `content-length` 与 body 不一致。
2. H2.TE：带 `transfer-encoding: chunked`，降级后被当 chunked。
3. 伪头重复：`:path`/`:method` 多次出现，看前后端取值。
4. 用 h2cSmuggler/支持 H2 的工具。

**成功标志**：降级后走私/绕过。

**失败分支**：前端严格→换 H1；H2 不支持→换路径。

## 04 绕过与边界

| 限制 | 替代 | 示例 |
|---|---|---|
| 拒绝 CL+TE | 只发 TE/混淆 | `xchunked` |
| 规范化头 | 空格/Tab/双写 | `Transfer-Encoding :` |
| 连接关闭 | 换目标/短连接 | 无法复用 |
| 前端严格 | H2 降级 | H2.CL/TE |
| 响应不可见 | 缓存/盲打 | 见缓存页 |
| WAF | 编码/分块 | 见 WAF 页 |

边界：走私影响同连接其他用户；只在授权环境验证；不同代理组合形态不同；H2 伪头大小写/重复的处理依实现。

## 05 非典型入口

| 位置 | 示例 | 注意 |
|---|---|---|
| CDN→源站 | CL/TE | 常见 |
| 负载均衡 | H2→H1 | 降级 |
| 反向代理 | 路径重写 | 鉴权差 |
| 缓存 | 响应队列 | 投毒 |
| WebSocket 升级 | 连接复用 | 边界 |
| gRPC 网关 | H2 | 伪头 |

## 06 差异速查

| 形态 | 前端 | 后端 | 结果 |
|---|---|---|---|
| CL.TE | CL | TE | 剩余字节 |
| TE.CL | TE | CL | 剩余字节 |
| TE.TE | 认 TE | 不认混淆 | 一方按 CL |
| H2.CL | H2 | H1 | 长度差 |
| H2.TE | H2 | H1 | 分块 |

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 无挂起 | 后端用 CL | 换 TE.CL |
| 400 | 严格解析 | 换混淆 |
| 无多出响应 | 前端也认 TE | 换 H2 |
| 连接关闭 | keep-alive | 换目标 |
| 缓存不污染 | 键/规则 | 见缓存页 |
| H2 失败 | 前端 | 换 H1 |
