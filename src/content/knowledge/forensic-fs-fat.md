FAT12、FAT16 和 FAT32 没有 inode，也没有主文件表。恢复靠目录项；链还在就沿链走，链被清掉就按起始簇和大小做连续候选。分区起点见[卷与引导扇区](/knowledge/forensic-fs-volume/)。原始镜像只读。

## 01 认识三块核心区域与簇偏移换算

FAT 卷由三块连续区域组成：最前面是**保留区**（含引导扇区，FAT32 另含 FSInfo 与备份引导扇区）；紧接着是**文件分配表区**（通常一式两份：FAT1 与 FAT2）；最后是**数据区**，并且数据区的第一个可用簇编号固定从 **簇 2** 开始。引导扇区的关键参数偏移如下：

| 偏移 | 字段 |
| --- | --- |
| `0x0B` | 每扇区字节 |
| `0x0D` | 每簇扇区 |
| `0x0E` | 保留扇区数 |
| `0x10` | FAT 份数，常见 2 |
| `0x11` | 根目录项数。FAT32 这里是 0 |
| `0x20` | 总扇区数，32 位 |
| `0x24` | 每份 FAT 的扇区数。FAT32 使用 |
| `0x2C` | 根目录起始簇，常见 2 |
| `0x30` | FSInfo 扇区 |
| `0x32` | 备份引导扇区，常见 6 |
| `0x52` | `FAT32   ` |

数据区起始扇区，相对卷，等于保留扇区数加上 FAT 份数乘以每份 FAT 扇区数。簇 N 的卷内字节偏移等于数据区起始扇区加上 (N 减 2) 乘以每簇扇区，再乘以每扇区字节。FAT12 和 FAT16 的根目录不在簇链里，它固定排在两份 FAT 之后，项数由偏移 `0x11` 决定，每项 32 字节。FAT32 的根目录是从偏移 `0x2C` 那个簇开始的普通簇链。引导扇区被抹掉时，用卷与引导扇区那一页从 `F8 FF FF 0F` 反推保留扇区数。

## 02 短目录项、长文件名和时间

短目录项 32 字节：

| 偏移 | 长度 | 含义 |
| --- | ---: | --- |
| `0x00` | 11 | 8.3 短名。`0x00` 表示后面没有项；`0xE5` 表示这项已删除 |
| `0x0B` | 1 | 属性。`0x10` 是目录，`0x20` 是归档，`0x0F` 则是长文件名项 |
| `0x0D` | 1 | 创建时间的 10 毫秒计数。长文件名项的这个位置不是时间 |
| `0x0E` | 2 | 创建时间 |
| `0x10` | 2 | 创建日期 |
| `0x12` | 2 | 访问日期，只有日期 |
| `0x14` | 2 | 起始簇高 16 位，FAT32 使用 |
| `0x16` | 2 | 修改时间 |
| `0x18` | 2 | 修改日期 |
| `0x1A` | 2 | 起始簇低 16 位 |
| `0x1C` | 4 | 文件大小。目录的这个字段是 0 |

长文件名是排在短项前面的若干条属性 `0x0F` 的项，磁盘上按序号从大到小排列。

| 偏移 | 长度 | 含义 |
| --- | ---: | --- |
| `0x00` | 1 | 序号。内容的第 1 段是 `0x01`；最后一段要或上 `0x40`。一共 2 段时，盘上的顺序是 `0x42`、`0x01`，然后才是短项。删除后这个字节也变成 `0xE5` |
| `0x01` | 10 | 文件名第 1 到 5 个 UTF-16LE 字符 |
| `0x0B` | 1 | 固定 `0x0F` |
| `0x0D` | 1 | 短文件名校验和 |
| `0x0E` | 12 | 第 6 到 11 个字符 |
| `0x1A` | 2 | 固定为 0，不是起始簇 |
| `0x1C` | 4 | 第 12 到 13 个字符。名字结束后先放 `00 00`，剩下的位置填 `FF FF` |

校验和使用短项里那 11 个原始字节，不足补空格，通常是大写。从 0 开始，对每个字节把当前和右旋 1 位再加这个字节，结果保留低 8 位。名字 `FLAG    TXT` 得到 `0xA0`。长名项的偏移 `0x0D` 等于这个值，才和后面的短项是一组。

日期和时间各是 2 字节小端整数，存的是本地时间，没有时区。日期从 1980 年起。

```text
年 = 1980 + (值 右移 9)
月 = (值 右移 5) 的低 4 位
日 = 值的低 5 位
时 = 值 右移 11
分 = (值 右移 5) 的低 6 位
秒 = 值的低 5 位，再乘 2
```

创建时间的两字节是 `D4 73`，日期是 `6F 58` 时，时间值 `0x73D4` 是 14 时 30 分 40 秒，日期值 `0x586F` 是 2024 年 3 月 15 日。这是本地时间。和 NTFS 的 UTC 比较之前，先确定当时的时区。短项偏移 `0x0D` 若不是 0，再把该值乘 10 毫秒加到创建时间上。

一组能对上校验和的例子，长名 `flag.txt`，短名 `FLAG    TXT`，起始簇 5，大小 45678：

```text

```

`6E B2 00 00` 是 `0xB26E`，也就是 45678。起始簇由高 16 位 `00 00` 和低 16 位 `05 00` 拼成 5。

## 03 分配表

FAT12 每个项 12 位，FAT16 是 16 位，FAT32 只用低 28 位。0 表示空闲。普通值是下一个簇。FAT32 的 `0x0FFFFFF8` 到 `0x0FFFFFFF` 是链尾，`0x0FFFFFF7` 是坏簇。FAT16 的链尾是 `0xFFF8` 到 `0xFFFF`，FAT12 的链尾是 `0xFF8` 到 `0xFFF`。

FAT12 的项 N 从 FAT 起点的字节 `N + N//2` 开始，读一个小端 16 位数。N 为偶数取低 12 位，奇数取高 12 位。字节 `F8 FF FF 03 40 00 FF 0F` 里，簇 2 的下一项是 3，簇 3 的下一项是 4，簇 4 是链尾。

Windows 删除文件时，通常把目录项首字节改成 `0xE5`，并把 FAT 链清成 0。起始簇和文件大小还在短项里。Linux 上的删除不一定清链。先看 FAT：链还在就沿链读；对应项已经是 0，就只把起始簇加大小当成连续候选。

## 04 实战：虚拟地址和连续导出

FAT 没有 inode。`fls` 行首的数字，例如 5 或 38，是 Sleuth Kit 用目录项所在扇区和槽位算出来的虚拟元数据地址。必须先跑 `fls`，把这个数整段交给 `istat` 和 `icat`。自己从簇号编一个号码，读到的会是别的目录项。

```bash
start=2048
fsstat -o "$start" disk.dd
fls -r -d -p -o "$start" disk.dd
istat -o "$start" disk.dd 38
icat -o "$start" disk.dd 38 > ./work/fat_icat.bin
```

`38` 换成 `fls` 打印的地址。链已经被清零时，`icat` 会从起始簇按文件大小连续往下读。原来若有碎片，后半段会混进别的文件。导出后要看文件尾：JPEG 以 `FF D9` 结束，PNG 的最后一块是 `IEND`，ZIP 要能找到中央目录。对不上就不要把这次导出当成原文件。

同一件事可以按目录项手算。下面的数都是例子：分区起始扇区 2048，保留扇区 32，两份 FAT，每份 1024 扇区，每簇 8 扇区，每扇区 512 字节，起始簇 5，大小 45678。

```bash
data_start_sec=$((2048 + 32 + 2 * 1024))
file_start_sec=$((data_start_sec + (5 - 2) * 8))
dd if=disk.dd bs=512 skip="$file_start_sec" status=none \
  | head -c 45678 > ./work/fat_by_dirent.bin
file ./work/fat_by_dirent.bin
sha256sum ./work/fat_by_dirent.bin
```

数据区整盘扇区是 4128，文件起点是 4152。镜像若本来就是单分区，不要再加 2048。`file` 只看开头，接着用尾部标记核验后半段没有接错。

X-Ways 在目录里看 First cluster，右键跳到目录项，再用 `FAT Directory Entry` 模板核对校验和和高 16 位簇号。引导扇区被抹掉时，先在副本上恢复备份引导扇区。DiskGenius 用转到簇核对簇首是不是文件头。R-Studio 扫描时文件系统只勾 FAT。完整菜单在[文件系统图形工具](/knowledge/forensic-fs-gui/)。
