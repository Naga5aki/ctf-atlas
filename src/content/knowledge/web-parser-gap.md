“过滤没生效”“看到了别人的页面”，常常不是 payload 不够花，而是两套程序对同一段字节做了不同切分。先找出是哪两套程序，再保存它们各自看到的请求。

> 只在本地题目或授权环境比较两边的日志；不要构造错位请求影响别人的连接。

## 00 30 秒速查

| 差异 | 两边看什么 | 现象 |
|---|---|---|
| 缓存键 | 头/查询/路径 | 同键不同正文 |
| 走私 | CL/TE | 一个连接两个请求 |
| 参数污染 | 同名参数取第几个 | WAF 与应用取值不同 |
| 分块 | 原文 vs 还原后 | 关键字被拆开 |
| Content-Type | 表单 vs JSON | 解析器不同 |
| 字符集 | UTF-8 vs GBK | 宽字节/绕过 |
| 路径 | 规范化/后缀 | 路由与缓存不一致 |
| 多层 | 入口 vs 上游 | 内部服务 |

## 01 原理与成立条件

```text
原始字节 → 代理/WAF → 缓存 → 应用框架 → 业务
             ├─ 各自解码/规范化
             ├─ 各自切分边界
             └─ 各自取参数
差异 = 两层对同一字节的理解不同
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 至少两层 | 代理/缓存/应用 | 单层无差异 |
| 解析规则不同 | 长度/编码/路径 | 找其他层 |
| 差异可观察 | 日志/响应/缓存 | 建对照 |
| 能控制原始字节 | 改包 | 用工具 |

## 02 判断与分型

```text
现象是什么？
 ├─ 同 URL 不同人看到不同内容 → 缓存键
 ├─ 一个连接多个请求 → 走私
 ├─ WAF 放行但应用执行 → 解析/编码
 ├─ 缓存静态后缀却返回动态 → 路径
 └─ 入口正常但上游异常 → 多层
保存三份材料：原始请求、设备日志、应用日志
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| 同键响应不同 | 未键控输入 | 缓存投毒 |
| 响应错位 | 走私 | CL/TE |
| WAF 放行、应用报错 | 解析不同 | 编码/类型 |
| 同名参数多值 | 污染 | 看框架取值 |
| `.css` 返回 HTML | 路径/缓存 | 欺骗 |
| 内部地址出现 | 多层 | 下一跳 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 缓存命中 | 正常过期 | 换 URL |
| 一次错位 | 网络重试 | 多次复现 |
| WAF 观察模式 | 只记录 | 看应用日志 |
| 路径 404 | 路由不存在 | 换后缀 |

## 03 利用阶梯

### L0 标出层与原始字节

**前提**：有代理/缓存/WAF/应用中的至少两层。

**步骤**：
1. 看响应头 `Server`/`Via`/`X-Cache`/拦截页。
2. 保存原始请求（含 CRLF、CL/TE）。
3. 对比设备日志与应用日志的请求起止。
4. 记录每层版本/配置。

**成功标志**：知道哪两层、差异在哪一段。

**失败分支**：只有一层→无解析差异；日志不可见→用响应推断。

### L1 缓存键与未键控输入

**前提**：有共享缓存。

**步骤**：
1. 两次请求只改身份，看响应体/缓存头。
2. 改头/查询/路径，看是否命中同一键。
3. 找“影响正文但不在键里”的头。
4. 确认命中标记后再判断投毒。

**成功标志**：同键响应含攻击者输入/他人数据。

**失败分支**：键包含该头→换头；无缓存→换目标。

### L2 走私与长度

**前提**：前后端对 CL/TE 理解不同。

**步骤**：
1. 发缺结尾的 chunked，看是否挂起。
2. 试 CL.TE/TE.CL，观察多出响应。
3. 保存代理与应用日志的请求边界。
4. 只在自己的连接上验证。

**成功标志**：一个连接在应用日志里变成两个请求。

**失败分支**：400→换混淆；连接关闭→无法复用。

### L3 过滤与参数解析

**前提**：WAF/框架对参数/编码处理不同。

**步骤**：
1. 同名参数：`a=1&a=2`，看 WAF 与应用各取哪个。
2. 分块：把关键字拆到不同块。
3. `Content-Type`：表单/JSON/多部分切换。
4. 字符集：UTF-8/GBK 宽字节。
5. 注释/大小写：按数据库词法，不按关键词表。

**成功标志**：WAF 放行，应用收到可执行值。

**失败分支**：规则覆盖最终值→换编码；应用不解析→换类型。

### L4 多层与路径

**前提**：入口后面还有内部 HTTP 服务/网关。

**步骤**：
1. 记录入口主机/路径、响应中的内部地址。
2. 看代码里的上游地址/代理配置。
3. 路径规范化：`..;/`、编码、后缀，比较路由与缓存。
4. 只在授权范围访问下一跳。

**成功标志**：找到层间差异/内部服务。

**失败分支**：看不到下一跳→停在入口；路径统一→换入口。

## 04 绕过与边界

| 层 | 差异 | 利用 |
|---|---|---|
| 缓存 | 键 vs 正文 | 投毒/欺骗 |
| 代理 | CL vs TE | 走私 |
| WAF | 原文 vs 解码 | 分块/编码 |
| 框架 | 同名参数 | 污染 |
| 解析器 | Content-Type | 换解析 |
| 字符集 | UTF-8/GBK | 宽字节 |
| 路径 | 规范化/后缀 | 路由差 |

边界：缓存投毒影响共享用户；走私影响同连接；日志可能只记录解码后的值；不同框架对同名参数取值不同。

## 05 非典型入口

| 位置 | 示例 | 注意 |
|---|---|---|
| 头 | `X-Forwarded-*` | 未键控 |
| 查询 | `utm_*`/重复参数 | 键归一化 |
| 路径 | `;`/编码/后缀 | 路由 |
| 正文 | 分块/多部分 | 解析 |
| 字符集 | `charset` | 解码 |
| 上游 | 内部 URL | 多层 |

## 06 差异速查

| 框架/服务器 | 同名参数 | 路径 |
|---|---|---|
| PHP | 最后一个 | 规范化 |
| Express | 数组 | 严格 |
| Spring | 第一个/绑定 | 后缀匹配 |
| Nginx | 原样转发 | `merge_slashes` |
| Varnish | 键含 Host | 路径 |

## 07 工具与验证

| 目标 | 工具/命令 |
|---|---|
| 原始请求 | Burp/`curl --trace` |
| 缓存 | `curl -I` 看 `Age`/`X-Cache` |
| 走私 | Repeater/Turbo |
| 参数 | 手工多值 |
| 指纹 | `wafw00f` |
| 记录 | 原始字节/日志 |

验证顺序：层 → 原始字节 → 差异 → 影响 → 复现。

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 无差异 | 单层/规则一致 | 换目标 |
| 缓存不命中 | 键/规则 | 换 URL |
| 走私 400 | 严格 | 换混淆 |
| WAF 仍拦 | 解码后匹配 | 换编码 |
| 参数取值相同 | 框架一致 | 换参数 |
| 路径 404 | 路由 | 换后缀 |
