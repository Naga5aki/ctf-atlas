## 适用场景

题目要求输入 flag、口令或序列号，程序最终给出成功/失败提示。目标不是从反编译文本中猜字符串，而是把**每个输入字节怎样到达比较点**写成可检查的关系。

## 01 找入口与比较点

从输入函数、GUI 事件回调或参数解析开始；另一端找 `memcmp`、字符串比较、循环逐字节比较或布尔返回。`strings` 可以帮助定位提示文字，但其文件偏移不等于运行时虚拟地址，需要在反编译器里核对映射和交叉引用。

```bash
strings -a -n 5 -t x sample.bin | rg -i 'correct|wrong|flag|password|success'
objdump -d -M intel sample.elf | less
```

`objdump` 的架构选项要与样本匹配。若已在 Ghidra/IDA 中打开样本，优先从提示文字的交叉引用追到包含它的函数，再回溯输入。反编译代码只是辅助视图；遇到类型、符号扩展或数组边界不清楚时回看汇编。

## 02 建一张变换表

| 节点 | 必须记录 |
|---|---|
| 输入 | 长度、编码、是否含换行或 NUL，大小写是否被规范化 |
| 变换 | XOR、加减、移位、轮转、索引置换、分组加密的顺序 |
| 常量 | 比较数组、密钥、IV、查表，来源是立即数还是运行时计算 |
| 比较 | 比较长度、比较范围、提前退出条件、成功分支 |

把每个节点写成 `状态 i → 运算 → 状态 i+1`。例如多层变换应按实际执行顺序记录，逆推时才按相反顺序还原。对加法和 XOR 要明确字节截断；对 `char` 要确认是有符号还是无符号；对 32/64 位常量要明确小端序。

## 03 找不可逆与未确定部分

哈希、比较截断、带损失的取模或多对一映射不能简单“反过来算”。此时利用输入长度、字符集、已知前缀、局部约束或分支反馈缩小候选范围。若程序调用 AES/SM4 等算法，先确认工作模式、密钥、IV 与填充，不要将 API 名称直接等同于完整算法链。

## 04 回到原程序验证

保存每层中间字节（十六进制与长度），把候选输入送回与分析相同的样本版本。若结果不符，依次核对换行、Unicode 编码、数组终止符、字节序和比较长度。候选脚本输出一串看似可读字符，只是线索；程序真实通过才是验证证据。详见 [GUI 程序校验逻辑逆推](/knowledge/reverse-validation/)。
