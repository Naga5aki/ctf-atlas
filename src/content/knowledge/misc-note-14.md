## 一、基础单位换算

**所有对齐判断的基础单位：**

1个十六进制数位（半字节/nibble）=4 bit

1标准字节（Byte）=8 bit

ASCII原始标准为7-bit编码，文件存储中通常按1字节（8-bit）对齐

## 二、分场景补零规则

### 1.二进制转ASCII/字节

（1）独立分组的短二进制

**特征：** 空格、逗号分隔的多组二进制，每组长度≤8bit，转十进制落在可打印ASCII范围内

**规则：** 左侧补零到8位（高位补前导零）

**示例：** 1100001→补零为01100001→对应字符a

**补充：** 7-bit ASCII不补零数值本身也正确，补零仅为对齐标准字节的存储格式。

（2）连续比特流（bitstream）

**特征：** 无分隔符的长二进制串

**长度恰好为8的倍数：** 按8位分组，直接解析为字节

**长度不是8的倍数：** 禁止直接尾部补零，优先排查异常原因：

起始bit偏移错位

首尾丢失比特

LSB/MSB比特顺序颠倒

实际为7-bit ASCII等非8位编码

提取通道、提取范围错误

（3）LSB隐写专属规则

**尾部不足8位的残余比特：**

**优先处理方式：** 仅解析完整的8位字节，残余比特暂时保留或直接忽略

**禁止直接尾部补零凑字节：** 残余比特可能是原图原生LSB、超出隐写载荷的无效数据、填充位，并非有效隐藏内容

**首字节就乱码时：** 优先排查比特顺序、RGB通道顺序、起始偏移，而非补零

### 2.二进制↔十六进制

（1）二进制→十六进制

**规则：** 整数左侧补零到4的倍数，按4位为一组转换

**示例：** 二进制101011→左补2个零→0010 1011→十六进制2B

（2）十六进制→二进制

**规则：** 每个十六进制字符必须展开为固定4位，前导零不能省略

**示例：** 十六进制05→二进制0000 0101，不能简写为101

### 3.奇数长度十六进制

**分两种场景判断：**

**表示整数：** 左侧补0对齐为偶数位属于正常操作，例如ABC→0ABC

表示字节流/网络数据包/加密数据：优先怀疑缺失半个字节，不能默认补前导零，需结合上下文验证结构

### 4.固定宽度字段（文件/协议格式）

**规则：** 必须补足到字段规定的字节宽度，不能仅保留有效位

**典型示例：**

PNG IHDR宽高为4字节字段，数值1080（0x438）需写为00 00 04 38，不能只写04 38

ZIP 16位标志位，数值1需表示为0x0001，小端存储为01 00

### 5.常见固定位宽对应场景

| 位宽 | 常见对应场景 |
| --- | --- |
| 1 bit | 单比特、LSB隐写 |
| 4 bit | 十六进制半字节 |
| 5 bit | 培根密码、自定义字母编码 |
| 6 bit | Base64索引 |
| 7 bit | 标准ASCII |
| 8 bit | 标准字节 |
| 16 bit | UTF-16、WORD |
| 32 bit | DWORD、IPv4、CRC32 |

## 三、工具实操

CyberChef

**独立短二进制组：** 手动左补零到8位后，使用From Binary解码

**连续二进制串：** 直接使用From Binary，设置Byte Length=8即可，无需手动补零

**二进制转十六进制：** 直接串接From Binary→To Hex，工具自动处理对齐
