题目给出 Node、Python、Java 或 PHP 代码却没有明确入口时，目标不是读完所有文件，而是得到一张可逐项核查的表：**启动方式、公开路由、认证依赖、输入字段、关键操作、输出**。先静态清点，不要直接运行未知附件。

> 只在本地副本/授权源码上审计；解压归档前先核对路径穿越与大小，不覆盖工作区。

## 00 30 秒速查

| 我要… | 先做… | 备注 |
|---|---|---|
| 启动方式 | `package.json`/`Dockerfile`/`main` | 决定加载哪些文件 |
| 路由 | 注解/`app.get`/`include_router` | 列全方法 |
| 入口 | Query/Body/Header/Cookie/文件 | 每项都要 |
| 危险函数 | `query/include/system/render/readObject` | 反向搜 |
| 数据流 | 参数→赋值→sink | 正向追 |
| 过滤 | 解码/白名单/类型 | 看顺序 |
| 盲区 | 自定义头/静态/健康检查 | 过滤器排除表 |
| 验证 | 本地起服务 | 请求+响应 |

## 01 原理与成立条件

```text
启动入口 → 加载路由/中间件 → 请求 → 参数 → 过滤 → sink
                                                   ├─ 查询
                                                   ├─ 文件
                                                   ├─ 命令
                                                   └─ 模板
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 源码可读 | 题目/备份/镜像 | 黑盒 |
| 路由可列 | 文件/注解/配置 | 反编译 |
| 数据流可追 | 赋值/调用 | 动态调试 |
| 运行可复现 | 依赖/环境 | 只静态结论 |

## 02 判断与分型

```text
先从哪条路走？
 ├─ 已知参数 → 正向追到 sink
 ├─ 已知危险函数 → 反向找输入
 └─ 已知功能 → 按步骤查权限
三条路结果对不上？
 ├─ 正向有入口无 sink → 可能封装
 ├─ 反向有 sink 无输入 → 找隐藏入口
 └─ 功能有页面无接口 → 找同名 API
```

| 路线 | 起点 | 容易漏 |
|---|---|---|
| 正向 | 请求参数 | 队列/定时任务入口 |
| 反向 | 危险函数 | 项目封装函数 |
| 功能 | 登录/支付/上传 | 同名接口/旧版本 |

| 信号 | 含义 | 下一步 |
|---|---|---|
| `app.get`/`@RequestMapping` | 路由 | 列方法 |
| `req.query`/`$_GET` | 入口 | 追赋值 |
| `query(` 拼接 | SQL | 看绑定 |
| `include`/`readFile` | 文件 | 看路径 |
| `system`/`exec` | 命令 | 看拼接 |
| `render_template_string` | 模板 | 看拼接 |
| 过滤器只绑查询 | 盲区 | 看头/路径 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 看到危险函数 | 参数不可控 | 跟数据流 |
| 有过滤器 | 只覆盖部分 | 看排除表 |
| 路由存在 | 需认证 | 看中间件 |
| 源码旧 | 线上已改 | 以运行态为准 |

## 03 利用阶梯

### L0 目录与启动

**前提**：有源码包/镜像。

**步骤**：
1. 看目录树、依赖锁、`.env` 模板、启动脚本。
2. Node：`package.json` 的 scripts、路由注册、中间件顺序。
3. Python：应用实例、router、依赖注入。
4. Java：JAR 清单/类列表，必要时反编译。
5. 记录运行命令与端口。

**成功标志**：知道入口文件与加载顺序。

**失败分支**：混淆/打包→反编译；无启动脚本→看文档/镜像。

### L1 建立路由表

**前提**：能定位路由注册。

**步骤**：
1. 列方法、完整路径、模块、是否需会话。
2. 记输入来源：Query/Body/Header/Cookie/文件。
3. 记转换：解析器、类型、校验、过滤顺序。
4. 记敏感操作与输出。

**成功标志**：一张可逐项验证的路由表。

**失败分支**：动态注册→搜字符串/调试；路由前缀→看配置。

### L2 正向数据流

**前提**：有一个可控参数。

**步骤**：
1. 从参数出发，跟每一次赋值/拼接/函数调用。
2. 标出每层是解码、白名单、类型转换还是直接拼接。
3. 追到查询/文件/命令/模板/响应。
4. 构造最小请求验证。

**成功标志**：参数到 sink 的完整链 + 可复现请求。

**失败分支**：链断→换参数；封装→看函数实现。

### L3 反向危险函数

**前提**：路由表不完整或入口未知。

**步骤**：
1. 列本语言 sink：`query/exec/system/include/render/readObject`。
2. 搜项目包装函数（可能改名）。
3. 倒查调用者与参数来源。
4. 对每个候选标“可达/需认证/不可控”。

**成功标志**：找到被正向漏掉的入口。

**失败分支**：全不可控→回 L2；封装深→动态调试验证。

### L4 过滤器盲区与验证

**前提**：有全局过滤器/WAF/中间件。

**步骤**：
1. 二次解码：过滤器解码一次，应用又解码一次。
2. 头/Cookie/路径未进规则。
3. 白名单路由（管理/静态/健康检查）仍执行敏感操作。
4. 把过滤器看到的字符串与应用日志参数并排。
5. 本地起服务复现。

**成功标志**：请求绕过过滤器到达 sink。

**失败分支**：规则覆盖最终值→换入口；无法复现→只留静态结论。

## 04 绕过与边界

| 缺口 | 代码形态 | 验证 |
|---|---|---|
| 二次解码 | 过滤器 `decode` 后应用再 `decode` | 双编码 |
| 头未覆盖 | 规则只绑 query/body | 自定义头 |
| 白名单路由 | 静态/健康检查排除 | 路径变体 |
| 封装 sink | 帮助函数改名 | 搜实现 |
| 顺序错误 | 先拼后过滤 | 看调用序 |

边界：过滤器日志“已拦截”不代表应用没处理另一条值；源码旧版要与运行态对照；主机权限与 Web 漏洞分开记录。

## 05 非典型入口

| 位置 | 示例 | 注意 |
|---|---|---|
| 消息队列 | 消费者 | 无 HTTP |
| 定时任务 | cron/worker | 参数来源 |
| 自定义头 | 租户/内部标记 | 过滤器盲区 |
| 静态路由 | 上传/下载 | 鉴权 |
| 健康检查 | `/health` | 排除表 |
| WebSocket | 帧 | 另一套解析 |

## 06 差异速查

| 语言 | 路由 | 入口 |
|---|---|---|
| PHP | 文件/框架 | 超全局 |
| Node | `app.get`/router | `req.*` |
| Python | 装饰器/蓝图 | `request.*` |
| Java | 注解/web.xml | 绑定 |

| 过滤 | 作用 | 盲区 |
|---|---|---|
| 中间件 | 统一处理 | 排除路由 |
| WAF | 网络层 | 编码/分块 |
| 类型转换 | 限值 | 数组/对象 |
| 白名单 | 限字符 | 等价语法 |

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 路由找不到 | 动态/前缀 | 搜字符串 |
| 参数不可控 | 覆盖/默认值 | 跟赋值 |
| sink 被封 | 封装 | 搜实现 |
| 过滤器挡住 | 最终值 | 换编码 |
| 本地跑不起 | 依赖/配置 | 看 Dockerfile |
| 线上不一致 | 版本 | 以运行态为准 |
