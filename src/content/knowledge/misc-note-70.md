## 一、核心原理

**最典型的题：** 给你一张 BMP，肉眼看着可能正常或很杂乱，普通分析没明显结果，但它的某个 RGB 通道最低位存在规律。把每个像素按最低位的奇偶性二值化后，就会显现出二维码。

**经典做法：** BMP 的像素最低位偶数映射成黑、奇数映射成白，最后得到 QR Code。

核心流程

BMP 像素值

↓

取某个通道的最低 1 bit

↓

0 → 黑

1 → 白

↓

重新组成黑白图

↓

二维码

↓

扫码得到 flag

**举例：**

| 像素值 | 二进制末位 | bit | 颜色 |
| --- | --- | --- | --- |
| 120 | ...0 | 0 | 黑 |
| 121 | ...1 | 1 | 白 |
| 200 | ...0 | 0 | 黑 |
| 203 | ...1 | 1 | 白 |

出题人并不是把二维码 "文件" 塞进 BMP，而是把二维码的黑白模块编码到像素最低位里。

## 二、识别特征

遇到下面情况可以优先想到 BMP 转二维码：

载体是 BMP

图片肉眼没有明显二维码

StegSolve 普通视图没东西，但切换 Red plane 0 / Green plane 0 / Blue plane 0 时出现规则黑白块

图片最低位明显呈现方阵结构

题目提示 low、LSB、RGB、QR、二维码、奇偶

## 三、标准解法：StegSolve

### 1. 查看 bit plane 0

StegSolve → 打开 BMP → 不断切换：

Red plane 0 / Green plane 0 / Blue plane 0

重点看 bit plane 0，也就是最低位。

如果看到规则黑白块，并逐渐形成二维码三个明显的大定位块：

基本就确定了。

有些旧题 / 工具对 BMP 显示不理想，已有 Writeup 会先无损另存为 PNG 再用 StegSolve 查看 RGB 最低位。原则上应保留原文件副本，避免随意有损转换。

### 2. 如果黑白反了

二维码可能显示为白模块 ↔ 黑模块，直接：

StegSolve → Invert

或用图像软件反相后再扫码。

### 3. 如果只有一个通道有二维码

**比如：**

Red plane 0 → 二维码

Green plane 0 → 噪声

Blue plane 0 → 噪声

所以一定要分别检查 R bit0、G bit0、B bit0，而不是只看 RGB 合并结果。

## 四、与普通 LSB 的区别

| 类型 | 处理方式 | 结果 |
| --- | --- | --- |
| 普通 LSB 隐写 | 提取 bit 流 → 01100110... → 转 ASCII / 文件 | 一串连续字节 |
| BMP 转二维码 | 提取 bit 平面 → 保持二维空间位置 → 直接形成黑白图 → 扫二维码 | 二维二维码图案 |

它本质上仍然属于 LSB 隐写，只不过隐藏内容不是一串连续字节，而是一个二维二维码图案。
