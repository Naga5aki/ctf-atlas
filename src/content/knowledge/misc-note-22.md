## 一、核心原理

### 1.攻击对象

仅针对传统PKWARE加密（ZipCrypto），属于流加密结构，内部状态由三个32位密钥（K0/K1/K2）维护。AES-128、AES-256等强加密无法用该方法攻击。

### 2.攻击本质

通过足够的明密文对应对，恢复ZipCrypto的三个内部密钥状态，而非ZIP的原始密码；得到内部密钥后即可直接解密、去除密码或重设密码，无需知道原密码。

### 3.加密链路

原始文件→压缩处理→ZipCrypto加密→ZIP内的密文数据

**核心关键：** ZipCrypto加密的是压缩后的数据，而非原始文件本身。

**Store模式：** 不压缩，加密数据=原始文件字节

**Deflate模式：** 加密数据=Deflate压缩后的字节流，与原始文件字节不同

### 4.明文门槛

官方要求至少12字节已知明文，其中至少8字节连续；连续字节越多，攻击速度越快、成功率越高。

## 二、前置检查与信息确认

### 1.查看压缩与加密信息

拿到加密ZIP后第一步执行，确认是否符合攻击条件：

bkcrack-L challenge.zip

输出包含每个条目的加密方式、压缩方式、CRC32、未压缩大小、压缩后大小、文件名等信息，可直接确认是否为ZipCrypto加密、是Store还是Deflate。

### 2.攻击成立的硬条件

加密算法必须为ZipCrypto

可获取至少12字节对应位置的已知明文（≥8字节连续）

## 三、Store与Deflate的核心区别

### 1.Store模式

特点

原始文件不压缩，加密前的明文就是原始文件字节，原始文件偏移与密文偏移一一对应。

优势

可直接利用文件头、固定格式字段、已知文本片段作为明文，攻击成本极低。

典型明文来源

标准文件头（如PNG前16字节高度固定）

已知固定字符串（如flag{开头）

格式填充字节（如大量0x00填充）

### 2.Deflate模式

特点

原始文件经Deflate压缩后再加密，加密前的明文是压缩数据流，原始文件字节不能直接作为明文使用。

难点

压缩软件、压缩级别、Deflate实现差异，都会导致压缩后的字节流不同；必须得到与原ZIP字节级完全一致的压缩数据，攻击才能成功。

纠正认知

❌Deflate不能明文攻击

✅可以攻击，但必须重现压缩后的字节流，难度远高于Store模式；即使有完整原始文件，也不一定能生成匹配的压缩流。

| 错误认知 | 正确结论 |
| --- | --- |
| CRC32一致说明压缩参数匹配 | CRC32校验的是未压缩的原始文件内容，与压缩流无关；不同压缩参数可得到相同CRC32 |
| ZIP Version字段可精确判断压缩软件 | 该字段是ZIP规范版本号，并非压缩软件ID，不能用来判定WinRAR/7-Zip等工具 |
| 删除加密项重加明文可100%复刻压缩流 | 重新添加会由当前工具重新压缩，生成新的压缩流，不会继承原参数 |
| Packed Size相同说明压缩流相同 | 仅长度一致，内容可能完全不同，仅能作为辅助筛选线索 |

## 四、三大经典攻击场景

### 场景1：Store+完整已知文件

最简单的场景，已知完整原始文件，直接对应明文。

bkcrack-C encrypted.zip-c known.png-p known.png

### 场景2：Store+可预测固定字节

无需完整文件，利用文件格式的固定字节作为明文。

**典型示例：** PNG文件头前16字节高度固定，可直接作为明文

bkcrack-C challenge.zip-c secret.png\

-x 0 89504e470d0a1a0a0000000d49484452

**注意：** 生成精确明文推荐用printf，避免echo自动添加换行符干扰字节。

### 场景3：Deflate+完整已知文件

先尝试用相同工具、压缩级别重新压缩生成明文ZIP，尽可能复现原压缩流。

bkcrack-C encrypted.zip-c known.jpg\

-P plain.zip-p known.jpg

**说明：** 这是官方推荐的归档对归档用法，是否成功取决于压缩流是否完全匹配。

## 五、攻击成功后的处理

攻击成功后会输出三个32位十六进制值，即ZipCrypto的内部密钥K0 K1 K2。

### 1.直接去除密码

生成无密码的新ZIP，自动保留原压缩方式，后续可直接用常规解压工具打开，无需手动处理压缩流。

bkcrack-C challenge.zip-k K0 K1 K2-D decrypted.zip

### 2.重设自定义密码

将ZIP密码改为自己指定的新密码，注意新密码是自定义值，并非破解出的原密码。

bkcrack-C challenge.zip-k K0 K1 K2-U unlocked.zip 123456

### 3.单文件解密

仅解密单个条目，输出原始加密前的数据：

bkcrack-C challenge.zip-c file.txt-k K0 K1 K2-d decrypted.bin

**Store模式：** 输出即为原始文件

**Deflate模式：** 输出是原始Deflate压缩流，并非乱码，需自行解压（可配合官方inflate.py工具）

### 4.密钥复用

若确认其他ZipCrypto加密的ZIP使用了相同密码，可直接复用已恢复的内部密钥解密。

## 六、高频易错点汇总

| 错误认知 | 正确结论 |
| --- | --- |
| bkcrack可以攻击AES加密的ZIP | 仅支持ZipCrypto传统加密 |
| 攻击成功会得到原始密码 | 得到的是内部密钥状态，不是原密码 |
| Deflate模式下原文件片段可直接当明文 | 加密的是压缩流，必须用压缩后的字节 |
| CRC32相同说明压缩流一致 | CRC32校验原始文件，和压缩流无关 |
| ZIP版本号可判断压缩软件 | 是规范版本号，不是软件标识 |
| 删除重加可复刻原压缩流 | 会重新生成压缩流，不继承原参数 |
| -d输出乱码说明解密失败 | Deflate模式下输出的是压缩流，需自行解压 |
| 所有文件头都有12字节固定内容 | 多数文件仅Magic固定，长度不足；PNG是少数前16字节高度固定的格式 |
