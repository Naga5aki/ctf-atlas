逻辑漏洞不靠 payload，而靠**对业务状态机的理解**：本该“先检查再扣减”的操作被拆成两步，或“只能一次”的校验没有原子性。并发题的核心是让多个请求在同一时间窗口内通过检查。

> 只对本地题目或授权环境测试；并发请求可能造成数据异常，先备份/快照。

## 00 30 秒速查

| 我要… | 看… | 备注 |
|---|---|---|
| 找并发点 | `stock`/`balance`/`limit`/`used` | 先检查后写入 |
| 证明只能一次 | 串行发两次 | 第二次应失败 |
| 单连接并发 | Turbo Intruder `BURP2` | gate 放行 |
| 多线程 | 独立 Session | 先 10 后加 |
| curl 并行 | `xargs -P` | 小批量 |
| 放大窗口 | 慢请求/分块 | 时长可控 |
| 判定 | 余额/库存/订单数 | 不只看状态码 |
| 失败 | 行锁/唯一索引/幂等 | 换点 |

## 01 原理与成立条件

```text
请求A ─┐
请求B ─┼─ 同时通过“检查” → 各自写入 → 多份收益
请求C ─┘
前提：检查与写入不是原子操作
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 非原子 | 先查后写/无锁 | 换接口 |
| 同一状态 | 同一账号/券/库存 | 多账号 |
| 时间窗 | 请求能同时到达 | 放大窗口 |
| 可观察 | 余额/库存/订单 | 找间接指标 |
| 授权 | 本地/书面 | 停 |

| 类型 | 例子 | 结果 |
|---|---|---|
| 并发兑换 | 优惠券/积分/礼品码 | 一码多用 |
| 并发下单 | 库存 1 件 | 超卖 |
| 并发提现 | 余额 100，提现 100×N | 负数/多倍 |
| 并发注册 | 同一手机号/邮箱 | 多账号 |
| 状态跳跃 | 未支付→已发货 | 白嫖 |
| 次数绕过 | 抽奖/签到/验证码 | 多次奖励 |

## 02 判断与分型

```text
操作是否“只能一次”？
 ├─ 是 → 串行第二次是否失败？
 │        ├─ 失败 → 试并发
 │        └─ 成功 → 是普通逻辑缺陷
 └─ 否 → 看状态机能否跳步
有唯一索引/行锁吗？
 ├─ 有 → 并发难，转逻辑/越权
 └─ 无 → 优先并发
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| `SELECT` 后 `UPDATE` | 检查写入分离 | 并发 |
| 无唯一索引 | 可重复插入 | 并发注册 |
| `used=0` 判断 | 非原子 | 多请求 |
| 库存/余额字段 | 可量化 | 记录变化 |
| 第二次串行失败 | 有校验 | 抢窗口 |
| 第二次串行成功 | 无校验 | 逻辑漏洞 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 多请求都 200 | 异步排队 | 看最终状态 |
| 余额没变 | 后续回滚 | 查订单/流水 |
| 库存暂减 | 缓存 | 等结算 |
| 并发失败 | 行锁/队列 | 换接口 |
| 一次成功 | 窗口没撞上 | 加轮次 |

## 03 利用阶梯

### L0 定位与串行基线

**前提**：已登录，找到“只能一次”的操作。

**步骤**：
1. 标出接口、参数、业务含义。
2. 串行发两次，记录第二次响应。
3. 记录初始余额/库存/订单数。
4. 确认判定指标（不是只看 200）。

**成功标志**：串行第二次失败，指标可读。

**失败分支**：第二次成功→转逻辑漏洞；指标不可见→找流水/订单页。

### L1 小批量并发

**前提**：串行基线成立。

**步骤**：
1. 10 个并发起步，观察状态码分布。
2. 每请求独立 Session/Cookie。
3. 结束后重新登录看余额/库存/订单。
4. 记录成功次数与净收益。

```python
import threading, requests
URL = "http://target/api/redeem"
COOKIE = {"session": "..."}
def hit():
    r = requests.post(URL, json={"code": "GIFT"}, cookies=COOKIE, timeout=10)
    print(r.status_code, r.text[:80])
ts = [threading.Thread(target=hit) for _ in range(10)]
for t in ts: t.start()
for t in ts: t.join()
```

**成功标志**：净收益 > 1 或订单数 > 1。

**失败分支**：全失败→窗口没撞上；429→降并发；余额回滚→查异步。

### L2 单包/同连接并发

**前提**：网络抖动让多线程撞不上。

**步骤**：
1. Turbo Intruder 用 `Engine.BURP2`、`concurrentConnections=1`。
2. 所有请求 `queue(..., gate='race1')`。
3. `openGate('race1')` 同时放行。
4. 看响应表与最终状态。

```python
def queueRequests(target, wordlists):
    engine = RequestEngine(endpoint=target.endpoint,
                           concurrentConnections=1,
                           engine=Engine.BURP2)
    for i in range(30):
        engine.queue(target.req, gate='race1')
    engine.openGate('race1')

def handleResponse(req, interesting):
    table.add(req)
```

**成功标志**：多次成功落在同一时间窗。

**失败分支**：HTTP/1.1 被复用→换 H2/多连接；仍失败→放大窗口。

### L3 多连接与窗口放大

**前提**：单连接仍撞不上，或目标是慢操作。

**步骤**：
1. 多连接并发 + 多轮重试（每轮重新取状态）。
2. 用大文件/慢请求/分块卡住检查阶段。
3. 上传竞争：先传临时文件，删除前访问。
4. 组合接口：领取与使用分开打。
5. 记录每轮时间窗与成功数。

```bash
seq 1 30 | xargs -P30 -I{} curl -s -o /dev/null -w '%{http_code}\n' \
  -b 'session=...' -X POST http://target/api/redeem -d 'code=GIFT'
```

**成功标志**：稳定复现多次收益。

**失败分支**：全局限流→降速/换号；锁表→换接口；窗口不可控→放弃并发转逻辑。

### L4 状态机与组合

**前提**：并发受限，但业务步骤有校验缺口。

**步骤**：
1. 直接请求最后一步（跳过支付/审核）。
2. 复用一次性 token/验证码。
3. 篡改价格、数量、角色字段。
4. 多账号/多券叠加。
5. 把“并发 + 跳步”组合，记录最小请求集。

**成功标志**：以更少请求达到同样收益。

**失败分支**：服务端重算→改数量/币种；状态绑定→换会话；全失败→回归并发。

## 04 绕过与边界

| 场景 | 边界 | 处理 |
|---|---|---|
| 行锁/事务 | 并发被串行化 | 换无锁接口 |
| 唯一索引 | 重复插入失败 | 换字段/多账号 |
| 幂等键 | 重复请求被丢弃 | 换 key/去 key |
| 限流 | 429/503 | 降并发/加间隔 |
| 异步队列 | 响应 200 但回滚 | 看最终状态 |
| 前端校验 | 只改前端 | 直接打接口 |
| 金额重算 | 改价无效 | 改数量/优惠 |

边界：并发不等于越多越好；每轮后状态会变，必须重新基线；`requests.Session` 非线程安全；测试结束回滚数据。

## 05 非典型入口

| 入口 | 手法 | 注意 |
|---|---|---|
| 文件上传 | 删除前访问/竞争 | 临时文件 |
| 邀请/分享 | 同码多次 | 归因 |
| 退款 | 退款与撤销并发 | 双向 |
| 抽奖 | 多请求同随机种子 | 看流水 |
| WebSocket | 同帧并发 | 帧顺序 |
| 队列消费 | 重复投递 | 幂等 |

## 06 差异速查

| 工具 | 并发模型 | 适用 |
|---|---|---|
| Turbo Intruder | 同连接 gate | H2 单包 |
| Python 线程 | 多连接 | 通用 |
| curl `-P` | 多进程 | 快速验证 |
| httpx/asyncio | 异步 | 高并发 |
| Burp Repeater | 手工 | 基线 |

| 现象 | 含义 | 处理 |
|---|---|---|
| 多个 200 | 可能成功 | 查最终状态 |
| 一个 200 其余 4xx | 锁生效 | 换点 |
| 全部超时 | 服务过载 | 停/降速 |
| 余额先增后减 | 回滚 | 看流水 |
| 库存为负 | 超卖 | 记录证据 |

## 08 实战流程

| 阶段 | 动作 | 产出 |
|---|---|---|
| 1 找点 | 唯一性/余额/库存 | 目标接口 |
| 2 基线 | 串行两次 | 应失败 |
| 3 并发 | 10→30→单包 | 成功数 |
| 4 放大 | 慢请求/多轮 | 稳定复现 |
| 5 组合 | 跳步/复用 | 最小集 |
| 6 记录 | 前后状态 | 证据 |

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 并发全失败 | 行锁/幂等 | 换接口 |
| 都没有净收益 | 异步回滚 | 查流水 |
| 429 | 限流 | 降并发 |
| 窗口撞不上 | 网络抖动 | 单包/放大 |
| 第二次串行成功 | 非并发问题 | 转逻辑 |
| 环境被污染 | 未回滚 | 重建/快照 |
