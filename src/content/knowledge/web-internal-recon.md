内网题的第一步不是扫全网，而是**确认自己站在哪、能去哪、拿什么去**。先把本机信息、路由、ARP、凭据收干净，再决定隧道与扫描方式。

> 只对授权靶场的内网操作；扫描前确认网段范围，避免打到题目之外的地址。

## 00 30 秒速查

| 我要… | 先看… | 备注 |
|---|---|---|
| 我是谁 | `id`/`whoami /all` | 权限/组 |
| 我在哪 | `ip a`/`ip route`/`ipconfig` | 双网卡 |
| 同网段 | `arp -a`/`arp-scan` | 先 /24 |
| 内网段 | 路由/`resolv.conf` | 下一跳 |
| 开放服务 | `ss -lntup`/`netstat` | 本机先看 |
| 已有凭据 | 历史/配置/SSH | 先复用 |
| 怎么出去 | ssh/frp/chisel | 看协议 |
| 代理扫描 | `proxychains4 nmap -sT` | 不用 -sS |
| 记录 | 每层入口/出口 | 防断链 |

## 01 原理与成立条件

```text
入口机 → 本机枚举 → 路由/ARP → 网段
                     ├─ 直接可达 → 扫描
                     ├─ 需跳板 → 隧道
                     └─ 凭据 → 横向
隧道 = 把内网端口/SOCKS 映射到可达位置
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 有命令执行 | shell/webshell | 先拿点 |
| 路由可达 | 双网卡/转发 | 找跳板 |
| 出网/入站 | 协议/端口 | 换隧道 |
| 凭据 | 口令/密钥 | 找配置 |

## 02 判断与分型

```text
先看自己：
 ├─ 单网卡 → 只能打同段
 ├─ 双网卡 → 可进内网
 └─ 有域/凭据 → 横向
再看出口：
 ├─ 能出 TCP → ssh/frp/chisel
 ├─ 只能 HTTP → reGeorg/chisel ws
 ├─ 只能 DNS/ICMP → 慢速隧道
 └─ 不能出 → 正向/端口转发
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| 多默认路由 | 多网卡 | 列网段 |
| `10./172./192.168` | 内网 | 扫 /24 |
| 本机监听 3306/6379 | 本地服务 | 弱口令/未授权 |
| `.ssh/id_*` | 密钥 | 试登录 |
| 历史命令含密码 | 凭据 | 复用 |
| 域环境 | AD | 见域渗透页 |
| 只允许 80/443 | HTTP 隧道 | chisel/reGeorg |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| ARP 有主机 | 网关/广播 | 逐端口确认 |
| 端口开放 | 服务假死 | 看 banner |
| 凭据可登录 | 权限低 | 看 sudo/组 |
| 隧道建立 | DNS 泄漏 | 看解析 |

## 03 利用阶梯

### L0 本机枚举

**前提**：有命令执行。

**步骤**：
1. Linux：`id`/`hostname`/`uname -a`/`ip a`/`ip route`/`ss -lntup`。
2. Windows：`whoami /all`/`ipconfig /all`/`route print`/`netstat -ano`。
3. 看历史、配置、SSH 密钥、环境变量。
4. 记录用户/权限/网卡/监听。

**成功标志**：知道权限、网段、本机服务、凭据线索。

**失败分支**：命令受限→换解释器/读文件；无权限→找提权。

### L1 网段与主机发现

**前提**：有内网网卡/路由。

**步骤**：
1. 先 `arp -a`/`ip neigh` 看邻居。
2. `nmap -sn 10.0.0.0/24` 或 `arp-scan -l`。
3. 只扫题目范围，先 /24 再扩展。
4. 记录存活主机与网关。

**成功标志**：一张存活主机表。

**失败分支**：无 ARP→换网段；全超时→隧道/路由问题。

### L2 端口与服务

**前提**：有存活主机。

**步骤**：
1. 本机优先 `ss -lntup`，避免扫自己。
2. 通过代理用 `nmap -sT -Pn -sV`，不用 `-sS`。
3. 常见端口：22/80/443/445/1433/3306/6379/8080/9000。
4. 看 banner/版本，标可疑服务。

**成功标志**：服务/版本清单。

**失败分支**：全 filtered→隧道/ACL；版本不明→手工 banner。

### L3 凭据复用与第一跳

**前提**：有凭据/密钥。

**步骤**：
1. 列“凭据 → 可登录目标”矩阵。
2. 试 SSH/MySQL/RDP/Web 后台同口令。
3. 读数据库/Redis 配置里的下一跳。
4. 先复用再考虑爆破，避免锁定。

**成功标志**：登录到下一台/读到下一跳配置。

**失败分支**：口令失败→看来源是否过期；锁定→停。

### L4 隧道与多层

**前提**：需要跨网段访问。

**步骤**：
1. 能出 TCP：`ssh -D 1080 -N -f`、frp、chisel。
2. 只能 HTTP：chisel `--reverse`/reGeorg。
3. 多级：EW/Venom，逐层映射 SOCKS。
4. `proxychains4` 配 `socks5 127.0.0.1 1080`，开 `proxy_dns`。
5. 每层记入口/出口 IP/端口，断链先查进程/防火墙。

**成功标志**：代理下能访问下一层服务。

**失败分支**：协议被拦→换 HTTP/DNS；不稳定→减层/保活。

## 04 绕过与边界

| 限制 | 替代 | 示例 |
|---|---|---|
| 不能出 TCP | HTTP/WS 隧道 | chisel |
| 只能 DNS | DNS 隧道 | dnscat2 |
| 只能 ICMP | ICMP 隧道 | ptunnel |
| 无入站 | 正向/反弹 | 看方向 |
| 代理扫描 | `-sT -Pn` | 超时调大 |
| DNS 泄漏 | `proxy_dns` | proxychains |
| 锁定 | 先复用/降速 | 停 |

边界：SYN 扫描需原始套接字；多层链每增加一跳都增延迟；隧道进程可能被杀；凭据有有效期；扫描范围以授权为准。

## 05 非典型入口

| 位置 | 示例 | 注意 |
|---|---|---|
| Web 后台 | 命令/文件管理 | webshell |
| 数据库 | `LOAD_FILE`/`xp_cmdshell` | 权限 |
| Redis | 写文件/主从 | 见 SSRF |
| CI/CD | 变量/runner | 授权 |
| 云主机 | 元数据 | 见云页 |
| 邮件/备份 | 凭据 | 复用 |

## 06 差异速查

| 隧道 | 方向 | 适用 |
|---|---|---|
| `ssh -L` | 本地 | 单端口 |
| `ssh -R` | 远程 | 内网映射 |
| `ssh -D` | 动态 | SOCKS |
| frp | 反向 | 稳定 |
| chisel | 双向 | HTTP/WS |
| EW/Venom | 多级 | 级联 |
| reGeorg | 正向 | 仅 Web |

| 系统 | 枚举 | 注意 |
|---|---|---|
| Linux | `ip`/`ss`/`capsh` | 权限 |
| Windows | `whoami /all`/`netstat` | 域 |

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 扫不到 | 路由/ACL | 换网段/隧道 |
| 全 filtered | 防火墙 | 换端口/协议 |
| 登录失败 | 凭据过期 | 找新凭据 |
| 隧道断 | 进程/端口 | 重建/保活 |
| DNS 泄漏 | 解析 | `proxy_dns` |
| 代理慢 | 多层 | 减层/超时 |
