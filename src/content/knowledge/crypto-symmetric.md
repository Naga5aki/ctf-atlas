## 适用场景

题目给出 AES/SM4、异或、循环移位、多密钥轮次或自定义 C/Python 变换时使用。把“拿到密钥”与“按正确方式解密”分开；模式、IV、nonce、填充和字节顺序都可能影响结果。

## 01 先画流水线

写成 `输入字节 → 编码 → 密钥派生 → 模式/轮次 → 输出表示`，逐段记录输入输出长度。若出现三个密钥，要确认它们是连续加密、加密-解密-加密，还是只参与轮密钥生成；仅凭变量名不能判断。对自定义算法，从实际循环顺序、整数宽度和溢出规则推导逆过程。

| 项目 | 必须确认 |
|---|---|
| 密钥 | 原始口令、哈希/截断方式、实际使用字节数 |
| 模式 | ECB、CBC、CTR、GCM 等；加密和解密是否同一模式 |
| IV/nonce | 来源、长度、是否随密文一起保存、计数器初值 |
| 填充与标签 | 何时加/去填充，认证标签放在何处 |
| 块顺序 | 是否有字节交换、反转、拼接或按块重排 |

CTR 以计数器生成密钥流，不使用分组填充；CBC 需要按块长处理明文并在解密时正确去填充。认证模式还必须验证标签。不要拿“解出可打印字符”代替完整校验。

## 02 做最小往返测试

先用一组明确的短输入，运行题目实现的加密函数，记录每层输出；然后用自己写的逆过程从末层返回，并逐字节比较是否回到原输入。若只能取得密文而不能运行原算法，就利用公开的明文格式、长度和校验关系做约束，但明确标记尚未完成往返验证。

```python
plain = bytes.fromhex("00112233")  # 演示用输入
encoded = bytes(value ^ 0x5A for value in plain)
assert encoded.hex() == "5a4b7869"
decoded = bytes(value ^ 0x5A for value in encoded)
assert decoded == plain
```

上例只演示“已知输入 → 变换 → 逆变换”的往返检查，并不是任何题目的实际加密算法。正式记录中应保存每层十六进制、差异出现的首个偏移以及所用参数，避免最终结果不对时从头重猜。
