Piet 题最重要的不是研究语法，而是看到图片时能快速联想到它可能是一段程序。Piet 本身是以画家 Piet Mondrian 命名的视觉编程语言，图片由规则纯色色块组成，颜色块本身就是指令。

**与普通图片隐写的关键区别：** 这张图片可能不是 "藏着数据"，而是图片本身就是可执行程序。

## 一、题目识别

典型图片特征

优先怀疑 Piet 的情况：

图片由大量规则的小色块、小像素块组成

颜色非常鲜艳，常见红、黄、绿、青、蓝、紫及其深浅变化

经常同时存在大量白色背景和黑色区域

图片看起来像彩色条带、像素画、抽象画，肉眼看不出正常内容

放大后可以明显看到规则的矩形颜色块

**典型外观：** 白底 + 大量规则纯色像素块 + 红黄绿青蓝紫反复出现。

题目提示特征

看到这些关键词基本可以直接考虑 Piet：

piet / npiet / color / colour / paint / pixel / codel / Mondrian

尤其题目出现 Mondrian（蒙德里安） 时要高度敏感，因为 Piet 本身就是以画家 Piet Mondrian 命名。

## 二、标准解题方法：npiet 直接运行

拿到疑似 Piet 图片，首选 npiet。

\# Windows

.\npiet.exe challenge.png

\# Kali/Linux

npiet challenge.png

如果题目比较简单，终端会直接输出 flag{xxxxxxxx}。

**比赛中的第一步非常简单：** 可疑 Piet 图片 → 直接 npiet 执行 → 看输出。不要一开始就手工分析颜色对应什么指令。

## 三、没有直接输出怎么办（排查流程）

### 1. 用 -t 看执行过程

npiet -t challenge.png

输出程序运行轨迹，包括：当前位置、颜色变化、执行的指令、栈中的数据、程序移动方向。

**适合判断：** 程序到底有没有正常执行、程序是不是卡住、是不是正在等待输入。

普通运行什么都不显示，不要马上认为失败，可以用 npiet -t 确认程序状态。

### 2. 用 -tpic 生成运行路径图

npiet -tpic challenge.png

运行后会生成 npiet-trace.png，用图片形式显示解释器实际走过的路线。

**适合：** 程序路径异常、死循环、某些区域没有被执行、想确认解释器是否正确识别图片。

| 参数 | 输出形式 |
| --- | --- |
| -t | 文字执行轨迹 |
| -tpic | 图形化执行路线 |

### 3. 检查是不是在等待输入

Piet 程序支持输入。执行后没有输出、光标停在那里，有可能不是崩溃，而是在等待数字、字符、密码、题目给出的某个值。此时结合题目描述尝试输入：

npiet challenge.png

12345

程序可能随后输出结果。

## 四、Codel Size：最常见的运行失败原因

Piet 的基本单位叫 Codel，可以理解成 "逻辑像素"。但题目为了方便显示，可能把 1 个 Codel 放大成 5×5、10×10、20×20 实际像素。

例如肉眼看到一个大色块，在程序里可能实际上只是 1 个 Codel。

npiet 一般会自动判断，但自动判断失败时需要手动指定：

\# 5×5 像素 = 1 个 Codel

npiet -cs 5 challenge.png

\# 10×10 像素 = 1 个 Codel

npiet -cs 10 challenge.png

图片明显是 Piet + npiet 运行结果异常，优先尝试 -cs 2、-cs 3、-cs 4、-cs 5、-cs 10...，具体数值根据色块大小判断。

## 五、不要修改图片本身

Piet 非常依赖颜色。原题图片不要：

截图、缩放、压缩

调色、加滤镜

转 JPEG、重新保存

尤其不要 PNG → JPG，因为 JPEG 是有损压缩，会把原本精确的颜色 FF 00 00 改成类似 FC 02 01，导致 npiet 可能无法正确识别指令。

**正确做法：** 原始 PNG 直接交给 npiet。
