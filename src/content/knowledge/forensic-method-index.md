## 01 按分析任务定位证据

本页用于把一个待验证的问题拆成“分析任务 → 证据对象 → 路径 → 操作 → 结果验证”。面对计算机、Android、服务器、网络配置与二进制样本，可以先从对应任务表选择入口，再用后面的路径总表补齐材料。表中的包名、表名和函数名用于说明可检查的结构；真实文件名、用户、主机和时间范围均应从检材确定，不预设结论。

**材料约定：** 以已取得的磁盘/文件系统镜像、应用目录提取、APK、站点文件、数据库与程序副本为输入。离线镜像需确认分区、文件系统和只读访问；数据库解析输出、修复件、解密件及统计表存到分析工作目录。运行现场和隔离仿真产生的状态另行标记，不能自动补进历史时间线。

### 01.1 计算机：系统身份、应用配置与嵌套内容

| 分析任务 | 证据对象与入口路径 | 分析与结果验证 |
| --- | --- | --- |
| 确定操作系统发行版与版本 | Linux `/etc/os-release`、`/usr/lib/os-release`；Windows `SOFTWARE\Microsoft\Windows NT\CurrentVersion` | 读取版本字段与软链关系，结合用户目录、包数据库或安装痕迹验证归属；发行版版本不等于内核版本 |
| 还原可疑邮件的发送身份 | 邮件客户端的 `AppData`、`~/.config/` 或实际 Profile 中的邮箱、缓存与附件 | 导出完整邮件头，分别记录 From、Reply-To、Return-Path 和 Received；界面显示的发件地址可能伪造，与附件、客户端账号和接收时间互证 |
| 提取桌面或便签中的联系方式 | 桌面、开始菜单快捷方式、记事本文件及相应用户应用数据 | 先定位具体用户与实体文件，保留上下文、编码和文件哈希；出现电话号码只证明留存内容，不直接证明实际联系或号码归属 |
| 还原加密设计图中的二维码载荷 | 图像密文与 `public.txt` 中的 RSA `n`、`e` | 先验证可用的 RSA 攻击条件与分块/编码，解密后核对图像结构，再识别完整二维码；把下载 URL 作为文本证据，不能直接访问未知端点 |
| 确定代理配置的监听端口 | `~/.config/clash/config.yaml`、`.config\clash\` 与应用实际配置 | 区分 `port`、`socks-port`、`mixed-port`、控制接口等字段；结合启用配置和已采集监听状态确认，不把配置值认定为历史持续监听 |
| 确定 AI 客户端配置的服务商或模型 | `~/.config/<app>/`、`AppData\<app>\` 中的配置与本地数据库 | 分开读取 provider、model、base URL；路由服务名称不一定是具体模型名，用请求/会话字段或本地模型配置验证 |
| 定位 AI 客户端留存的 API 凭据 | 同一客户端配置、本地数据库及用户保护相关材料 | 记录密钥字段位置、编码/加密方式与账户绑定，展示时遮盖主体；只在已取得材料内核对使用引用，不通过真实请求测试有效性 |
| 定位勒索程序的联系信息 | 已解锁的加密卷、下载历史与 Go 程序中的 `main_main`、`main_a` 等候选函数 | 从字符串到交叉引用，再确认显示/拼接/写入通知的调用链；下载记录与程序哈希对应，静态联系常量不等于实际发送过邮件 |
| 修复媒体偏移后读取画面内容 | MP4 box 树、`stco`/`co64` 块偏移与 `stsz` 等采样表 | 在副本上定位异常字段与统一偏移关系，核对修复后采样指向和实际播放；不能见到异常就给所有偏移加固定数值 |
| 从复合文档绘图记录恢复点阵内容 | `.et`/OLE 文档的 Workbook/Book 流、BIFF 与 `MSODRAWING` | 按记录长度解析边界，提取真实坐标并绘制，结合图形/文本记录检查是否有其他内容；可读数字需与坐标映射、渲染方向和其他记录互证 |

计算机身份与应用证据的具体步骤见[Linux 系统与服务清单](/knowledge/fic-case-03/)、[浏览器痕迹](/knowledge/forensic-browser/)与[媒体/文档结构分析](/knowledge/forensic-documents/)。加密卷是后续程序、媒体和文档分析的前置对象，需要同时保留容器哈希、解锁材料来源与只读访问条件。

### 01.2 Android：设备、应用数据与代码路径

| 分析任务 | 证据对象与入口路径 | 分析与结果验证 |
| --- | --- | --- |
| 确定设备型号与系统构建 | 设备信息及 `/system/`、`/vendor/`、`/product/` 中的 `build.prop` | 比较 model、brand、device 与 build fingerprint，记录分区和属性名；修改过的属性、模拟器或克隆备份可能改变归属判断 |
| 从便签还原计划日期 | `/data/user/0/com.miui.notes/databases/todo.db`、相关 WAL/SHM | 查询表结构、便签正文、状态与创建/修改时间，区分计划中的日期与实际出行证据；同时查看便签内是否有跨设备卷口令候选 |
| 确定应用安装记录时间 | `/data/system/packages.xml`、包管理清单与按用户保存的状态 | 核对字段单位与含义，区分首次安装、升级、恢复、文件创建和使用时间；安装日期与应用目录时间交叉，不预设某个固定日期 |
| 确定聊天数据库实体文件名 | `/data/user/0/com.talk.uuuim/databases/wk_<identifier>.db` | 建立同目录库、WAL、SHM 和账户标识对应；记录实际完整文件名、大小与哈希，不把模版里的标识当真实对象 |
| 验证聊天数据库解密材料 | 同一库的文件名标识、偏好、资源、设备参数与 SQLCipher 配置 | 文件名可能参与派生，只有代码引用或成功解析才支持这种关系；核对 cipher 版本、页大小、KDF 参数、表结构及多条记录，避免把错误密码读出偶然字节当成功 |
| 提取聊天中约定的备用收款地址 | 已验证的聊天库与消息/附件记录 | 记录消息 ID、发送方、时间、完整地址及语境；地址格式检查只证明语法，资金接收需与交易记录验证 |
| 对应转账截图与交易标识 | 截图文件、附件索引及可能以交易哈希命名的文件名 | 保存完整交易标识再按需要导出前缀；核对截图内容、链/网络和交易记录，哈希式文件名不自动证明交易成功或首次发生 |
| 统计 AI 会话中指定类型消息 | `/data/user/0/com.pocketpalai/pocketpalai.db` 与会话/消息表 | 确定角色、方向、会话范围、删除/重试标志和去重规则，再计数；说明“主动提问”的可操作定义，不能直接数全部行 |
| 确定本地模型文件与版本候选 | `/data/user/0/com.pocketpalai/files/models/local`、配置和会话引用 | 记录模型名、容器元数据与哈希，并检查实际加载配置；文件名或下载残留不证明已使用该模型版本 |
| 确定无人机飞行轨迹的行政区域 | `/storage/emulated/0/Android/data/dji.go.v5/files/FlightRecord/*.txt` | 确认日志版本、加密/压缩状态、经纬度单位和飞行时间；按轨迹点及行政区边界交叉，不能用手机 GPS、起飞点或缓存地图替代完整飞行区域 |
| 分析涉及隐私的权限声明 | APK `AndroidManifest.xml`、运行时授权/系统状态及敏感 API 调用 | 列出权限、组件与访问对象，分开声明、获得授权、调用和实际采集四层；存在权限不证明读取成功 |
| 定位 WebView 加载的离线页面 | APK `assets/www/index.html` 与 Java/DEX 中的加载调用 | 核对 `file:///android_asset/www/index.html` 的调用来源、路径拼接与页面内容；文件存在不证明 WebView 实际访问过 |
| 恢复数据上传接口候选 | APK `classes*.dex` 中 Base64 字符串及解码/网络调用 | 离线还原 URL，跟踪请求方法、参数、启用条件和回调；通过日志/流量确定实际请求，静态接口仅作为候选 |
| 定位应用使用的 SQLite 表 | APK `classes*.dex` 中 SQL 语句锚点和实际数据库 schema | 从 CREATE/INSERT/SELECT 的表名到读写方法，核对字段与库实例；代码内 `user_collection` 等字符串是否实际出现于已取得数据库要单独验证 |
| 还原资源种子派生的加密配置 | APK `assets/config.dat`、`resources.arsc` 中 `config_seed` 与派生代码 | 核对 seed 编码、MD5 原始字节或十六进制表示、截断方式、AES 模式/IV/填充；解密后以结构与多个字段验证，不把可打印片段当完整成功 |
| 定位 WebView 与通讯录读取桥接 | `AppNative`、`NativeBridge` 等桥接类及 `getContactsList()` 候选方法 | 将 JavaScript 调用、注册对象、注解、权限检查和底层 Contacts API 串联；方法名存在不足以证明可从任意页面触发或实际读取过 |
| 恢复 Native 层备用端点 | APK `lib/<abi>/libsecurity.so` 的调用链与 `.rodata` 密钥候选 | 先确认 ARM64/其他 ABI 与函数边界，再核对 XTEA 等运算参数与解码结果；分析何时走备用通道，实际连接仍需日志/流量证据 |

Android 目录布局需同时检查 `/data/user/0/<pkg>/`、其他用户/工作资料以及 CE/DE 状态。系统辅助对象 `/data/system/usagestats/`、`accounts.db`、`sync/` 可补充账户与使用范围，缺旧路径不等于不存在该类痕迹。应用沙盒定位和解密验证见[Android 数据定位](/knowledge/forensic-android-storage/)、[SQLite 读取](/knowledge/forensic-sqlite/)与[移动应用分析](/knowledge/forensic-mobile-apps/)。

### 01.3 服务器：系统、存储、站点与数据库

| 分析任务 | 证据对象与入口路径 | 分析与结果验证 |
| --- | --- | --- |
| 确定服务器发行版标识 | `/etc/os-release` 与 `/usr/lib/os-release` | 普通 `/etc` 文件优先；软链在检材根内定位实体；与包数据库、启动痕迹核对，不从分析机命令结果推定目标系统 |
| 对应根分区 UUID | `/etc/fstab`、分区表与已定位文件系统超级块 | 按 UUID/PARTUUID、类型、挂载点逐项对应；克隆可重复 UUID，配置残留也不保证该分区被成功挂载 |
| 整理本地镜像创建时间 | 自定义数据根 `/data/image/overlay2/imagedb/content/sha256/*.json` 或实际 Docker 元数据布局 | 取镜像配置 `created` 并核对 ID、层与时间格式；镜像构建时间不等于容器启动/部署时间，容器展开见 Docker 专题 |
| 定位根文件系统的历史子卷 | Btrfs 子卷/快照清单与 `/root/history` 候选 | 用子卷属性确认 ID、UUID、Parent UUID、Received UUID 及挂载关系，再判断快照来源与覆盖范围；目录名含 history 不能单独证明快照 |
| 还原后台入口路径变化 | `/var/www/html/maccms10/`、`.git/index`、`.git/objects/pack/pack-*.pack`、访问日志 | 导出历史树/索引中的路径与 blob，和现存文件字节、URL 时间线对应；日志路径切换也可能是 rewrite，不能单独证明实体改名 |
| 提取站点备案配置 | `application/extra/maccms.php` 与站点渲染/配置加载处 | 记录字段、完整值与所用配置版本，确认它被页面引用；配置里的备案文字不等于外部备案真实性 |
| 确定站点主要域名配置 | 同一业务配置的 `site_url`、移动/WAP 域名及 Web 虚拟主机 | 把主域、备用域和移动域分开，交叉日志 Host/服务配置；字段值只表示配置，不单独证明域名归属或实际服务可达 |
| 区分分类拼音与内容拼音 | `mac_vod.vod_en` 与分类表/`type_en` | 先按实际分类关联确定条目范围，再读取条目字段；同名、空值、多语言与迁移记录均须说明，不能用分类别名替代内容字段 |
| 定位启用的前端模板输入文件 | 业务配置中的模板标识、`template/<template>/info.ini`（如 `template/001tep/info.ini`） | 从配置到实际目录和模板元信息核对，区分模板 ID、目录名和输入文件名；旧模板残留不证明正在使用 |
| 计算完整伪静态配置摘要 | `/etc/nginx/sites-available/default`、`sites-enabled` 链接与实际 include 实体 | 定位真实文件后整字节计算 SM3，保留换行/BOM/注释；若对象定义为某个文件，就不能只抽规则片段或把软链文本当其内容 |
| 恢复数据库主机名对应的 IP | `application/database.php`、`/etc/hosts` 及分区镜像中残留行 | 当前 hosts 被 `0x00` 覆写时搜索原始分区字节、保留偏移与上下文；将候选完整行与服务配置/网段核对，不自动覆盖现配置或认定仍在用 |
| 判断数据库所在部署层 | `/var/lib/lxc/<name>/config`（示例 `/var/lib/lxc/mytidb/config`）、`lxcbr0`、rootfs 与服务配置 | 配置、网桥、rootfs、启动/进程归属共同支持 LXC 等判定；`docker0`、`lxcbr0` 及默认网段都可自定义，不能凭端口或网段单独定性 |
| 确定备份数据库版本 | `/media/zfs`、ZFS 池元数据、TiDB 集群 JSON 与实际端点 | 对照池/数据集身份、节点配置和版本字段，区分主库与备份库；4000 只是常见入口线索，查询输出必须绑定明确实例 |
| 统计注册用户最多的日期 | `mac_user.user_reg_time` 与账户记录 | 确认 Unix 秒/毫秒、NULL/异常值、时区及去重口径，按日期聚合并显示并列；留存表记录不一定覆盖全部历史注册 |
| 确定指定账户留存的末次登录 IP | `mac_user.user_last_login_ip`、账户名/拼音候选与登录日志 | 用稳定账户 ID 消歧，确认整数 IPv4 字节序/符号，`INET_NTOA()` 仅用于对应的 IPv4 数值格式；数据库末次字段需与登录事件核对 |
| 判断某类文件系统或存储层的使用证据 | `/etc/lvm/backup/root`、`/etc/lvm/backup/volum`、`/dev/mapper/*`、fstab 与超级块 | 区分文件系统类型和 LVM 卷管理层，分开当前挂载、配置痕迹与历史使用；搜索范围未发现 NTFS 等不能无限推定“从未使用” |
| 清点实际数据库服务部署 | `/var/lib/postgresql/17/main`、`pg_hba.conf`、`/db/tidb`、其他配置/包/日志 | 服务端包、初始化数据、配置、日志/采集的进程监听四线验证；`mariadb-client` 或单一客户端命令不证明服务端已部署 |

服务器命令历史 `/root/.bash_history` 用于补充环境搭建过程，条目时间与写盘方式须核对；`/etc/crontab` 则可定位服务和隧道的启动引用。Docker 的镜像、容器与存储结构集中在[Docker 镜像与容器身份](/knowledge/docker-evidence-01/)、[Docker 现场流程](/knowledge/docker-evidence-02/)及[Docker 存储与日志](/knowledge/docker-evidence-03/)。本索引保留入口和验证任务，沿专题读取参数与操作边界。

### 01.4 网络与互联网关联：链接、备份记录和隧道

| 分析任务 | 证据对象与入口路径 | 分析与结果验证 |
| --- | --- | --- |
| 提取业务站点配置的社交群组标识 | `application/extra/maccms.php`、模板与已取得页面 | 保留标识中的 `@` 等符号及完整上下文，对照渲染引用；配置提到群组不等于账号加入或发送过消息 |
| 定位备份库中条目的图片文件名 | 明确的 TiDB 备份端点（如 4000）、`mac_vod.vod_pic` 及条目关联键 | 用同一条目的稳定 ID 查询，记录 URL/路径与 basename；摘要式图片名需要与实际图片内容重新计算比对，主库和备份库须分开 |
| 还原隧道曾使用的域名/端点 | `/root/.config/ngrok/ngrok.yml`、`/etc/crontab`、用户历史、启动与隧道日志 | 分开静态保留域与动态分配域，按运行账户、配置引用和日志时间关联；在仿真中重新启动得到的新域名不能替代历史端点 |

网络关联依赖已经取得的配置、日志、流量或数据库，见[远程连接与隧道证据](/knowledge/forensic-remote-connections/)与[流量分析](/knowledge/forensic-network-traffic/)。域名、群组和钱包地址先作为文本对象保存，查询外部状态若另行进行，应记录查询时间与新增材料范围。

### 01.5 二进制样本：标识、校验、解密与账本

| 分析任务 | 证据对象与入口路径 | 分析与结果验证 |
| --- | --- | --- |
| 计算 PE 文件的 MD5 标识 | 可移动介质导出的 `sample.exe` 完整字节与采集清单 | 对明确实体计算 MD5 并同时保存 SHA-256、大小和路径；十六进制大小写只是表示，不能为格式改变输入文件 |
| 评估 PE 中的构建时间候选 | PE 头、调试目录与 PDB 记录 | 保留字段名称、原始值与工具解释；COFF/PDB 时间可能修改或由可复现构建生成，需其他构建/下载记录交叉，不单独认定真实编译日期 |
| 复现程序的口令校验逻辑 | `winmain` 到候选函数（如 `sub_1400024A0`、`sub_140002200`）及算法常量 | 记录字符编码、字节序、溢出宽度、轮数、比较值，离线复现并以多组输入/反向关系检查；函数地址只是样例定位方式 |
| 确定解密载荷的实际类型 | 原始 RC4 密文、已验证密钥材料与解密副本 | 不运行可能自清理的程序；先保存密文，再按 KSA/PRGA、密钥编码复现，核对文件头/尾与容器结构；扩展名不代替 VHD/VHDX 格式识别 |
| 统计虚拟磁盘账本中的收款金额 | 已只读访问的 `.vhd` 内交易记录、收款地址与资产字段 | 按地址、网络、币种、方向、状态和去重键筛选，使用整数最小单位或 Decimal；列出纳入/排除记录与总数，转账截图/本地账本不独立证明链上确认 |

嵌套载荷处理见[二进制与密码逻辑分析](/knowledge/fic-case-07/)、[密码材料与受保护数据](/knowledge/forensic-protected-data/)及[镜像与文件系统](/knowledge/fic-case-02/)。每一层保存输入哈希、输出哈希、工具参数与成功/失败依据；不能仅凭脚本正常退出确认解密或挂载正确。

## 02 按证据形式选择读取路线

| --- | --- | --- |

| 配置键值 | 系统标识、挂载、域名、代理、AI、社交链接 | 一份配置可以支持多个字段定位，分别记录每个键的实际使用引用；静态配置不能直接证明行为 |
| 数据库记录 | 条目拼音、注册统计、登录 IP、聊天、AI 消息、图片 | 先读 schema 与字段含义，保存查询条件、关联键、原值、行数及数据范围，不直接以列名猜业务意义 |
| 密码与编码 | 图像 RSA、SQLCipher、Base64、AES/KDF、Native XTEA、RC4 | 识别算法/编码 → 定位材料 → 复现参数 → 用结构与记录校验；编码、哈希与加密分别处理 |
| 文件结构 | MP4 采样偏移、OLE/BIFF 绘图、VHD 载荷 | 先定位外层容器，再按真实字段边界处理；修改副本时记录偏移、原字节、新字节及验证结果 |
| 程序常量 | Go 联系信息、口令校验、备用端点与密钥 | 字符串/常量 → 数据引用 → 关键函数 → 可达调用链；存在常量不足以证明实际调用 |
| 移动应用沙盒 | 便签、聊天、模型、消息、外部附件 | 同时查 `databases/`、`shared_prefs/`、`files/` 和外部数据，记录用户/包/版本及 CE/DE 可读边界 |
| 金额与交易 | 收款地址、截图交易标识、账本总额 | 完整交易标识与地址对应，再定义币种/单位/方向/状态/去重口径，金额总和与记录清单相互验证 |

## 05 实战：从配置摘要任务到实体路径与输出

### 05.1 场景、材料与检索路线

**场景：** 取得 Linux 服务器镜像，要计算一个站点伪静态配置的完整 SM3，并说明摘要对应哪个实际文件。**材料：** 已只读访问的根文件系统、`/etc/nginx/` 中的站点文件和软链、明确需要计算的文件范围，以及分析机工作目录。任务先落到服务器表中的“计算完整伪静态配置摘要”，再从路径表找到 `sites-enabled`、`sites-available` 和 `conf.d/`，沿实际链接/include 确定实体；若委托范围未定义整文件还是某个 include，先记录这个缺口，不能自行拼接不同对象。

以下假设已核实 `/mnt/evidence` 为目标检材根，输出目录在分析机。先看对象和选项，再读取文件；软链目标如果是绝对路径，必须重新定位到检材内部。

```bash
EVIDENCE_ROOT=/mnt/evidence
mkdir -p ./work
findmnt -no SOURCE,TARGET,FSTYPE,OPTIONS /mnt/evidence
ls -ld "$EVIDENCE_ROOT/etc/nginx/sites-enabled/default"
readlink "$EVIDENCE_ROOT/etc/nginx/sites-enabled/default"
cp -- "$EVIDENCE_ROOT/etc/nginx/sites-available/default" ./work/rewrite.conf
openssl dgst -sm3 ./work/rewrite.conf
sha256sum ./work/rewrite.conf
```

`cp` 的前提是已经确认实体文件位于检材内且需要的 include 范围明确；此处复制的是示例实体，不能先复制错误文件再补解释。`findmnt` 没找到挂载时，目录可能属于分析机父文件系统，停止把该目录当检材；`ro` 单独也不保证脏 ext3/ext4 不回放日志。哈希对象若是完整配置，所有换行、BOM、空格和注释均参与计算，输出大小写不会改变摘要意义。

假设 `readlink` 的示例输出为：

```text
../sites-available/default
```

这一行说明应在同一检材的 `/etc/nginx/sites-available/default` 读取实体；不是去计算软链字符串的摘要。若输出为 `/etc/nginx/sites-available/default`，同样要重定位到 `$EVIDENCE_ROOT/etc/nginx/sites-available/default`。若不是软链，直接检查条目是否为普通文件并确认它被加载，不能按预设输出强行替换。

最后保存一个可复核的输出单元：任务名称、镜像/分区身份、链接文本、实体完整路径、文件大小、SM3、SHA-256、复制/计算时间及工具版本。SM3 输出应包含该工作副本对应的 64 位十六进制摘要；摘要值由实际字节计算，本页不预设。将工作副本与原实体大小/字节摘要比较，确认没有在复制或编辑时改变换行/BOM，再把结论限定为该实体文件；其他 include 文件与历史规则另列，不能由一个摘要概括全部运行配置。

### 05.2 原始记录到时间/IP/金额结果

数据库先使用副本和相关 WAL/SHM，查询前记录版本、库实例、表结构及字段类型。对注册统计要同时保存总行数、有效时间行数、所用时区、每日计数和并列日期；对账户检索覆盖中文 UTF-8/GBK/UTF-16 与拼音，但最终用稳定账户 ID 消歧。对 IPv4 整数先验证一条已知记录的存法，再决定 `INET_NTOA()` 是否匹配，不用可读 IP 倒推字段正确。

金额统计保存完整交易标识，按网络、资产、地址、方向与状态筛选，用最小单位整数或 Decimal 相加，列出去重键和排除原因。若只取得截图/本地账本，结论限定为其留存记录；链上确认需要独立交易材料。日期、IP 与金额结果都应能回到入选的原始行，而非只保留一个最终值。

### 05.3 嵌套磁盘的只读访问

解密后先识别格式，再使用合适读取器。下面仅用于已确认传统 VHD（格式 `vpc`）的副本；VHDX/QCow2 必须改为实际格式，不能凭文件后缀套命令。

```bash
guestmount --format=vpc -a ./work/disk.vhd -i --ro /mnt/evidence
findmnt -no SOURCE,TARGET,FSTYPE,OPTIONS /mnt/evidence
# 完成读取后解除挂载
guestunmount /mnt/evidence
```

`--ro` 明确禁止对源镜像写入；`-o ro` 是 FUSE 层选项，不能代替它。自动探测失败并不等于没有文件，记录错误并按实际分区定位。需要 NBD 时用 `qemu-nbd --read-only` 并限定空闲分析设备，具体参数见[镜像访问命令](/knowledge/fic-case-13/)。只读语义与访问限制可对照[guestmount 手册](https://libguestfs.org/guestmount.1.html)和[QEMU NBD 手册](https://www.qemu.org/docs/master/tools/qemu-nbd.html)。

## 06 验证与结论范围

这些示例展示证据路线，未对读者的检材实际复跑。输出应明确“发现候选、已对应对象、结构解析成功、行为已交叉验证”中的哪一层完成，并列出未取得分区、缺失日志、密钥未知、版本不支持或无法复现的限制。通用路径全集见[跨平台系统目录与关键文件](/knowledge/fic-case-14/)，结果边界见[判定原则与易错点](/knowledge/forensic-method-pitfalls/)。

检查任务完整性时，对每个任务分别保存证据对象、实际路径、读取方法、输出记录与验证结果。服务器配置摘要不能代替使用行为，文件名中的交易哈希不能代替链上确认，程序静态端点不能代替实际连接。若两条材料冲突，保留它们各自的版本和时间范围；解析结果没有可回定位的字段/偏移时，先补齐定位，再写结论。

### 07.3 用依赖图记录缺口

例如：`完整分卷 → 可解析文档 → 候选口令 → 可读加密卷 → 内层文件 → 匹配程序解密 → 内容验证`。每个箭头记录输入、操作、输出摘要和验证条件；缺少上游对象时先标注缺口，不使用另一副本的固定值填充。另一条手机链可以是 `匹配 APK → 数据库参数 → 消息 → 附件口令 → 解密文档`。这些是可复用的工作路线，具体内容和结论都由当前材料决定。

## 08 实战：把手机聊天、桌面聊天与网站业务分别关联

### 08.1 先确定设备与应用的归属

**场景与材料：** 已取得手机 WhatsApp 数据、计算机 Signal Desktop 数据，以及服务器站点文件、访问日志和业务数据库。目标是验证某条消息、某个附件与某次网站操作之间的关系。WhatsApp 的本组材料来自手机；Signal Desktop 的本组材料属于计算机用户应用，沿用户目录与实际应用配置定位，不能把桌面应用整段归入手机取证。其他平台或版本仅在实际材料出现时纳入，不预设固定路径或解密参数。

| 输入对象 | 首先保存 | 进入方法 |
| --- | --- | --- |
| 手机 WhatsApp 容器、备份或导出 | 设备标识、应用版本、账户、提取方式、数据库/WAL及附件覆盖 | [手机应用记录判读](/knowledge/forensic-mobile-apps/) |
| 计算机 Signal Desktop 的用户应用数据 | 计算机与用户 Profile 身份、桌面应用版本、账户/设备链接信息、库及附件覆盖 | [计算机用户应用痕迹](/knowledge/forensic-windows-artifacts/) |
| 服务器网站与数据库 | 主机/实例、站点域名与代码版本、日志格式/轮转、库/表结构及快照时刻 | [服务与日志](/knowledge/forensic-server-services/)和[SQL 查询](/knowledge/fic-case-05/) |
| FTP 配置与传输材料 | 生效配置时段、账户来源、认证/传输动作、路径映射与日志范围 | [vsftpd 证据流程](/knowledge/forensic-server-services/) |

每个来源分配独立证据编号并计算原始对象哈希；主机名、设备显示名或登录用户名只是属性，不能替代镜像/设备身份。数据库记录、解析器导出、界面截图和恢复候选分别标记；恢复件、仿真登录及新生成消息不能混入历史记录。无法读取加密材料时写明已取得范围和缺失条件，不用另一个版本的固定密钥补齐。

### 08.2 建立能够回到原始对象的关联表

先保留每个来源的原字段，再生成派生表。统一的 `account_id`、`device_id` 与 `message_id` 是分析表列名，不代表不同应用已经共用同一标识命名空间。

| 字段组 | 最小记录 | 需要核对 |
| --- | --- | --- |
| 来源与定位 | 证据编号、镜像/原对象哈希、设备、系统用户、应用版本、路径、库/表/主键或偏移 | 解析器导出的 ID 能否回到原行；逻辑备份是否覆盖附件/删除数据 |
| 账户与联系人 | 本机登录账户 ID、会话 ID、发送方/接收方 ID、实际存在的绑定/设备字段 | 显示名、好友备注、群名与稳定账户 ID 分列；群会话 ID 不等于发送者 |
| 消息语义 | 原生消息 ID、方向、状态、引用/转发标记、正文位置、删除/恢复状态 | 方向相对哪个登录账户；发送、投递、已读及同步状态按版本解释 |
| 时间 | 原始数值/字符串、字段语义、单位、时区/偏移、转换规则、UTC值与不确定范围 | 发送、接收、服务器处理、本地写库、备份与导出不是同一时刻 |
| 附件 | 原生附件 ID、消息引用、路径、大小、MIME/实际格式、完整文件 SHA-256 | 原件、缓存、缩略图、截图和解密件分别计算；缺文件不能凭文件名匹配 |
| 网站请求 | 主机/站点、原日志位置、请求 ID、方法/路径、来源地址、会话映射、状态码 | 反向代理与真实客户端字段、会话与用户对应、请求是否进入业务处理 |
| 数据库业务 | 实例/快照、库/表/主键、用户外键、业务/对象 ID、状态与时间字段 | 是否提交、状态定义、软删、重复、快照是否晚于请求；只有HTTP成功码不保证业务完成 |

账户映射另做一张表，记录 `来源应用 / 原账户ID / 目标账户ID / 依据对象 / 对应时段 / 置信范围 / 冲突`。相同手机号、显示名或昵称只能产生待验证候选；绑定关系也可能随时间改变。不要将 WhatsApp ID、Signal ID 和网站 user ID 直接相等连接；只有独立绑定材料、已核对的会话认证映射或其他明确标识关系才可建立跨系统映射。自然人身份仍需独立的设备使用和账户控制材料支持。

### 08.3 按步骤验证一条关联链

1. **固定范围。** 分别列出手机、计算机和服务器的采集时刻、可见用户、应用/站点版本、备份时段、缺失分区和日志区间。先确认三份数据是否覆盖同一目标时段；不能把较晚快照的当前设置当作较早操作的配置。
2. **核验本地聊天。** 在各自来源中确认登录账户、会话、原生消息 ID、实际发送者和方向。对群聊、引用、转发、编辑和系统消息保留类型；一条“我已上传”的文本只能说明记录中有该表述，不证明上传完成。手机消息步骤见[WhatsApp 与手机记录](/knowledge/forensic-mobile-apps/)，桌面材料继续用计算机入口。
3. **统一时间并保留原值。** 对每种时间字段先用可独立确认的样本验证单位、时区和含义，再换算 UTC。设备时钟偏差、网络延迟、链接设备同步和备份恢复可能使顺序错开；保存推定依据和误差范围，未知时区保持未知。详细规则见[时间证据](/knowledge/forensic-time-evidence/)与[时间线关联](/knowledge/fic-case-11/)。
4. **核对附件实体。** 通过消息到附件的实际引用取得文件，计算完整字节哈希，再比较另一设备留存件与服务器对象。相同文件名、相似画面或相同缩略图不能替代原件匹配；跨应用复制或转发也不一定保留原消息 ID。哈希一致支持字节内容相同，不能独立证明谁制作、何时发送或由哪个设备上传。
5. **从请求回到站点账户。** 在留存日志中找目标时段和对象路径，结合请求 ID、会话认证记录与站点代码确认账户。来源 IP 或 User-Agent 可作辅助线索，不能单独把请求归给某人；共用网络、代理与伪造字段要保留。若日志只含路径和状态码，明确缺少账户映射，不从聊天昵称填补。
6. **从请求回到业务行。** 使用已恢复的隔离副本或授权只读读取，按业务 ID、对象 ID、稳定用户外键和请求 ID等实际可用键定位。核对 DDL、状态枚举、业务写入代码及事务/历史材料，确认当前行、已提交历史行和恢复候选的区别。SQL 方法见[SQL 查询](/knowledge/fic-case-05/)，删除恢复见[数据库恢复](/knowledge/forensic-database-recovery/)。
7. **检查反例与重复。** 保留同名不同账户、同附件被多人转发、聊天时间晚于请求、状态失败、路径相同但哈希不同及多个快照重复记录。跨设备同步产生的副本分别保留来源，可按确认的原生键合并事件计数；不要仅按正文+时间去重，也不要把一次操作的日志、聊天引用和业务行统计为三次操作。
8. **形成逐条结论。** 对每个连接写出成立依据、替代解释、缺口和证据位置。若只完成“聊天留存相同附件”，就报告该层；缺网站认证映射或业务行时不能继续提升为账户实施了某次网站操作。聊天中的自述、指称或显示名不能直接作出自然人身份、参与程度或违法犯罪的结论。

### 08.4 构造样本：相同附件、不同消息 ID 与时区

下表是教学用模拟记录，`H1` 仅代指一份已保存的完整 SHA-256，不是可供读者直接采用的摘要。各账户和 ID 都是分析占位值；网站业务状态的含义已在这个构造场景中通过代码确认。

| 来源 | 原记录与原时间 | 转为 UTC 后 | 支持什么 |
| --- | --- | --- | --- |
| 手机 WhatsApp | 账户 W-A，消息 WA-21，方向发送，`2026-07-01T18:00:02+08:00`，引用附件 A-1，实体哈希 H1 | `2026-07-01T10:00:02Z` | 该手机来源中留存一条对应账户的发送记录与附件引用 |
| 计算机 Signal Desktop | 账户 S-A，消息 SG-8，方向接收，`2026-07-01T10:01:10Z`，引用附件 A-9，实体哈希 H1 | `2026-07-01T10:01:10Z` | 桌面来源留存相同字节内容；WA-21 与 SG-8 仍是不同消息 |
| 站点访问日志 | 请求 R-17，`POST /files/import`，`2026-07-01T10:02:03Z`，响应 201 | `2026-07-01T10:02:03Z` | 留存一次导入请求与响应，单独不证明业务完成或账户归属 |
| 站点认证/应用记录 | 请求 R-17 对应已认证会话与网站账户 U-42 | 按实际认证字段解释 | 在该请求的证据范围内建立会话→网站账户映射 |
| 业务库及文件 | 已提交业务行 OBJ-42，外键 U-42，关联 R-17，状态为已存储；其实体哈希 H1 | 业务字段时间另列 | 该网站账户对应这项已提交存储记录，文件字节与聊天附件相同 |

三种应用时间必须先解释再排序。两份聊天附件及网站文件的哈希一致，加上请求/会话/业务键，可以支持“这些来源留存相同文件，且网站账户 U-42 有一项对应的存储记录”。这些材料没有给出 W-A、S-A、U-42 与同一自然人的独立对应，也没有证明跨应用消息转发路径，因此不能从时间接近和相同附件推定同一人完成全部操作。

**反例：** 若桌面只留缩略图、网站业务行为失败、服务器文件已被覆盖，或认证日志轮转缺失，应分别写“仅外观候选”“未见业务完成”“当前实体无法代表历史版本”“网站账户映射未知”。若一条消息声称已上传而同一业务 ID 的日志/数据库记录失败，保存冲突，不能删除不符合叙述的证据。完整输出应包含来源表、账户映射表、附件对应表、原始/UTC时间线、请求与业务行索引，以及未成立连接和缺失范围。
