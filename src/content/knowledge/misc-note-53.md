## 一、题型判断

**实战主要分两类：**

| 类型 | 特征 | 适合工具 |
| --- | --- | --- |
| 规整网格型 | 碎片大小一致、行列规则、顺序已知 / 可推导 | ImageMagick montage |
| 乱序自动拼接型 | 碎片位置完全打乱、不知道正确排列 | Puzzle-Merak / Jigsaw Puzzles |

ImageMagick 的 montage 只负责 "按照给定顺序排成网格"，不会智能判断哪两个碎片应该相邻。只有当文件名本身就是正确顺序、题目给了排列规律、或者你已经推导出顺序时，才适合直接 montage。如果所有碎片真正随机打乱，单纯调整 -tile 无法恢复正确原图，应使用边缘匹配类拼图工具。

## 二、规整网格型：ImageMagick 快速拼接

**适合：** 所有碎片尺寸相同 + 排列顺序已知 / 可推导 + 只需要重新排成 n×m 网格。

命令

\# ImageMagick 7 (Windows)

magick montage *.png -tile 18x10 -geometry +0+0 result.png

\# 明确每块 125×125

magick montage *.png -tile 18x10 -geometry 125x125+0+0 result.png

\# Kali (ImageMagick 6)

montage *.png -tile 12x12 -geometry +0+0 result.png

参数含义

-tile 18x10：18 列 × 10 行

-geometry +0+0：水平和垂直间距均为 0

行列数判断

碎片总数 = 180，可以考虑 18×10、20×9、15×12 等。但总数能整除只能说明这个行列组合 "数学上可能"，不能证明它就是正确排列。应结合原图比例、碎片尺寸、题目提示、拼接后的画面连续性判断。

文件名排序是高频坑

例如目录 1.png、2.png、...、10.png、11.png，某些程序按字符串排序时可能变成：

1.png → 10.png → 11.png → 2.png → 3.png

最好提前整理为 001.png、002.png、...、010.png、011.png 再 montage。

不要随意缩放碎片

如果碎片本应大小一致却发现不同，应先判断：是否有边缘块尺寸不同、提取过程出错、本来就不是规则网格题。强行 resize 会改变边缘内容，反而可能破坏拼图。

## 三、乱序拼图：Puzzle-Merak / Jigsaw Puzzles

当碎片顺序完全随机 + montage 无论怎么排列都明显错乱时，需要使用自动边缘匹配工具。这类工具本质上比较：

碎片 A 右边缘 ↔ 碎片 B 左边缘

碎片 A 下边缘 ↔ 碎片 C 上边缘

根据颜色、像素差、边缘连续程度等计算相似度，再寻找整体最优排列。

Puzzle-Merak 最重要的输入规则

输入 Puzzle-Merak 的不是一个装着大量单独碎片的文件夹，而是一整张已经包含所有乱序碎片的完整图片。

如果题目直接给的是很多独立碎片（001.png、002.png、...），通常要先用 montage 把它们无缝排成一张大图：

montage *.png -tile 10x10 -geometry +0+0 shuffled.png

这个阶段不要求正确顺序，目的只是把所有碎片组成 Puzzle-Merak 可以读取的一张整体图片，然后再让 Puzzle-Merak 自动重新排列。

## 四、Puzzle-Merak 自动拼接方法

进入工具后，根据版本一般会看到类似：自动拼接（gaps）、自动拼接（比较边缘）、自动拼接（像素比较）。

| 模式 | 适合场景 | 特点 |
| --- | --- | --- |
| gaps | 规则矩形切块、块与块之间存在容易识别的边界、标准 CTF 网格拼图 | 速度较快，首选 |
| 边缘比较 | 普通图片被规则切块、没有明显间隙特征 | 速度和准确率均衡 |
| 像素比较 / 高精度 | 边缘非常接近、普通模式局部拼错 | 计算量更大 |

**顺序建议：** gaps → 边缘比较 → 高精度像素比较，不要一开始就跑最慢模式。

参数理解

某些版本会要求类似 个体数量;迭代次数;单块尺寸，例如 100;500;64：

**个体数量：** 每代参与搜索的候选方案数量

**迭代次数：** 算法优化多少轮

**单块尺寸：** 每一个拼图块的宽 / 高

调参策略

结果大部分正确但几块位置错误 → 提高迭代次数

整体经常陷入错误排列 → 适当提高个体数量 + 提高迭代次数（代价是运行时间增加）

## 五、高频问题判断

| 现象 | 处理方式 |
| --- | --- |
| montage 后完全乱 | 先判断行列数错还是碎片顺序本来随机；换了几组合理 -tile 仍毫无连续关系，就不要继续爆行列，转 Puzzle-Merak |
| 整幅图大致正确，只有局部错块 | 自动匹配已接近正确，提高迭代次数、换更精确的边缘 / 像素模式，不要重新随机尝试 |
| 图片出现明显规则，但 flag 仍看不见 | 正确拼图只是第一层，继续 StegSolve、zsteg、二维码识别、盲水印、图片通道等后续分析 |
| 图片上下 / 左右方向整体正确但内容颠倒 | 考虑整图旋转 90°/180°/270°、水平翻转、垂直翻转；这是完成拼接后的整体方向问题，不等于碎片排列错误 |
