## 适用场景

脚本或输出中出现 `n/e/c`、椭圆曲线点、矩阵、密文十六进制串时，先完成参数台账。大量“算法算对了却得不到明文”的问题，实际是**进制、字节序、长度、填充或题目实例不一致**。

## 01 先列参数表

| 字段 | 要写清的内容 |
|---|---|
| 数学对象 | 整数、模数、有限域元素、点、向量或原始字节 |
| 表示方式 | 十进制、`0x` 十六进制、Base64、文本编码，是否有前导零 |
| 长度与顺序 | 位长、字节长、大/小端、块边界、拼接顺序 |
| 依赖关系 | 哪些值由随机数生成，哪些值每次运行改变 |
| 已知条件 | 公开参数、泄露位、约束方程、可验证等式 |

读题目脚本只做静态检查；未知脚本不应因为文件名叫 `task.py` 就直接执行。先区分脚本中写死的常量与运行后才生成的随机值，否则容易把不同运行实例的参数混在一起。

## 02 用短脚本核对表示

以下是独立的**字节表示演示**，不是任何题目的解法。把实际输入替换后，先比较长度和十六进制，再进入数学计算。

```python
raw = bytes.fromhex("004142")
value = int.from_bytes(raw, "big")
print(len(raw), raw.hex(), value)
print(value.to_bytes(len(raw), "big").hex())
```

整数 `0x4142` 自身不保存最前面的 `00`；回转为字节时必须显式指定原长度。若将 `b"4142"` 当成 `bytes.fromhex("4142")`，输入会从四个 ASCII 字节变成两个原始字节。解密后还要区分“整数正确”和“填充/文本解码正确”。

## 03 再决定方法

先问：题目是否是 RSA 的模幂关系、椭圆曲线群运算、线性方程加噪声，还是自定义的逐字节变换？把每种候选方法的**成立前提**写在计算前，例如因子已知、共享模数、点确实在曲线上、密钥流是否复用。未满足前提时不要直接套攻击脚本；先找缺失参数或回到表示层排错。
