核心是把文件数据以二进制点阵的形式编码进BMP图片里，常规工具读不出来，必须用PaperBack这种专门的解码器还原

## 一、核心原理

**基本过程：**

原始文件 → 压缩（可选）→ 加密（可选）→ 分块 + Reed-Solomon 纠错 → 编码成二维点阵 → BMP / 打印到纸张

不是简单的黑白像素映射

不要简单理解成 "黑像素 = 1，白像素 = 0"。实际图像内部存在：

网格定位信息

数据块与冗余块

Reed-Solomon ECC 纠错信息

数据块分散排列（提高部分区域损坏后的恢复能力）

可选压缩 + 可选 AES 加密

## 二、识别特征

看到以下特征，应优先想到 PaperBack：

**视觉特征：** BMP 图片中出现大量规则、密集排列的黑色小点 / 小方块，呈明显二维数据阵列，而不像二维码

**题目关键词：** PaperBack、Paperbak、BackPaper、paper backup、点阵

**工具排除：** 普通图片隐写工具基本没有有效结果

## 三、标准处理流程

点阵图片 → 确认/转换为 PaperBack 可识别 BMP → PaperBack 加载 BMP → 识别数据块 → 观察 Good/Bad/Incomplete → Save 恢复原文件 → 分析恢复文件

官方支持的 BMP 格式

未压缩的 8-bit 灰度 BMP

未压缩的 24-bit RGB BMP

不要把 "32 位 BMP" 当成标准格式要求。

识别状态含义

| 状态 | 含义 |
| --- | --- |
| Good blocks | 正常识别的数据块 |
| Bad blocks | 存在错误的数据块 |
| Incomplete | 尚未完整恢复的数据页 / 数据 |

PaperBack 会利用 Reed-Solomon ECC 自动尝试修复部分损坏的数据，因此有少量错误块并不一定意味着恢复失败。

全部数据识别完成后使用 Save 保存恢复出的原始文件；如果原始数据启用了加密，保存阶段会要求输入密码。

## 四、识别失败时重点检查

### 1. 图片格式

**优先保证：** BMP、未压缩、8-bit 灰度 / 24-bit RGB。

用 010 Editor 查看文件头 42 4D（即 ASCII BM），通常说明是 Windows BMP 文件。

如果题目给 PNG，可以无损转换成 BMP，但应避免：

JPEG 有损压缩

模糊

锐化

插值缩放

裁掉点阵边缘

修改点阵结构

这些操作可能破坏点阵识别。

### 2. 不要求分辨率必须与原图完全一致

PaperBack 本来就是为 "打印 → 扫描 → 恢复" 设计的，扫描后的图像显然不可能与生成时逐像素一致。官方甚至建议扫描分辨率约为点阵密度的 3 倍。真正重要的是点阵仍然清晰且几何结构没有遭到严重破坏。

### 3. 通常不需要手动旋转 90°/180°

PaperBack 官方说明：页面是横向、纵向、倒置甚至镜像，均可以识别。真正需要注意的是网格不能发生过大倾斜，官方给出的扫描倾角范围约为 ±7°。

识别失败→首先检查格式、清晰度、裁剪、缩放，而不是首先反复旋转图片。
