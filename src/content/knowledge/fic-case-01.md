## 01 建立可复核的分析流程

数字取证需要把“发现一条线索”推进到“解释它来自哪里、表示什么、还能怎样核对”。同一工作流适用于计算机镜像、Android 数据、服务器文件系统、网络记录与程序样本：先固定对象，再解析结构，定位证据，处理保护层，最后交叉印证。

### 01.1 五步工作流与交付物

| 步骤 | 目标 | 具体动作 | 应保留的结果 |
| --- | --- | --- | --- |
| 固定 | 保留原始状态 | 标识检材、记录大小、计算 SHA-256；兼容既有清单时补充 MD5；建立只读原件与工作副本 | 对象清单、采集时间、哈希、复制关系 |
| 解析 | 获得可读结构 | 识别整盘、分区、卷管理层、文件系统与嵌套文件；先离线解析，必要时隔离仿真 | 层次图、分区偏移、工具参数与解析日志 |
| 落点定位 | 找到有关记录 | 按配置、业务数据、日志和原始介质逐层查找 | 路径、字段、文件偏移、关联对象 |
| 还原保护层 | 读取受保护内容 | 确定编码或加密算法、密钥来源、字节序与填充，在副本上离线复现 | 参数、脚本输入输出、中间结果与派生文件哈希 |
| 交叉印证 | 限定结论范围 | 用不同机制产生的证据核对对象、行为与时间 | 已确认事实、合理推断、缺失项及冲突项 |

**操作顺序：** 静态材料已能回答问题时，先完成离线分析。启动仿真会新增日志、更新时间和数据库状态，不能把启动后的表现直接当作采集时现场。需要观察界面或程序行为时，使用隔离副本与快照，记录每一次安装、启动、连接和文件变化。

### 01.2 实战：固定一个可执行文件

**场景：** 从移动存储镜像导出 `sample.exe`，需要识别后续分析使用的确切对象。先记录镜像编号、导出路径、原目录和导出方式；不要双击样本。

```bash
# 已导出的只读原件位于 evidence/，工作目录位于 work/
ls -l ./evidence/sample.exe
sha256sum ./evidence/sample.exe
md5sum ./evidence/sample.exe
mkdir -p ./work
cp --preserve=timestamps -- ./evidence/sample.exe ./work/sample.exe
sha256sum ./work/sample.exe
cmp -- ./evidence/sample.exe ./work/sample.exe
```

SHA-256 输出是“摘要 + 文件名”；比较两份摘要与 `cmp` 结果确认复制时字节一致。MD5 适合与已有标识对照，但面对刻意构造的碰撞不能单独承担完整性证明。大小写只影响摘要显示，记录时统一格式并保留原始输出。

**判读示例：** “镜像导出的样本与工作副本长度一致，SHA-256 相同，逐字节比较未发现差异。”这证明当前两个对象字节相同；还需采集记录说明它们与原设备的关系。仅记录一个哈希，不能证明采集过程完整或文件未在采集前被修改。

## 02 从四个层次定位证据

### 02.1 配置、数据、日志与介质各自回答什么

| 层次 | 可回答的问题 | 常见落点 | 下一步验证 |
| --- | --- | --- | --- |
| 配置 | 系统、应用和连接如何设置 | `os-release`、`fstab`、`nginx/`、`application/*.php`、`lxc/<name>/config` | 路径是否有效、服务是否运行、配置是否被覆盖 |
| 业务数据库 | 账户、内容、通信和交易的结构化记录 | MySQL/TiDB 业务表、SQLite/SQLCipher | 字段含义、更新时间、删除状态与实例范围 |
| 日志 | 请求、启动与活动何时出现 | `access.log`、应用日志、飞行日志、带时间的命令历史 | 时区、记录完整性、日志轮转与时钟偏差 |
| 原始介质 | 已删除或覆盖记录是否残留 | 未分配区、COW 旧树、SQLite WAL 与 freelist | 残留的版本、所属对象、有效结构与时间范围 |

`crontab` 是调度配置，通常证明执行意图；它本身不是任务成功运行的日志。命令历史记录输入文本，也不能单独证明命令执行成功。优先级应随目标变化：确认连接目标先读配置，确定行为时刻则先找带时间的记录。

### 02.2 实战：从应用配置追踪数据库归属

**所需材料：** 网站目录、宿主机 `/etc/hosts`、网络配置与可能的容器根文件系统。假设已只读挂载到 `/mnt/evidence`，读取前检查路径与软链是否仍落在检材根内。

```bash
EVIDENCE_ROOT=/mnt/evidence
grep -nE 'hostname|database|hostport|username' \
  "$EVIDENCE_ROOT/var/www/html/site/application/database.php"
grep -nE '(^|[[:space:]])db-internal([[:space:]]|$)' \
  "$EVIDENCE_ROOT/etc/hosts"
```

示例配置记录主机名 `db-internal`、端口 `3306`；静态映射记录 `10.0.3.120 db-internal`。可先形成“配置指向该名称，静态映射将其关联到该地址”的结论，再核对网桥、LXC 配置和容器内数据库目录。

**交叉验证：** 相同网段只能辅助定位。还需容器配置中明确的网络接口、地址或根目录记录，才能确认实例归属。`/etc/hosts` 已损坏时回到镜像或快照寻找旧版本；恢复字符串需要记录偏移和上下文，不能把任意旧副本当作当前有效配置。

## 03 跨设备和跨实例关联

### 03.1 实战：把加密卷与移动端便签关联

**场景：** 计算机中存在无法打开的 VeraCrypt 文件，手机便签可能保存口令。这里的分析目标是验证两份检材之间的关系，不预设便签里的字符串一定可用。

1. 固定加密文件，记录文件名、大小、所在账户和相邻文件；高熵、无普通文件头只是加密线索。
2. 在手机的 `/data/user/0/com.miui.notes/databases/todo.db` 及配套 WAL 中检索与卷名、用途、账户有关的便签。先确认表结构，再查看内容和时间字段。
3. 保留便签完整内容、记录 ID、时间、数据库路径以及候选口令的来源关系；对敏感口令限制展示。
4. 在工作副本中验证口令、PIM、密钥文件等实际条件。打开成功后记录内部文件系统与可读文件，不修改原卷。
5. 将卷内材料的用途与便签上下文、计算机文件路径核对。成功解密支持口令与卷的对应关系，但自然人归属还需账户和使用证据。

可把关系写成：`手机便签记录 → 候选凭据 → 计算机加密文件副本 → 内部文件系统 → 目标材料`。任一环缺失都应明确标出，不能用同名文件或一条便签直接跳到人物结论。

### 03.2 实战：核对主库与备份库

同一网站可能保存 `db-internal:3306` 与 `backup-db:4000` 两套连接。先从现存配置、备份配置、启动脚本和日志列出已发现的端点，再在隔离恢复的实例中分别读取。现场端口只用于补充采集时状态，不能在分析机执行监听查询后填写为目标证据。

| 比较项 | 主实例示例 | 备份实例示例 | 解释 |
| --- | --- | --- | --- |
| 连接端点 | `db-internal:3306` | `backup-db:4000` | 不同端点需要分别证明服务身份 |
| 数据库 | `site_main` | `site_backup` | 名称不能证明复制关系 |
| 目标记录 | 未命中 | 命中一条图片记录 | 支持材料中存在差异，不能自动解释为主库人为删除 |
| 时间依据 | 最新日志时间 | 备份时间与导出清单 | 决定哪一份适用于目标时段 |

继续比较主键、资源路径、内容哈希和快照时间。备份较旧、复制延迟、查询条件不同、库名错误，都可能导致差异。保留两端查询条件和行数，避免只展示选中的结果。

## 04 按材料安排分析顺序

### 04.1 以结构和风险分配工作

| 材料 | 优先完成 | 后续重点 |
| --- | --- | --- |
| 计算机镜像 | 分区、账户目录、下载与浏览记录 | OLE/BIFF 绘图坐标、MP4 偏移、加密图片与嵌套卷 |
| Android 数据 | 用户和包名、数据库/WAL、应用文件 | SQLCipher、APK 资源与代码、飞行日志 |
| 服务器镜像 | 文件系统、快照、存储层、服务清单 | Web 配置、CMS 数据库、容器归属与旧文件恢复 |
| 网络相关记录 | 地址、名称解析、代理与隧道配置 | 历史端点、请求日志、多个数据库实例 |
| 二进制样本 | 格式、架构、哈希与静态结构 | 校验逻辑、AES/RC4、虚拟磁盘与自清理 |

这是同一批材料的工作顺序，不是对每台设备都强行应用所有技术。只在结构和上下文出现相应线索时深入；优先处理易变化的现场与可直接读取的记录，再处理成本较高的解密和恢复。

### 04.2 形成可独立复核的结论

每条结论按“对象与路径 → 原始字段或偏移 → 处理方式 → 交叉证据 → 适用范围”记录。例如：应用配置写入主机名，静态映射提供地址，容器配置和数据目录确认实例归属，历史日志说明运行时段。

来自同一数据库的两张截图、同一文件的两次哈希、同一记录的两种工具展示，不一定是独立证据链。优先组合由不同机制产生的记录；若只有一条链，说明现有材料支持什么、尚不能支持什么。结论中同时区分已确认事实、待验证推断与未发现的证据，让分析者可以按同一路径复核。
