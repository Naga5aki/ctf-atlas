## 1. 先锁定键盘报告

USB 流量可能同时包含鼠标、存储设备和多个端点。先在 Wireshark 中查看设备描述符、接口与端点，确定属于键盘的那一路；再按帧号保留时间顺序。不同抓包方式和解析版本会把报告放在 `usb.capdata` 或 `usbhid.data`，先检查本机支持的字段：

```bash
tshark -G fields | rg 'usb\.capdata|usbhid\.data'
tshark -r capture.pcapng -Y 'usb.capdata || usbhid.data' \
  -T fields -e frame.number -e frame.time_epoch \
  -e usb.capdata -e usbhid.data > reports.tsv
```

输出为空时，先确认流量中确有 HID 键盘和有效数据，再在 Wireshark 的包详情查看对应字节字段；不要把“某字段为空”直接解释为“没有按键”。分析多个设备时按设备地址和端点分别整理，避免把鼠标报告当成按键。

## 2. 把报告变化还原为事件

常见的 **8 字节 Boot Keyboard 报告**中，第 1 字节是修饰键位图，第 2 字节保留，后 6 字节是同时按下的按键 Usage ID。先确认抓到的确实是这种 8 字节布局；带 Report ID、NKRO 或厂商自定义布局的设备不能直接套用。

| 报告片段 | 含义 | 处理方式 |
| --- | --- | --- |
| `00 00 04 00 00 00 00 00` | Usage `0x04`，通常为字母 `a` | 与上一帧按键集合比较，新增才记为按下 |
| `00 00 00 00 00 00 00 00` | 全部释放 | 更新状态，不添加字符 |
| `02 00 04 00 00 00 00 00` | 左 Shift 与 `0x04` | 在相应键盘布局下记为 `A` |
| Usage `0x2a` / `0x28` | 退格 / 回车 | 保留事件，并同步更新编辑结果 |

同一个按键持续出现在连续报告中，不应每帧追加一次字符；释放后再次出现才是新一次按下。左 Shift 对应修饰位 `0x02`，右 Shift 对应 `0x20`。Caps Lock、非美式键盘布局、输入法与键盘自动重复都可能改变最终字符，遇到这类情况要回看设备布局和上下文。

## 3. 同时保留两种结果

按帧号保存“**按下/释放/退格/回车**”的逐键记录，再单独构造应用退格后的最终文本。USB 键盘流量不能只看最终字符串：先输入、后删除的字符仍可能是题目的线索。*wkm 的保险箱* 就需要关注输入历史。

候选密码或密钥应与后续容器解密结果交叉验证；若自动脚本只给出一串字符，回到关键帧核对 Usage ID、修饰键、帧顺序和同一端点的前一状态。
