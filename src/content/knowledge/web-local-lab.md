环境决定你能不能重复一次观察。题目附件、容器和虚拟机是三种材料，混在一起会把实验日志写成题目原本的行为。扫描器只对本地题目或书面授权的目标运行。

> 只在副本上构建/运行；端口绑 `127.0.0.1`，结束停容器/恢复快照。

## 00 30 秒速查

| 我要… | 先做… | 备注 |
|---|---|---|
| 看附件 | `unzip -l`/`tar tzf` | 先不解压 |
| 找启动 | `Dockerfile`/compose/README | 端口/依赖 |
| 判架构 | 系统/Web/语言/数据库 | 四件套 |
| 起容器 | 副本目录 + 回环映射 | 不带 `--network host` |
| 看端口 | `docker ps`/`compose ps` | 实际映射 |
| 多网段 | 虚拟机仅主机/内部网络 | 快照 |
| 扫描 | 主动/被动都限速 | 授权 |
| 复核 | 原请求重放 + 对照 | 五步 |
| 记录 | 哈希/命令/端口 | 可清理 |

## 01 原理与成立条件

```text
附件 → 清单 → 解压到空目录 → 读启动说明
                              ├─ 容器 → 副本构建 → 回环端口
                              ├─ 虚拟机 → 内部网络 → 快照
                              └─ 直接运行 → 隔离目录
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 有启动材料 | Dockerfile/compose/README | 按入口判语言 |
| 依赖可得 | 镜像/离线包 | 记录失败 |
| 网络可隔离 | 回环/内部网络 | 不启动 |
| 可清理 | 副本/快照 | 不污染宿主 |

| 架构 | 组合 | 入口线索 |
|---|---|---|
| LNMP | Nginx+MySQL+PHP | `fastcgi_pass` |
| LAMP | Apache+MySQL+PHP | `DocumentRoot` |
| WISA | IIS+SQL Server+ASP.NET | 站点绑定/`.aspx` |
| Java | Tomcat/JAR+DB | `server.xml`/`application.yml` |

## 02 判断与分型

```text
附件是什么？
 ├─ 源码+compose → 容器
 ├─ 镜像 tar → docker load
 ├─ 虚拟机盘 → 虚拟机
 └─ 单文件 → 本地解释器
需要多网段吗？
 ├─ 是 → 虚拟机内部网络
 └─ 否 → 回环映射
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| `docker-compose.yml` | 多容器 | 副本构建 |
| 端口写在 README | 映射 | 回环 |
| `.env`/配置 | 依赖/口令 | 不改原文件 |
| 镜像拉取失败 | 网络 | 离线包 |
| 数据卷 | 旧数据 | 换题清卷 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 容器起不来 | 端口占用 | 换端口 |
| 页面 502 | 上游未起 | 看日志 |
| 数据像上一题 | 旧卷 | 清卷/换名 |
| 扫描器报漏洞 | 未复核 | 手工请求 |

## 03 利用阶梯

### L0 只读清点附件

**前提**：拿到压缩包/镜像/说明。

**步骤**：
1. 放单独目录，`unzip -l`/`tar tzf` 看清单。
2. 核对路径穿越、绝对路径、超大文件。
3. 解压到空目录，先读 README/compose/Dockerfile。
4. 记附件哈希。

**成功标志**：知道启动方式/端口/依赖，未执行未知文件。

**失败分支**：清单异常→停/隔离；无说明→按入口判语言。

### L1 本地构建

**前提**：有启动材料。

**步骤**：
1. 复制到 `work/lab`，在副本构建。
2. `docker compose up --build`，`ps` 看端口。
3. 端口映射写 `127.0.0.1:8080:80`。
4. 浏览器/Burp 访问映射端口，留基线请求。

**成功标志**：本机可访问，端口只绑回环。

**失败分支**：镜像失败→离线包；端口冲突→换端口；502→看日志。

### L2 网络隔离

**前提**：需要多网段/宿主网络观察。

**步骤**：
1. 虚拟机网卡设仅主机/内部网络。
2. 实验前打快照。
3. 需要容器互访时用 compose 网络/服务名。
4. 不用 `--network host`，除非题目明确要求。
5. 记录“请求从哪个命名空间发出”。

**成功标志**：实验网络不出宿主，快照可回退。

**失败分支**：容器访问宿主→换地址；网络不通→看网段。

### L3 扫描与复核

**前提**：授权范围内。

**步骤**：
1. 主动扫描限速；被动扫描只观察已有流量。
2. 报告抽原始请求/响应。
3. Repeater 原样重放，确认稳定。
4. 与随机路径/正常业务对照，排除错误页。
5. 留“工具结论/重放结果/代码位置”。

**成功标志**：每条结论都有一条手工请求支撑。

**失败分支**：重放不稳→会话/动态；对不上→删结论。

### L4 记录与清理

**前提**：实验结束。

**步骤**：
1. 记附件哈希、启动命令、映射端口、基线请求。
2. 停容器/`compose down`，确认卷名再删。
3. 恢复虚拟机快照。
4. 移除浏览器/Burp 上游扫描代理。
5. 新日志标“实验产生”，不写成题目原始证据。

**成功标志**：环境干净，记录可复现。

**失败分支**：卷残留→换题清卷；快照未打→重建。

## 04 绕过与边界

| 场景 | 边界 | 处理 |
|---|---|---|
| 端口映射 | 左边是宿主 | 写回环 |
| `--network host` | 共享宿主网络 | 不用 |
| 数据卷 | 跨题残留 | 清卷 |
| 镜像来源 | 不明镜像有风险 | 用题目/官方 |
| 扫描器 | 请求量大 | 限速 |
| 反连平台 | 只填自己控制 | 编号对应 |

边界：容器内 `127.0.0.1` 是容器自己；`docker save` 不含卷；`compose down -v` 会删卷；虚拟机快照要在实验前。

## 06 差异速查

| 命令 | 作用 | 注意 |
|---|---|---|
| `docker run -p 127.0.0.1:8080:80` | 回环映射 | 左边宿主 |
| `docker ps` | 运行中 | 端口实际 |
| `docker exec` | 进容器 | 非宿主 |
| `docker cp` | 拷文件 | 方向 |
| `docker save/load` | 镜像 | 不含卷 |
| `compose down -v` | 删卷 | 确认 |

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 容器 502 | 上游/端口 | 看日志 |
| 端口占用 | 本机服务 | 换端口 |
| 镜像拉不下 | 网络 | 离线包 |
| 数据旧 | 卷 | 清卷 |
| 扫描全 200 | 自定义 404 | 比正文 |
| 复核不稳 | 会话/动态 | 重登/固定 |
| 实验污染 | 未隔离 | 快照/副本 |
