## 一、核心原理与识别

典型结构

原始音频 A → 修改部分采样点/字节 → 隐写音频 B

**真正需要分析：** B - A

识别特征

同时给出两个内容相似的音频

时长、采样率、文件大小接近

人耳听起来基本一致

单独查看波形、频谱、strings、binwalk 没明显结果

题目出现 diff、difference、对比、找不同、original/stego 等提示

三类隐藏方式

| 方式 | 说明 |
| --- | --- |
| 文件字节不同 | 直接修改 WAV 文件字节，最简单 |
| PCM 采样点存在微小差异 | 采样值 LSB 级别修改，反相抵消后可见 |
| 左右声道或两个音轨之间存在差异 | 单文件双声道内部做 Diff |

## 二、Audacity：核心解法

Audacity 最重要的作用是：将其中一个音频反相，再与另一个音频相加，使两者相同的声音互相抵消，只留下不同部分。

A、B 完全相同 → A - B = 0 → 接近静音

B 中藏有微小修改 → A - B = 隐藏差异 → 残留需要分析的信号

### 1. 导入并检查两个音频

文件 → 导入 → 音频，同时导入 original.wav 和 stego.wav。

**导入后先检查：**

两轨起始时间是否一致

时长是否一致

采样率是否一致

单声道还是双声道

两轨音量是否相同

对齐极其重要，哪怕只错开几个采样点 A(t) - B(t+Δt) 都会产生大量残差信号，导致整个 Diff 失去意义。要先把两个轨道起点精确对齐，不断放大波形找明显峰值，保证处于同一时间位置。

### 2. 对其中一轨执行 "反相"

选中其中一个完整轨道（如 B），Ctrl + A 注意只选中目标轨道，然后执行：效果 → 反相（Invert）。

反相不是声音倒着播放，而是波形绕零轴上下翻转：原采样 +1000 → -1000，原采样 -500 → +500。这是 Diff 最关键的一步。

### 3. 将两个轨道混合

现在有轨道 A（A）和轨道 B（-B），选中两个轨道，执行：轨道 → 混音 → 混音并渲染为新轨道（Mix and Render to New Track），最终生成 A + (-B) = A - B。

直接执行混音并渲染不会自动计算 Diff。如果不先反相，得到的是 A + B，两个音频反而会叠加增强。正确流程必须是：一个轨道反相 → 两个轨道混音 → 得到差值。

### 4. 放大残留信号

如果两个文件几乎一样，Diff 后残留通常非常小，看起来接近一条直线，这不代表没有信息。先单独播放残留轨道，然后使用效果 → 放大（Amplify）或效果 → 标准化（Normalize），把微弱残留提高到容易观察的程度。

放大只用于分析副本，不要覆盖原始证据文件。然后不断时间轴放大、波形纵向放大，观察差值形态。

## 三、Diff 后怎么看隐藏信息

反相抵消后主要观察三种情况：

**情况一：** 出现明显声音

残留轨道能听出摩尔斯、语音、DTMF、短促蜂鸣、高低音，说明隐藏的是独立音频信号。直接继续听声音 → 看波形 → 切换频谱图进一步识别。

**情况二：** 出现规则脉冲

存在两种明显的振幅状态，可能是在用差异编码 0/1。此时应：

横向放大，判断每个符号的固定时间宽度

观察高 / 低、正 / 负、存在 / 不存在等两种状态

按题目规律转成二进制，每 8 bit 转成字节

**情况三：** 残留是一串极微小噪声

通常说明修改发生在 PCM 采样点最低位。例如两个 16-bit PCM 样本：原始 10000 / 隐写 10001，差值 1；原始 -8532 / 隐写 -8533，差值 -1。人耳基本听不出来，但反相抵消后能看到大量 ±1 级别的采样变化，这就是典型的采样点 Diff / LSB Diff。

Audacity 适合确认差异存在、观察分布和规律，但如果真正需要逐样本恢复二进制，通常需要进一步使用二进制 / 采样分析工具。

## 四、声道 Diff 的 Audacity 解法

有些题不是音频 A vs 音频 B，而是左声道 vs 右声道。例如双声道 WAV 中 Left ≈ Right，但右声道被轻微修改。

Audacity 中：

立体声轨道 → 拆分立体声轨道 → Left / Right

→ Right 反相 → Left + (-Right) → Left - Right

这样就能提取左右声道之间的差异。因此看到双声道音频时，可以同时考虑文件 A vs 文件 B 和 Left vs Right 两个方向。

## 五、010 Editor 等工具作为补充

Audacity 主要负责采样 Diff、波形 Diff、声道 Diff、频谱 Diff。如果怀疑是直接修改文件字节，再使用 010 Editor。

### 1. 010 Editor

打开两个 WAV 后使用二进制比较功能，重点查看 WAV 的 data 数据块。

不要机械认为 WAV 前 44 字节全部是文件头，44 字节只是最常见的简单 PCM WAV 头长度。WAV 本质是 RIFF 容器（RIFF → fmt / LIST / JUNK /fact/data /...），不同文件的 data 起始偏移可能完全不同。正确做法是找到 data chunk，再比较真正的音频采样数据。

如果差异字节直接出现 66 6C 61 67 7B，ASCII 就是 flag{，说明是最简单的字节 Diff。

### 2. Linux cmp

快速确认两个文件是否存在二进制差异：

cmp file1.wav file2.wavcmp -l

file1.wav file2.wav   # 详细列出差异

适合快速定位不同偏移，但不适合复杂音频信号分析。

## 六、格式与对齐的几个重要补充

### 1. MP3/AAC 不适合直接做采样级二进制 Diff

MP3、AAC 属于有损压缩格式，即使两段听起来完全一样，压缩参数、编码器、帧结构、标签、码率模式不同都可能造成大量二进制差异。如果题目目标明显是音频内容 Diff，可以在 Audacity 中分别导入，让软件解码为采样数据后再反相抵消。

把两个压缩文件分别重新 "转换成 WAV" 并不能保证它们自动变得完全可比，真正需要保证的是解码后的采样率、声道、长度、起点、采样位置一致。

### 2. 不要随便截断较长音频

两个文件长度不同不能直接把长的截到和短的一样，因为长度差本身可能就是线索。先判断差异来自前后附加数据、不同元数据、多出的采样、时间偏移，再决定是否只比较公共部分。

### 3. 32-bit Float WAV 不需要因为 "浮点误差" 直接转 16 位

如果两个文件保存的是 32-bit float PCM，文件里的采样数据依然是确定的二进制数据。不能简单认为 "32 位浮点 → 自动产生无关 Diff"，真正问题通常来自重新编码、格式转换、增益处理、采样率转换，而不是 WAV 自己产生 "浮点精度随机误差"。贸然转成 16-bit 反而可能量化丢失最低位差异，正好把隐藏信息破坏掉。

尽可能保持原始音频格式分析。
