## 一、核心概念与基本原则

### 1.本质定义

将多个字节片段按正确顺序、正确偏移重组为完整文件，或修复缺失/损坏的局部字节；纯字节拼接无任何额外分隔符、换行、文件名、长度字段等冗余数据。常见场景：普通文件切块、文件头/尾拆分、磁盘流量碎片、偏移重组、尾部追加文件、结构字段损坏、标准压缩分卷。

### 2.二进制处理红线

禁止用普通文本编辑器、文本模式脚本、字符串复制处理二进制数据，避免自动加换行、编码转换、CRLF/LF转换、空字节丢失等不可逆破坏。

**优先工具：** 十六进制编辑器、cat/dd、Python二进制接口、PowerShell二进制API。

### 3.拼接前必查项

### 1）分块顺序是否正确

### 2）是否存在缺块、重复块、重叠数据

### 3）每块是否为原文件的连续切片

### 4）是否属于标准压缩分卷

### 5）是否包含完整的文件头与文件尾

### 4.操作原则

**原文件永久备份：** 所有修改在副本上执行，禁止直接在原题附件上反复修改。

**顺序优先级：** 明确偏移量>题目/程序给出的序号>文件名自然数字顺序>文件内容结构>时间信息；修改时间仅作辅助，不可作为可靠依据。

## 二、基础拼接操作

### 1.基础命令：cat

适用于多个连续无重叠的字节块，按顺序直接拼接，无任何额外数据。

cat part1 part2 part3>merged.bin

### 2.标准split分块恢复

split按字母序生成的part_aa/part_ab等分块，字典序与真实顺序一致，可直接通配符拼接：

cat part_*>original.bin

恢复后必须用格式工具验证完整性。

### 3.数字文件名排序陷阱

part1~part10这类命名，Shell通配符按字典序会出现part1、part10、part2的错误顺序，直接cat part*会拼接失败。

**少量分块：** 手动按顺序书写文件名执行拼接

**大量分块：** 使用自然排序后再拼接

printf'%s\0'part*|sort-zV|xargs-0 cat-->merged.bin

### 4.跨平台拼接方法

| 平台 | 命令/方法 | 注意事项 |
| --- | --- | --- |
| Windows CMD | copy/b part1+part2 merged.bin | 必须显式加/b指定二进制模式 |
| PowerShell小文件 | ReadAllBytes数组拼接 | 大文件会占用过高内存 |
| PowerShell大文件 | 流式复制逐文件写入输出流 | 内存占用低，适合大文件 |
| Python | 逐文件读取写入输出流，大文件分块读取 | 跨平台稳定，可自定义排序逻辑 |

三、精确字节级操作：dd

dd适用于按偏移截取、局部覆盖、定点修复，区别于cat的全量拼接，是二进制修复的核心工具。

### 1.核心参数

| 参数 | 含义 |
| --- | --- |
| if= | 输入文件 |
| of= | 输出文件 |
| bs= | 块大小，决定skip/seek/count的单位 |
| skip= | 从输入文件开头跳过的块数 |
| seek= | 从输出文件开头跳过的块数 |
| count= | 读取的块数 |
| conv=notrunc | 不截断输出文件，仅覆盖指定位置 |

### 2.bs=1说明

bs=1表示块大小为1字节，此时skip/seek/count的单位均为字节，逻辑最直观，适合CTF小文件精确操作。

**纠正：** 不是所有dd操作都必须用bs=1；默认块大小为512字节，也可通过iflag=skip_bytes,count_bytes直接按字节处理。

### 3.常用操作

（1）精确截取

从指定偏移提取指定长度的字节段，支持十六进制偏移：

#从偏移0x100开始，提取0x200字节

dd if=file.bin of=chunk.bin bs=1 skip=$((0x100))count=$((0x200))status=none

（2）局部覆盖修复

结合conv=notrunc，仅覆盖指定偏移的字节，保留文件其余内容不变，是修复文件头、CRC等字段的标准方法：

#从偏移0处覆盖4字节ZIP文件头

printf'\x50\x4B\x03\x04'|dd of=fixed.zip bs=1 seek=0 conv=notrunc status=none

（3）插入数据

dd本身不支持直接插入字节（会覆盖后续数据），需拆分为「前半段+插入数据+后半段」再拼接实现。

（4）删除中间段

将文件拆分为删除位置前后两段，再拼接跳过删除区域。

| 操作 | 效果 | 文件大小变化 | 实现方式 |
| --- | --- | --- | --- |
| 覆盖 | 替换指定位置字节，后续偏移不变 | 不变 | dd seek+conv=notrunc |
| 插入 | 在指定位置新增字节，后续整体后移 | 增加 | 拆分前后段+新数据再拼接 |

### 4.核心概念区分

**易错点：** 文件头被覆盖≠文件头缺失，错误地prepend追加头部会导致整个文件偏移错位，所有结构字段全部失效。

## 四、典型文件修复场景

### 1.文件头修复

**头部确实缺失：** 确认头部被删除时，用printf生成正确Magic，再cat拼接到文件开头；优先用printf而非echo-e，行为更稳定可控。

**头部被覆盖：** 禁止prepend追加，用dd从偏移0处覆盖对应字节，保持原文件整体偏移不变。

2.PNG Chunk与CRC修复

Chunk结构

**每个Chunk固定结构：** 4字节Length+4字节Type+Length字节Data+4字节CRC

CRC规则

**计算范围：** Type+Data，不包含Length字段

**CRC偏移：** Chunk起始偏移+8+Data长度

**存储字节序：** 大端序

### 3.重叠分块处理

已知各分块原始偏移存在重叠时，跳过重叠部分再拼接，避免重复字节；偏移信息的优先级远高于文件名排序。

### 4.缺失分块判断

拼接后出现CRC错误、文件截断、结构损坏，优先排查是否缺块，而非反复调整顺序；缺失数据需结合格式规则判断是否可推导，不可强行拼接。

## 五、压缩分卷与普通切块的区分

### 1.核心区分原则

| 类型 | 本质 | 处理方式 |
| --- | --- | --- |
| 标准压缩分卷 | 压缩格式原生的多卷机制，包含卷号、目录关系、跨卷压缩流等结构 | 用对应解压工具打开第一卷 |
| 普通字节切块 | 完整文件按字节机械切割，无额外格式结构 | cat拼接恢复原文件 |

### 2.常见标准分卷

**WinRAR分卷：** archive.part1.rar/part2.rar，直接打开第一卷即可正常解压

7-Zip分卷：archive.7z.001/.002，用7z x archive.7z.001自动读取后续卷

Split ZIP：archive.z01/.z02/.zip，用ZIP工具识别分卷集处理

### 3.认知纠正

❌所有.001文件都绝对不能拼接

✅原生压缩分卷必须用工具打开；若只是普通文件被按字节机械切块，则需要拼接恢复原文件

压缩分卷包含专属元数据与结构，强行cat会破坏格式语义，导致解压失败。
