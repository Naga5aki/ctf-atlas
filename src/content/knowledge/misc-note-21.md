zipinfo是Info-ZIP工具集中的ZIP元数据快速查看工具，等价于unzip-Z，是ZIP题型的第一轮快速侦察工具。它依赖ZIP的中央目录（Central Directory）输出条目信息，可快速定位加密、压缩方式、异常结构等线索，发现问题后再配合zipdetails、十六进制编辑器做深度分析。

## 一、工具定位

核心作用

快速输出ZIP归档内所有条目的文件名、大小、权限、加密状态、压缩算法、时间、扩展字段等技术信息，适用于首轮快速筛查。

进阶工具

发现伪加密、结构损坏、隐藏条目、ZIP64、异常扩展字段时，进一步使用：

zipdetails test.zip

zipinfo-v test.zip

unzip-t test.zip

7z t test.zip

## 二、压缩包整体信息

**典型输出开头：**

**Archive:** test.zip

Zip file size:12345 bytes,number of entries:3

### 1.归档标识

**Archive:** 文件名仅标识当前分析的ZIP文件，无特殊考点。

### 2.文件大小与尾部拼接判断

Zip file size是ZIP文件自身的实际磁盘大小。

### 3.条目数量

number of entries:N是中央目录中登记的成员总数，不等于普通文件数量。

**条目可能包含：** 普通文件、目录、符号链接、空文件、重复文件名、特殊条目等。条目数与可见文件数不一致，不能直接判定存在隐藏文件，还需考虑目录条目、损坏条目、加密成员等情况。

## 三、单条目字段详解

**典型单条目行：**

-rw-r--r--3.0 unx 1024 tx defN 24-May-20 10:30 flag.txt

**从左到右依次为：** 权限位、ZIP版本、宿主平台、未压缩大小、属性字段、压缩方法、修改日期、修改时间、文件名。

### 1.权限与文件类型

**首字符标识文件类型：** -普通文件、d目录、l符号链接；后续三组rwx对应Unix读/写/执行权限。

执行权限在该字段中体现，与属性字段的x无关。

**辅助判断：** 可执行权限+Unix平台，可能对应脚本、ELF等文件。

### 2.ZIP创建版本

例如3.0，表示创建该条目的ZIP程序版本近似值，用于标识格式兼容性，不能精确判定具体压缩软件。

**异常版本提示：** 可能存在ZIP64、AES加密、特殊扩展算法、非标准生成工具。

### 3.宿主平台

例如unx，标识条目来源的宿主文件系统，常见值：unx（Unix）、fat、mac、hpf、vms。

仅作辅助线索，ZIP可被重打包修改，不能仅凭平台断定题目环境。

### 4.未压缩大小

单位为字节，是文件解压后的原始大小。

重点关注

**0字节：** 可能是空文件、目录条目、干扰项，也可能是Data Descriptor导致本地头大小字段为0，需结合bit3判断。

极大值（如4294967295）：警惕ZIP64，真实值存储在ZIP64扩展字段中，并非正好4GiB-1。

**极高压缩比：** 提示数据高度重复（大量0、重复字符），也可能是ZIP bomb题型。

### 5.属性字段（核心修正点）

两位字符组成，第一位表示文件类型+加密状态，第二位表示扩展字段/数据描述符状态；其中第二位的x不是“可执行”，可执行权限在左侧权限位中。

**第一位：** 类型与加密

| 字符 | 含义 |
| --- | --- |
| t | 标记为文本，未加密 |
| b | 标记为二进制，未加密 |
| T | 标记为文本，已标记加密 |
| B | 标记为二进制，已标记加密 |

仅为ZIP工具的属性标记，不能替代file命令的真实文件类型识别。

**第二位：** 扩展结构状态

| 字符 | 含义 |
| --- | --- |
| - | 无Data Descriptor，无Extra Field |
| l | 存在Data Descriptor/扩展本地头 |
| x | 存在Extra Field |
| X | 同时存在Data Descriptor和Extra Field |

### 6.压缩方法

常见缩写对应不同算法与级别：

| 缩写 | 含义 |
| --- | --- |
| stor | Store存储模式，不压缩 |
| defS | Deflate超快速压缩 |
| defF | Deflate快速压缩 |
| defN | Deflate标准压缩（最常见） |
| defX | Deflate最高压缩 |

### 7.修改时间

记录条目的修改时间，使用zipinfo-T可输出便于排序的标准化时间格式。

异常时间（1970、1980、2099、规律排列）可作为解题线索，但也可能是打包工具默认值、时区差异导致。

### 8.文件名

**重点关注：** 特殊字符、十六进制/Base64串、重复文件名、异常路径、隐藏文件、双扩展名、路径穿越（../）、乱码、超长名称。

进阶考点

ZIP的LFH和CDH各自保存一份文件名，高级题型可能制造两份文件名不一致，导致不同工具显示不同名称，需通过十六进制分析确认。

## 四、核心考点专项

### 1.加密标志与伪加密

加密位纠正

ZIP的General Purpose Bit Flag中，bit 0为加密标志位，置1表示文件标记为加密；bit 3是Data Descriptor标志位，二者不可混淆。

伪加密判断

看到属性字段出现T/B（标记加密），不要直接爆破密码，先对比LFH与CDH的加密标志位：

**典型伪加密：** LFH bit0=0，CDH bit0=1，两份元数据不一致，实际数据未加密。

**修复原则：** 仅清除bit0，即new_flags=old_flags&~0x0001，禁止直接全改为00 00，避免破坏bit3（Data Descriptor）、bit11（UTF-8）等其他有效标志位。

2.Data Descriptor

当flag bit3=1时，LFH中的CRC32、压缩大小、未压缩大小字段无有效值，真实数据存储在文件数据后的Data Descriptor中。

**易错点：** 看到LFH中size为0，不能直接判定文件为空，需先检查bit3是否置位。

3.Extra Field

属性第二位为x/X时，说明存在扩展字段，可能存储：ZIP64信息、Unix/NTFS时间戳、UID/GID、Unicode文件名、AES加密信息、扩展属性等。

异常ZIP推荐使用zipinfo-v查看扩展字段详情。

### 4.压缩方法

Store模式

不压缩，文件原始数据直接存放在LFH之后，未加密的Store文件可直接手工carve：

数据起始偏移=LFH偏移+30字节固定头+文件名长度+扩展字段长度

**注意：** Store+加密模式下，数据仍是密文，无法直接读取明文。

Deflate模式

分四种压缩级别，均为标准Deflate算法，仅压缩效率不同，不影响解压兼容性。

### 5.尾部统计与压缩率

**输出末尾示例：**

3 files,3072 bytes uncompressed,1120 bytes compressed:63.5%

**百分比含义：** 节省的空间比例，即(1-压缩后/未压缩)×100%，不是压缩后占原文件的比例。

0%压缩率：可能是Store模式，也可能是JPEG、压缩包、加密数据等不可压缩内容，不等于一定是Store。

95%+高压缩率：通常对应高度重复的数据。

## 五、能力边界与局限

zipinfo的列表完全依赖中央目录（CD），因此存在固有局限：

仅登记在中央目录中的条目才会被列出。

若存在孤立LFH（仅本地文件头+数据，未登记进中央目录），zipinfo无法发现，即所谓的“未登记文件/孤儿条目”。

应对方法

使用binwalk、foremost、xxd、010 Editor等工具直接搜索50 4B 03 04，统计所有本地文件头数量，与中央目录条目数对比，排查隐藏条目。
