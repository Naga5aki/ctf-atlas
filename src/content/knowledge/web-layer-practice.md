多层题的核心不是“再扫一遍”，而是**把流量从攻击机送到目标网段，再把结果带回来**。路由、端口转发、SOCKS 代理是三种不同的东西，混用会断。

> 只在授权靶场搭建与测试；跨网段扫描前确认范围。

## 00 30 秒速查

| 我要… | 先做… | 备注 |
|---|---|---|
| 画拓扑 | 每台 `ip a`/`ip route` | 双网卡 |
| 第一跳 | 边界机出网/入站 | 选方向 |
| 单端口 | `ssh -L`/socat | 简单 |
| 全局 | `ssh -D`/frp socks5 | 工具友好 |
| 穿 NAT | 反向隧道 | 目标出网 |
| 多层 | 每层一个 SOCKS | 级联 |
| 代理扫描 | `proxychains4 nmap -sT` | 不用 -sS |
| 断链 | 逐层 curl/日志 | 定位 |
| 稳定性 | 心跳/守护 | 防掉线 |

## 01 原理与成立条件

```text
攻击机 → 边界（双网卡）→ 跳板（双网卡）→ 目标
             ├─ 路由转发
             ├─ 端口转发
             └─ SOCKS 代理
每层 = 一个可达位置 + 一组凭据
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 边界可达 | 第一跳登录/执行 | 先拿点 |
| 转发允许 | `ip_forward`/ACL | 改 SOCKS |
| 出网/入站 | NAT/防火墙 | 换方向 |
| 凭据 | 下一层 | 复用/找配置 |

## 02 判断与分型

```text
攻击机能直接到内网吗？
 ├─ 能 → 加路由
 └─ 不能
     ├─ 边界能出网 → 反向隧道
     ├─ 边界能入站 → 正向端口转发
     └─ 只能 HTTP → chisel/reGeorg
需要多端口吗？
 ├─ 单端口 → ssh -L/socat
 └─ 多端口 → SOCKS
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| 边界双网卡 | 可进内网 | 选隧道 |
| `ip_forward=1` | 可路由 | 加路由 |
| 只能 80/443 出 | HTTP 隧道 | chisel |
| 目标主动连出 | 反向 | frp |
| 多层双网卡 | 级联 | 每层 SOCKS |
| 扫描 filtered | ACL | 从边界扫 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| ping 通但 curl 超时 | 只开特定端口 | 换端口 |
| 隧道建立但扫不到 | 路由/DNS | 逐层测 |
| SOCKS 通但工具失败 | 不支持代理 | proxychains |
| 一次断线 | 长连接超时 | 心跳 |

## 03 利用阶梯

### L0 画拓扑

**前提**：已拿到边界机。

**步骤**：
1. 每台机器 `ip a`/`ip route`/`ipconfig`。
2. 标出网段、双网卡、网关、DNS。
3. 画“攻击机→边界→跳板→目标”的图。
4. 标每层可用凭据/端口。

**成功标志**：拓扑图与每层入口/出口。

**失败分支**：信息不全→回内网收集页；无第二网卡→单层。

### L1 第一跳

**前提**：边界机可执行/可登录。

**步骤**：
1. 判断方向：边界能出网→反向；攻击机能入站→正向。
2. 单端口先 `ssh -L 8080:target:80`。
3. 测 `curl 127.0.0.1:8080`。
4. 记录启动命令与端口。

**成功标志**：攻击机本地端口能访问内网服务。

**失败分支**：端口冲突→换端口；协议不对→换工具。

### L2 SOCKS 全局代理

**前提**：需要多端口/多工具。

**步骤**：
1. `ssh -D 1080 -N -f user@boundary`。
2. 或 frp `plugin = socks5`。
3. `proxychains4` 配 `socks5 127.0.0.1 1080` + `proxy_dns`。
4. `curl`/`nmap -sT` 验证。

**成功标志**：代理下能访问多个内网端口。

**失败分支**：UDP/ICMP 不支持→换工具；DNS 泄漏→`proxy_dns`。

### L3 级联与多层

**前提**：目标在第二/第三层网段。

**步骤**：
1. 每层只暴露一个 SOCKS，减少配置。
2. 跳板 B 回连边界机的 frps，边界机再回连攻击机。
3. 或 Venom/EW 逐层 `goto`。
4. 每层用 `curl` 测下一跳，再扫描。
5. 记录每层入口/出口/端口。

**成功标志**：攻击机代理链能到最深目标。

**失败分支**：级联配置错→逐层日志；端口未暴露→补映射。

### L4 稳定性与目标

**前提**：链路已通。

**步骤**：
1. 心跳/保活：frp `heartbeat_interval`、chisel `--keepalive`。
2. 守护：`nohup`/`systemd`/循环。
3. 降并发/减层，避免 SOCKS 瓶颈。
4. 拿目标后记录路径/权限，不改配置/删日志。
5. 按题目要求清理。

**成功标志**：链路稳定，目标可复现访问。

**失败分支**：频繁掉线→换 chisel/减层；被封→降速/停。

## 04 绕过与边界

| 限制 | 替代 | 示例 |
|---|---|---|
| 不能改路由 | SOCKS/端口转发 | ssh -D |
| 不能出 TCP | HTTP/WS | chisel |
| 只能 DNS | DNS 隧道 | 慢 |
| 云 ACL | 从边界本地扫 | 换源 |
| 工具不走代理 | proxychains | 包一层 |
| 长连接断 | 心跳/守护 | 保活 |
| 单连接瓶颈 | 多端口/降并发 | 分流 |

边界：路由需二层可达与转发权限；云安全组常拦源地址；SOCKS 不转 ICMP/UDP；多层每加一跳增延迟；扫描范围以授权为准。

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 本地端口不通 | 转发/进程 | 看日志 |
| 扫描全 filtered | ACL/源 | 从边界扫 |
| DNS 失败 | `proxy_dns` | 开/写 hosts |
| 级联断 | 端口/配置 | 逐层测 |
| 频繁掉线 | 长连接 | 心跳/换工具 |
| 工具报错 | 不支持代理 | proxychains |
