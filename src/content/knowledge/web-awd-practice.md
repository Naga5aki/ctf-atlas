AWD（Attack With Defense）里，每队一台相同靶机，既要打别人，也要防住别人。得分来自**攻破他人 + 自己服务可用 + flag 不被拿走**；只攻不防会掉分，只防不攻拿不到分。

> 只在比赛规则允许的范围内操作；不要攻击主办方或其他非靶标地址。

## 00 30 秒速查

| 我要… | 先做… | 备注 |
|---|---|---|
| 读规则 | flag 位置/提交/重启 | 先确认 |
| 备份 | 源码/配置/数据库 | 带哈希 |
| 审计 | 上传/包含/命令/SQL | 先 grep |
| 打点 | 复现→批量→提交 | 排除自己 |
| 修补 | 最小改动 | 不自断服务 |
| 监控 | 访问日志/新文件 | 找 webshell |
| SLA | 首页/登录/接口 | 每轮自测 |
| 复盘 | 被打点/补丁/下轮 | 记录 |

## 01 原理与成立条件

```text
攻击：漏洞 → 读 flag → 提交
防守：服务可用 + flag 不被读 + 修补不被绕过
轮次：固定时间刷新 flag
```

| 条件 | 含义 | 不满足时 |
|---|---|---|
| 规则允许 | 目标/手段 | 停 |
| 服务可访问 | 端口/首页 | 保 SLA |
| 漏洞可复现 | payload | 换点 |
| 补丁不破坏功能 | 自测 | 回滚 |

## 02 判断与分型

```text
先看自己：
 ├─ 服务正常？→ 保 SLA
 ├─ 有 webshell？→ 清
 └─ 补丁是否生效？→ 自测
再看对手：
 ├─ 同漏洞可复现 → 批量
 ├─ 只读 flag → 提交
 └─ 被修 → 换点/换队
```

| 信号 | 含义 | 下一步 |
|---|---|---|
| 首页 502 | 服务挂 | 先恢复 |
| 新增 `.php` | webshell | 隔离/删 |
| 访问日志异常 POST | 被打 | 看 payload |
| flag 刷新 | 新轮次 | 重取 |
| 补丁后功能坏 | 过度修改 | 回滚 |
| 对手已修 | 换漏洞 | 审计 |

| 假阳性 | 原因 | 处理 |
|---|---|---|
| 文件时间是现在 | 部署/同步 | 看内容 |
| 日志有扫描 | 未成功 | 看响应 |
| 补丁没拦截 | 入口不同 | 换点 |
| 服务 200 | 功能可能坏 | 自测 |

## 03 利用阶梯

### L0 规则与开局

**前提**：拿到靶机/账号。

**步骤**：
1. 读 flag 位置/提交方式/能否重启/能否改源码。
2. 备份源码/配置/数据库，记哈希。
3. 记录初始 flag、端口、账号。
4. 起访问日志/进程监控。
5. 分工：攻击/审计/修补/提交。

**成功标志**：有备份、基线、分工。

**失败分支**：权限不足→问主办方；备份失败→换目录。

### L1 快速审计

**前提**：有源码/备份。

**步骤**：
1. grep 执行/包含/反序列化/超全局。
2. 看上传目录、后台、SQL 拼接。
3. 对照正常请求找入口。
4. 记录“文件:行号 + payload”。

**成功标志**：至少一个可复现漏洞。

**失败分支**：源码混淆→解密；无源码→黑盒。

### L2 批量打点

**前提**：漏洞可复现。

**步骤**：
1. 单目标验证，确认读 flag。
2. 目标列表排除自己/主办方。
3. 每目标独立会话，失败不阻塞。
4. 先小批量，再全量；降并发。
5. 记录成功目标/ payload/时间。

**成功标志**：稳定拿到他队 flag 并提交。

**失败分支**：被 WAF→降速/换 payload；对手已修→换点。

### L3 修补与监控

**前提**：知道自己漏洞/被打。

**步骤**：
1. 最小改动：删危险点/白名单/关函数/加兜底。
2. 改完立即自测首页/登录/上传/接口。
3. 监控访问日志、新增/修改文件、进程/cron。
4. 发现 webshell：隔离样本→删→查入口。
5. 不用影响他人的持久化手段。

**成功标志**：漏洞被堵，服务正常，webshell 清除。

**失败分支**：补丁破坏功能→回滚；入口未知→继续审计。

### L4 轮次复盘

**前提**：一轮结束。

**步骤**：
1. 记被打点、payload、是否成功。
2. 补丁是否生效、是否被绕过。
3. 对手哪些队未修、下轮打谁。
4. 更新脚本/目标表。
5. 保留备份，准备回滚。

**成功标志**：下轮有明确攻击/防守清单。

**失败分支**：信息不足→加日志；时间不够→保 SLA 优先。

## 04 攻防边界

| 场景 | 做法 | 边界 |
|---|---|---|
| 读 flag | 只读命令/查询 | 不改数据 |
| 批量 | 降并发 | 不打非靶标 |
| 修补 | 最小改动 | 保功能 |
| webshell | 隔离后删 | 留样本 |
| 持久化 | 比赛通常不需要 | 不留后门 |
| 提权 | 规则允许才做 | 不崩服务 |

边界：改源码可能影响 SLA；重启可能清 flag/服务；对手可能已修；监控日志本身可能被清；所有操作以规则为准。

## 05 非典型入口

| 位置 | 示例 | 注意 |
|---|---|---|
| 上传目录 | webshell | 清理 |
| 后台 | 弱口令 | 改密 |
| 数据库 | flag 表 | 只读 |
| 计划任务 | 对手持久化 | 清 |
| 日志 | 攻击痕迹 | 保留 |
| 配置 | 数据库口令 | 备份 |

## 06 差异速查

| 计分 | 来源 | 影响 |
|---|---|---|
| 攻击分 | 他队 flag | 提交 |
| 防守分 | 自己 flag | 不被读 |
| SLA | 服务可用 | 宕机扣分 |
| 轮次 | 定时刷新 | 重取 |

## 07 工具与验证

| 目标 | 工具/命令 |
|---|---|
| 备份 | `tar`/`sha256sum` |
| 审计 | `grep -rnE` |
| 批量 | Python requests |
| 监控 | `tail -f`/`tcpdump` |
| 找 shell | `find -mmin`/grep |
| 自测 | curl 首页/登录 |

验证顺序：规则 → 备份 → 审计 → 打点 → 修补 → 复盘。

## 08 实战流程

| 阶段 | 动作 | 产出 |
|---|---|---|
| 1 开局 | 规则/备份/基线 | 环境 |
| 2 审计 | grep/入口 | 漏洞 |
| 3 打点 | 单点→批量 | flag |
| 4 修补 | 最小改动 | 堵住 |
| 5 监控 | 日志/文件 | 告警 |
| 6 复盘 | 得失/下轮 | 计划 |

## 09 失败分支

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 服务挂 | 补丁/进程 | 先恢复 |
| 打点失败 | 已修/WAF | 换点/降速 |
| flag 提交错 | 格式/轮次 | 看规则 |
| 补丁无效 | 入口不同 | 重审 |
| 功能坏 | 改多 | 回滚 |
| webshell 反复 | 入口未堵 | 找写入点 |
