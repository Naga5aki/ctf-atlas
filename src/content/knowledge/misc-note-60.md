## 一、ICMP协议基础考点

### 1.协议定位与典型应用

ICMP（Internet Control Message Protocol，互联网控制报文协议）主要用于网络诊断、差错控制与状态反馈，日常使用的ping命令就是基于ICMP Echo请求/应答机制实现。

### 2.核心报文类型

流量分析中最常见的是Echo类报文，也是隐写题的主要载体：

Type 8：Echo Request（回显请求），即ping发出的请求包

Type 0：Echo Reply（回显应答），即对方返回的响应包

### 3.核心关键字段

| 字段名 | 含义 | 考点定位 |
| --- | --- | --- |
| icmp.type | ICMP报文类型 | 区分请求/应答，过滤去重必用 |
| icmp.code | 报文代码 | 配合类型细分报文功能，冷门隐写载体 |
| icmp.seq | 序列号 | 匹配请求与响应对；序列号隐写的核心载体 |
| icmp.ident | 标识符 | 区分同主机的多个ping会话；冷门隐写载体 |
| frame.len | 数据帧总长度 | 长度隐写高频字段，包含链路层头部开销 |
| ip.len | IP数据包总长度 | 长度隐写精准字段，包含IP头+ICMP头+载荷 |
| data.len | ICMP载荷长度 | 纯数据部分长度，最精准的长度隐写载体 |

## 二、核心高频考点：ICMP长度隐写

### 1.隐写原理

**属于典型的存储型隐蔽信道：** 不将秘密数据直接放在报文载荷明文中，而是通过人为控制每个ICMP包的总长度，用长度数值对应字符的ASCII编码，通过长度序列传递隐藏信息。

例如要传输flag，对应ASCII值为102、108、97、103，则构造4个长度分别为对应数值（叠加固定偏移）的ICMP包，接收方提取长度序列后即可还原明文。

### 2.典型异常识别特征

出现以下特征时，可优先判定为长度隐写题型：

**长度异常波动：** 正常ping包载荷长度固定，题目中数据包长度持续无规律变化

**载荷无意义：** ICMP载荷内容仅为固定前缀+重复无意义字符（如heiheihei!!+连续的a），无实际语义信息

**数量匹配：** 数据包数量与flag常规长度相近，呈一一对应关系

### 3.三类长度字段的区分

不同层级的长度字段包含的开销不同，解题时需先确认隐写对应的长度层级，不可直接混用。

frame.len：整帧总长度，包含以太网链路层头+IP头+ICMP头+数据载荷，数值最大

ip.len：IP数据包总长度，包含IP头+ICMP头+数据载荷，不含链路层开销

**载荷长度：** 纯数据部分的长度，可通过换算得到：

ICMP载荷长度=ip.len-20（标准IP头）-8（标准ICMP头）

### 4.固定偏移与偏移爆破

偏移产生的原因

协议头部、固定前缀字符串会带来固定的长度开销，因此实际提取的长度值=真实字符ASCII值+固定偏移量，直接转换通常会得到乱码。

偏移爆破方法

遍历0~128范围内的偏移值，将每个长度减去偏移后转换为字符，筛选出全部为可打印ASCII、且匹配flag{等格式前缀的结果，即为正确偏移。

**典型Python实现逻辑：** 遍历偏移→批量计算长度-偏移→校验是否全为可打印字符→输出候选结果

### 5.请求/应答去重

正常ping通信中，请求包与应答包的载荷长度完全一致。若不做过滤直接提取长度，会导致数据成对重复，拼接后出现字符重复。

**标准处理：** 过滤仅保留icmp.type==8的请求包，或仅保留应答包，单侧提取数据。

## 三、其他ICMP隐蔽信道考点

除长度隐写外，ICMP还有多种常见隐写载体，属于进阶延伸考点：

| 隐写类型 | 藏匿位置 | 特点 |
| --- | --- | --- |
| 载荷明文隐写 | ICMP数据载荷（data.data） | 入门级考点，数据直接以明文、Hex、Base64等形式藏在载荷中 |
| 序列号隐写 | icmp.seq字段 | 每个包的序列号对应一个字符的ASCII值，逐个传递数据 |
| 标识符隐写 | icmp.ident字段 | 用法与序列号类似，或用于区分不同隐蔽信道会话 |
| 时间型隐写 | 数据包的时间间隔（frame.time_delta） | 通过相邻包的发送时间差传递数据，属于时间型隐蔽信道，隐蔽性更强 |
| 类型/代码隐写 | icmp.type+icmp.code | 冷门考点，通过类型与代码的组合编码传递数据 |
| 分片载荷隐写 | 多个ICMP包的载荷拼接 | 将完整文件/大段数据拆分到多个ICMP载荷中，需按序重组 |

## 四、工具操作考点

### 1.Wireshark常用过滤语法

**基础筛选所有ICMP：** icmp

**仅查看请求包：** icmp.type==8

**仅查看应答包：** icmp.type==0

**结合IP过滤：** icmp&&ip.addr==1.1.1.1

### 2.tshark批量提取命令

**提取所有请求包的帧长度：**

tshark -r抓包文件.pcap -Y"icmp.type==8" -T fields -e frame.len

同时提取多维度字段（帧序号、帧长度、IP长度、序列号）：

tshark -r抓包文件.pcap -Y"icmp.type==8" -T fields\

-e frame.number -e frame.len-e ip.len -e icmp.seq

**核心参数：** -r读取文件、-Y过滤规则、-T fields字段输出模式、-e指定提取字段

## 五、高频易错点与避坑指南

**长度层级混淆：** 误用frame.len直接转ASCII，未扣除链路层头部开销，导致整体数值偏大、全量乱码。

**请求应答未去重：** 未过滤单侧报文，导致提取的序列字符全部重复，拼接结果错误。

**偏移盲猜硬凑：** 未系统爆破偏移，仅凭个别字符猜测，易出现局部正确、整体错位的问题。

**载体遗漏：** 仅盯着长度分析，忽略序列号、载荷、时间间隔等其他隐写载体，无法定位数据。

**顺序错乱：** 未严格按数据包时间顺序提取字段，导致还原的明文顺序颠倒、内容错乱。

**大小端错误：** 多字节数据场景下，未注意字节序问题，导致数值转换错误。

**异常包干扰：** 少量正常ping包、重传包混入序列，需结合特征剔除异常值后再解码。
