## 一、适用范围及原理

JPHS（JPEG Hiding System）是 CTF Misc 方向 JPEG 频域隐写的核心工具，抗检测能力显著高于同类工具，通用隐写工具无法解析其嵌入的数据。

**格式边界：** 仅支持 JPEG/JPG 格式，不兼容 PNG、BMP、GIF 等其他图像格式，处理非 JPEG 文件必然失败。

**实现原理：** 基于 DCT 系数的伪随机 LSB 替换机制。以用户密码为种子，通过 Blowfish 算法生成伪随机序列，随机选取非零 DCT 系数修改其最低位嵌入隐藏数据，最后重新压缩为 JPEG 图像。

**核心特性：** 隐藏数据在图像中均匀分布，无明显统计特征；对图像质量影响极小，肉眼完全不可察觉；单张图片隐藏容量约为文件体积的 10%~15%。

## 二、使用方法

（一）Kali Linux 命令行版

工具包含 jphide（嵌入数据）和 jpseek（提取数据）两个命令行程序。

### 1.嵌入隐藏数据

jphide  原图.jpg  输出加密图.jpg  待隐藏文件  密码

工具会自动校验载体容量，超出上限则拒绝执行嵌入。

### 2.提取隐藏数据

jpseek  加密图片.jpg  输出文件路径  密码

密码错误时无明确报错提示，仅输出乱码二进制数据。

（二）Windows 图形化版（JPHSWIN）

图形化程序集成嵌入与提取全部功能，无需命令行操作。

### 1.嵌入数据流程

① 点击 Open jpeg 选择载体 JPG 图片；

② 点击 Hide 选择需要隐藏的文件；

③ 点击 Pass phrase 设置加密密码；

④ 点击 Save jpeg as 指定输出路径，生成带隐写的图片。

### 2.提取数据流程

① 点击 Open jpeg 加载带隐写的 JPG 图片；

② 点击 Pass phrase 输入正确密码；

③ 点击 Seek 指定输出文件路径，提取隐藏数据。

3.关键注意：所有文件路径、文件名必须为纯英文，禁止包含中文、空格或特殊字符，否则会静默失败。

## 三、应用场景

### 1.基础 JPEG 隐写解题

对应 CTF 常规 JPHS 考点，出题人将 flag、压缩包、密钥等文件以密码加密嵌入 JPEG 图片，输入密码即可直接提取。

### 2.密码爆破场景

JPHS 无专用高速爆破工具，需通过 Python 脚本调用 jpseek 进行字典爆破，速度约为每秒数百次。实战中优先尝试通用弱口令，再结合 EXIF 信息、题目提示文本等线索定位密码。

### 3.批量隐写处理

结合 Shell 脚本批量遍历目标目录下的所有 JPEG 文件，依次提取隐藏数据并自动拼接，适用于 flag 拆分藏匿到多张图片的综合题型。

## 四、补充点

### 1. 隐写识别方法

**精准识别：** 使用stegdetect工具扫描图片，输出包含jphide字样即可确认，这是目前准确率最高的识别方式。

**辅助特征：** 同分辨率下文件体积异常偏大；题目描述出现 “频域”“DCT”“JPEG 专用” 等关键词。

### 2. 标准解题流程

① 先用steghide info快速排查 Steghide 隐写；

② 无结果则用stegdetect检测，确认是否为 JPHS 隐写；

③ 尝试通用弱密码提取；

④ 结合题目线索寻找密码，必要时小范围字典爆破；

⑤ 提取文件后根据格式做后续深度分析。

### 3. 避坑指南

**严格限定格式：** 仅处理 JPEG 文件，非 JPEG 格式直接跳过；

**路径规范：** 文件路径、输出路径、密码禁止包含中文、空格及特殊字符；

**密码大小写敏感：** 必须与嵌入时的密码完全一致；

**版本通用兼容：** 命令行版、Windows 图形版、第三方兼容版算法完全统一，可交叉加解密；

Windows 环境：JPHSWIN 必须放在纯英文路径下运行，中文路径会导致提取失败且无报错。

### 4. 进阶注意事项

二次压缩会改变 DCT 系数，直接破坏隐藏数据，导致无法提取；

若出题人修改 JPHS 源码自定义算法，常规工具失效，需手动分析 DCT 系数定位数据；

密码正确但输出乱码时，可通过 binwalk 识别文件格式，排查是否为压缩包、二次加密文件等。
