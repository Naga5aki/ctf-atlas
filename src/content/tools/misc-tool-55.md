## 一、工具概述

BaseCrack 是Misc 方向的全自动多进制嵌套解码工具，核心用于解决多层 Base 家族编码循环嵌套的高频考点，支持Base16/32/36/58/62/64/64url/85/91 全主流编码类型，可省去人工逐层试解码的繁琐操作。v4.0 版本新增图片 EXIF 元数据提取、OCR 文字识别能力，覆盖纯文本、图片两类主流密文载体。

## 二、核心命令及参数

核心参数表

| 参数 | 功能说明 |
| --- | --- |
| -m | 开启 Magic 自动递归模式，自动识别每层编码类型并循环解码至无法继续，是多层套娃题的核心必加参数 |
| -s "密文串" | 直接在命令行传入密文字符串解码，适配短密文、单行密文场景 |
| -f 密文文件.txt | 读取本地文本文件内的密文解码，适配长密文、多行分段密文、批量密文场景 |
| -i 图片文件 | 从图片载体提取密文解码，默认启用 EXIF 元数据提取模式 |
| -b 编码类型 | 手动锁定编码类型，禁止自动遍历识别，适配明确指定编码的题型 |
| -c | 图片解码时切换为 OCR 文字识别模式，适配密文绘制在图片画面中的场景 |
| -o 输出文件.txt | 将完整解码过程与最终结果保存到指定文件 |
| -h | 查看工具全部参数说明 |

高频组合命令

**字符串多层嵌套解码：** python basecrack.py -m -s "密文串"

文件密文批量解码并导出结果：python basecrack.py -m -f 密文.txt -o result.txt

图片 EXIF 密文自动解码：python basecrack.py -m -i 图片.png

图片 OCR 识别并解码：python basecrack.py -m -i 图片.png -c

**指定单一编码解码：** python basecrack.py -b base58 -s "密文串"

## 三、应用场景

### 1.多层 Base 套娃题

**题目特征：** 直接给出无额外提示的杂乱长字符串。

**解法：** 开启自动递归模式，一键完成全部嵌套层级的解码。

### 2.文档批量密文题

**题目特征：** 附件为 TXT 文本，包含多段 Base 编码或超长密文，不适合命令行直接粘贴。

**解法：** 读取文件解码并将结果导出到本地文件，可直接搜索 flag 关键词快速定位答案。

### 3.图片 EXIF 藏密文题

**题目特征：** 图片视觉内容正常，密文隐藏在 EXIF 元数据的注释字段中，右键属性无法直接查看。

**解法：** 默认 EXIF 模式直接提取并自动递归解码。

### 4.图片内嵌文字密文题

**题目特征：** 密文以文字形式直接绘制在图片画面中，无法直接复制。

**解法：** 开启 OCR 模式识别图片文字后自动解码；识别出错时可手动提取文字，再通过文件模式解码。

### 5.固定单一编码题

**题目特征：** 题干明确指定密文的编码类型，不允许自动遍历解析。

**解法：** 手动指定编码类型，关闭自动递归模式，避免过度解析产生乱码。

## 四、补充点

### 1. 版本核心差异（v4.0 vs v3.x）

| 功能项 | v3.x 及更早版本 | v4.0 版本 |
| --- | --- | --- |
| 默认解码行为 | 自动递归解码到底 | 仅解码 1 层，不递归 |
| 递归控制参数 | -r 指定解码层数 | 移除该参数，改用 -m 开启递归 |
| 图片支持 | 无 | 支持 EXIF 提取与 OCR 识别 |
| 指定编码参数 | -e | 改为 -b |

### 2. 高频避坑指南

遗漏 -m 参数：v4.0 默认仅解码 1 层，不加该参数会导致多层密文仅解出第一层中间结果，是最常见的使用错误。

CMD 特殊字符冲突：Windows CMD 中，密文包含 &、|、<、> 等控制字符时会被解析为命令，需先执行 chcp 65001 切换 UTF-8 编码，或将密文保存为文件通过 -f 参数读取。

**过度解析乱码：** 单一编码的密文开启递归模式，会被强行向下解析产生乱码；需去掉 -m 参数，手动指定编码类型。

OCR 识别误差：图片文字模糊、倾斜、有背景干扰时会导致识别残缺，需手动校正文字后再解码。

**密文不完整：** 必须完整复制全部密文，包括末尾的 = 填充符，缺失字符会直接导致解码失败。

**小众自定义编码：** 工具仅支持主流 Base 编码，遇到自定义编码时会停止解析，需手动编写解码脚本。

### 3. 标准解题流程

**判断密文载体类型：** 纯字符串优先用字符串模式解码；TXT 附件用文件模式解码；图片附件先尝试默认 EXIF 模式，无结果再开启 OCR 模式。

若自动解码结果为乱码，关闭递归模式，改用 -b 参数手动指定题目提示的编码类型。

解码完成后，在结果中搜索 flag{ 关键词快速定位最终答案。
