## 适用场景

需要对 PE、ELF 或其他本机代码做静态分析时使用。先对样本副本计算哈希，再导入到独立项目。Ghidra 成功加载文件，只证明它能够解析当前格式；反编译函数的变量名和类型仍需结合汇编验证。

## 01 导入与自动分析

1. 建立独立项目，使用 **File → Import File** 选择样本副本。
2. 核对 Ghidra 识别出的格式、处理器、大小端和基址；原始二进制若未被识别，需要人工确定装载参数。
3. 打开程序并运行自动分析。保留导入时的选项和程序哈希，方便后来复现。

若符号表被剥离，不必等待自动命名给出答案；从入口、导入函数、字符串和控制流找锚点。

## 02 沿证据阅读

| 视图 | 用途 | 注意点 |
|---|---|---|
| Strings/Defined Strings | 寻找提示文字、路径和格式串 | 字符串存在不代表执行到它 |
| References/Xrefs | 从提示或常量回溯调用者 | 区分直接引用与间接构造 |
| Listing | 看真实指令、调用约定、内存访问 | 类型和符号扩展以指令为准 |
| Decompiler | 快速理解分支和变换 | 推断出的变量名与数组边界可能失真 |

从成功提示的引用追到比较函数，再向上找输入源；把关键函数按“读取输入、转换、比较、输出”重命名。遇到看似不可能的反编译表达式，回到 Listing 检查字节宽度、位运算优先级与内存布局。

## 03 留下可复核记录

记录函数地址、样本哈希、关键常量的原始字节、比较长度以及自己改过的类型/名称。最终候选输入要回原程序验证；静态分析项目中的注释不是运行证据。
