## 一、适用范围及原理

**工具定位：** 经典文本隐写工具，是 CTF 中行尾空白隐写的核心考点。

**核心原理：** 以文本行尾的空格、制表符为隐写载体，用空格代表二进制 0、制表符代表二进制 1，将隐写数据拆分后逐位嵌入行尾空白处，肉眼无法分辨。

**功能特性：** 内置数据压缩与加密能力，CTF 题目普遍启用压缩模式嵌入隐写内容。

**格式边界：** 仅作用于纯文本文件，完全依赖行尾空白字符存储隐写数据。

## 二、使用方法

核心参数

| 参数 | 功能说明 |
| --- | --- |
| -C | 启用压缩模式，匹配绝大多数出题场景，是最易遗漏的核心参数 |
| -p "密码" | 指定解密密钥，用于提取带密码加密的隐写数据 |
| -l 数值 | 限定每行末尾可用空白长度，适配限制空格位数的冷门题型 |

常用命令

**无密码无压缩基础提取：** snow 目标文本.txt

压缩模式提取（最高频）：snow -C 目标文本.txt

压缩 + 密码提取：snow -C -p "密码" 目标文本.txt

## 三、应用场景

**基础行尾空白隐写：** flag 直接以压缩模式嵌入纯文本行尾，单条命令即可完成提取。

**带密码加密隐写：** 隐写数据经密码加密，需结合题目描述、文件元数据等线索获取密码后提取。

**载体嵌套隐写：** 隐写文本内嵌于图片、压缩包等载体中，需先通过 binwalk、zsteg 等工具分离出纯文本文件，再执行解密。

**多层复合隐写：** stegsnow 提取结果为 Base 编码、摩斯密码等中间格式，需二次解码转换后得到最终 flag。

## 四、补充点

高频避坑指南

禁止用 Windows 记事本打开 / 另存文件，记事本会自动清除行尾空白，直接销毁隐写数据；推荐使用 Notepad++ 并开启「显示所有字符」，直观查看空格与制表符分布。

不可直接复制粘贴文本内容，会丢失行尾空白字符，必须使用原始文件进行解密。

提取结果为空时，优先追加-C参数重试，90% 空结果由未开启压缩模式导致。

少数题目将空白隐写于段落中间而非行尾，常规命令失效，需手动提取所有空格 / 制表符序列，转换为二进制后手动解码。

标准解题流程

**特征校验：** 用 Notepad++ 打开文本，开启显示所有字符，确认存在行尾空格与制表符；

**高频模式尝试：** 优先执行snow -C 目标文件提取数据；

**降级尝试：** 无结果则去掉-C参数，尝试无压缩模式提取；

**密码排查：** 仍失败则梳理题目线索，搭配-p参数尝试常见弱密码；

**手动兜底：** 自动工具全部失效时，提取全部行尾空白字符，转换为二进制序列后手动解码。
