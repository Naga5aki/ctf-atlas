## 适用场景

适合梳理浏览器与题目服务之间的请求、Cookie、跳转和接口调用。页面这里只列**分析方法**；本机目录是否能正常启动、扩展是否可靠，需自行核对实际安装。只连接本地题目或已授权环境。

## 01 保存真实请求

1. 在浏览器完成一次正常操作，同时在 **Proxy → HTTP history** 找到对应请求。
2. 记录方法、完整路径、目标主机、会话标识、请求体类型、响应码与 `Location`。
3. 将目标请求发送到 **Repeater**，先原样发送一次，确认能复现基线响应。

如果从历史中复制的请求已过期，先更新登录状态并记录新会话；不要把会话失效误判成权限拦截。

## 02 一次只改一个因素

| 本轮修改 | 想回答的问题 |
|---|---|
| 去掉认证头或 Cookie | 是否匿名可访问 |
| 更换同权限账户 | 数据是否与用户绑定 |
| 更换资源 ID | 服务端是否检查资源归属 |
| 改 `Content-Type` 或参数位置 | 服务端使用哪一套解析路径 |

每次保存“变更字段 → 响应差异 → 后端状态变化”。关注 Repeater 当前目标主机与端口；改了 `Host` 头并不保证请求真的发往该主机。含写入或删除的请求先用可恢复的测试数据，避免把题目环境状态改乱。

## 03 读结果而不是猜结论

`200` 可能是错误页，`302` 可能跳去登录页，`403` 也可能来自代理而非应用。比较响应体、长度、重定向和应用日志；写入类接口还应再次读取确认。只有当身份、资源、请求与结果都能对上，才写“授权检查通过/缺失”。

## 04 常用模块与快捷键速查

| 模块 / 操作 | 快捷键或入口 | 用途与核对重点 |
| --- | --- | --- |
| 发送到 Repeater | `Ctrl + R` | 单包手动重放，每次只改一个字段 |
| 发送到 Intruder | `Ctrl + I` | 枚举参数或测试边界值（先 `Clear §` 再只给目标参数加 `§`） |
| URL 编码 / 解码选中文本 | `Ctrl + U` / `Ctrl + Shift + U` | 在表单或查询串里安全编码 `&`、`=`、`+`、空格 |
| Base64 编码 / 解码 | `Ctrl + B` / `Ctrl + Shift + B` | 在 Repeater 编辑器内直接转换选中片段，无需切到 Decoder |
| 切换请求方法（GET ↔ POST） | 右键 `Change request method` | 核对框架是否混读 `$_REQUEST` 或只校验单一方法 |
| 导出原始请求供 `sqlmap -r` 使用 | 右键 `Copy to file` | 保存包含完整 Cookie 与请求头的原始报文 |

HTTPS 证书安装、Intruder 四种攻击模式次数计算与 `Grep - Extract` 动态令牌提取详见知识页 [Burp Suite](/knowledge/web-burp/)。
