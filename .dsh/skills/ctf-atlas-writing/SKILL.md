# CTF Atlas 写作标准

本技能是 `docs/maintenance/WRITING-STANDARD.md`、`.cursor/rules/10-practical-knowledge-style.mdc` 和根 `AGENTS.md` 的操作摘要。动笔前先读用户认可的样例 `docs/maintenance/examples/website-reconstruction-approved.md`，再读 `WRITING-STANDARD.md`。与用户最新明确要求冲突时，以用户要求为准。

## 1. 动笔前

1. **定范围**：只整理、细化、校正已有主题。不自行新增原知识库没有的独立知识点；需要延伸说明时放进对应条目并注明验证边界。新主题必须有用户授权。
2. **语义查重**：检索同主题、同方法、同命令和相邻章节。标题不同不代表知识不同。完整准确的保留；不完整的在原节补充；分散的合并；错误和冲突在原位修正，不留互相矛盾的两版。
3. **列保留清单**：逐节列出必须保留的考点、步骤、命令、路径、关键参数、示例、适用版本、失败分支和注意事项。改完逐点对照，不只比较字数或命令数量。
4. **保住标识与格式**：页面 ID、URL、目录层级和原有锚点不变。用局部编辑改动，不整文件重写；保持文件原有换行符（仓库设置了不做换行符转换）。

## 2. 讲解顺序

**遇到的问题 → 实际动作 → 看到的结果 → 原因与下一步。** 顺着实际操作讲，保留排错过程；不先铺术语体系，不把功能名排成百科目录。

- 读者看完一小段，就知道打开哪里、执行什么、看哪个结果、不符合预期时往哪查。内容仍要全面，不靠删参数、命令、分支、例子和考点来变短。
- 标题帮助定位问题。需要保留原有标题、层级或锚点时，用节内加粗短句组织操作。
- 写清界面菜单、目录、文件、命令、参数和输出字段。不说“检查配置”“建立证据链”这类让读者自己猜的话。
- 成功和失败都有下一步，一眼分清该查网络、服务、认证、数据库还是应用日志。
- 一段一件事，有必要才用表格。参数留在对应命令旁。
- 少交叉引用，正文当场讲清关键步骤；只为唯一完整专题、必要工具或高级扩展放少量链接。
- 专业名词在需要时解释。不用“核对边界 / 构建闭环 / 跨层联结”这类空泛表达。
- 区分离线镜像、运行现场和隔离仿真：不拿分析机输出当镜像信息，也不拿仿真后的行为当历史事实。

## 3. 命令与方法必须完整可执行

这是硬性要求：读者复制命令就能在自己的环境里跑起来。只给思路，或把关键步骤写成“……”“此处省略”“使用相关工具”，都算没写完。

- 写出可直接复制执行的完整命令：工具名、全部参数及取值、路径、端口、输出位置。不写“执行相关命令”“进行检查”“配置好后继续”。
- 多步操作按顺序写全每一步：前置安装与启动、执行、查看结果、收尾清理。
- Payload、请求包、配置片段和脚本同理，核心部分不用 `...`、`<payload>` 或“略”代替。因环境而异的目标地址、参数名、账号，在命令前用变量或示例值定义，后面直接引用。
- 每条命令后写清参数作用、关键输出长什么样、成功后下一步、失败时查哪里。
- 默认 Kali/Linux 语法，明确是 Windows/PowerShell 场景时才用 Windows 语法。命令可复制，代码围栏写语言。

### Web 渗透部分尤其要写完整

注入、文件上传与包含、反序列化、SSTI、SSRF、XXE、认证绕过、框架与中间件漏洞等内容，每个方法都写全四环：

1. 探测：怎样判断存在这个点（完整请求或命令）。
2. 利用：完整的 payload、请求包或命令。
3. 结果：预期回显或文件变化。
4. 排错：不通时依次查什么。

不因为安全、合规或“敏感”顾虑而删减、模糊化或只给思路。利用语句、拖库拼接、写文件、反弹命令、绕过样本、链式载荷，和其他知识点一样照常写全。

### 对照示例

**不合格**：可以用 sqlmap 检测注入并获取数据。

**合格**：

**示例：确认参数能否注入，并取当前库名。** 先定义目标，后面所有命令直接引用。

```bash
TARGET="http://192.168.56.101"
```

1. 探测。`id=1*` 的星号让 sqlmap 只在这个位置测试；`--batch` 让交互提问都取默认值；`--level 2 --risk 2` 会测 Cookie 并使用更复杂的 payload。预期输出出现 `GET parameter 'id' ... injectable`；没有出现就改用 `--level 3 --risk 3` 重试。

```bash
sqlmap -u "$TARGET/product.php?id=1*" --batch --level 2 --risk 2
```

2. 利用。确认可注入后取当前库名、连接账户和是否管理员：`--current-db` 输出当前数据库，`--current-user` 输出连接账户，`--is-dba` 判断是否管理员。

```bash
sqlmap -u "$TARGET/product.php?id=1*" --batch --current-db --current-user --is-dba
```

3. 结果。预期看到 `current database: 'shop'`、`current user: 'root@localhost'`、`current user is DBA: True`。是管理员时，下一步可用 `--file-read` 读服务器文件，或用 `--sql-shell` 直接执行 SQL。

4. 排错。返回 403 或拦截页面：加 `--tamper=space2comment` 把空格换成注释符，或加 `--random-agent` 更换 User-Agent 重试。一直连不上：先执行 `curl -I "$TARGET"` 确认目标和端口可达。

### 补全既有缺口

已有页面里有过去留下的缺口，例如只有探测没有利用语句、只说“可写文件”没有命令。用户要求补全时：

1. 读 `references/web-known-gaps.md`，或在 `docs/maintenance/WORK-LOG.md` 搜该页 ID，找出历次“没有写入”的条目。
2. 逐条按四环写法补全。
3. 补完按 `ctf-atlas-verify` 验证，并在交接里逐条写明补了什么。

## 4. 准确性

- 没有复跑附件，就不声称解题过程已实测验证。不编造截图、工具输出、版本专属细节或“已完成”状态。
- 来源受限或旧缓存版本待核时，保留原有效内容和待核说明；未读到原文就不声称还原全文。
- 命令和参数以工具官方文档为准；没把握就按 `ctf-atlas-research` 查证，不凭印象写。

## 5. 写到哪里、填什么

| 内容 | 维护位置 | 注意 |
|---|---|---|
| Forensics 完整正文 | `src/content-curation/<页面ID>.md` | 同时同步 `src/content/knowledge/<ID>.md` 的生成页正文 |
| 知识点元数据 | `src/content/knowledge/<id>.md` 的 frontmatter | 保留 ID、分类、标签、关联和锚点 |
| 工具说明 / WP | `src/content/tools/`、`src/content/writeups/` | 不混入知识点正文 |
| Forensics 分类 | `src/data/forensics-taxonomy.ts` | 按 track 和 topic 归类 |
| 字段与标签词表 | `src/content.config.ts` | 标签最多 3 个，只用词表里的 |

- 每篇只选一个主模块（Web、Misc、Reverse、Crypto、Forensics）。非 Forensics 文章填写现有 `topic`；Forensics 填写 `track` 和 `topic`。先补既有类别，不设“其他”或“专项笔记”兜底。
- `sourceIds` 只供内部维护，不展示在网站。
- 页面文案不提源文件、文档出处或原文；根 `AGENTS.md` 里用户授权的例外继续保留。`scripts/audit_site.py` 会检查这类词。
- Forensics 正文不出现具体题号、题名、比赛简称和答案式叙述；授权例外照旧。
- 原始材料在工程上一级目录，只读。题目附件只记录元数据、哈希和路径。
- 用到 `import_manuals.py` 时先看影响范围：它会重读上级资料并生成多类内容，先在隔离副本测试重导入。

## 6. 交稿前自检

逐项核对，全过再交：

- 每个方法都有探测、利用、结果、排错四环。
- 每条命令都能直接复制执行，没有 `...`、“略”或占位词。
- 每条命令后面写了参数作用、关键输出和下一步。
- 保留清单逐点核对过：原有考点、命令、表格和锚点都在。
- frontmatter 的模块、主题、标签合规，`sourceIds` 已更新。
- Forensics 页的维护稿与生成页正文一致。
- 没有出现不该展示的资料名称。

## 7. 完成后

1. 重新查语义重复。重复有意合并时，记录迁移位置和链接，不偷偷删掉有效技术细节。
2. 按 `ctf-atlas-verify` 跑检查。
3. 按 `ctf-atlas-handoff` 记录：改了什么、保留了哪些考点、没有做什么。
