# CTF Atlas 写作标准

本技能是 `docs/maintenance/WRITING-STANDARD.md`、`.cursor/rules/10-practical-knowledge-style.mdc` 和根 `AGENTS.md` 的操作摘要。动笔前先读用户认可的样例 `docs/maintenance/examples/website-reconstruction-approved.md`，再读 `WRITING-STANDARD.md`。与用户最新明确要求冲突时，以用户要求为准。

## 1. 动笔前

1. 定范围：只整理、细化、校正已有主题。不自行新增原知识库没有的独立知识点；需要延伸说明时放进对应条目并注明验证边界。新主题必须有用户授权。
2. 语义查重：检索同主题、同方法、同命令和相邻章节。标题不同不代表知识不同。完整准确的保留；不完整的在原节补充；分散的合并；错误和冲突在原位修正，不留互相矛盾的两版。
3. 列保留清单：逐节列出必须保留的考点、步骤、命令、路径、关键参数、示例、适用版本、失败分支和注意事项。改完逐点对照，不只比较字数或命令数量。
4. 页面 ID、URL、目录层级和原有锚点保持不变。

## 2. 讲解顺序

**遇到的问题 → 实际动作 → 看到的结果 → 原因与下一步。** 顺着实际操作讲，保留排错过程；不先铺术语体系，不把功能名排成百科目录。

- 读者看完一小段，就知道打开哪里、执行什么、看哪个结果、不符合预期时往哪查。内容仍要全面，不靠删参数、命令、分支、例子和考点来变短。
- 标题帮助定位问题。需要保留原有标题、层级或锚点时，用节内加粗短句组织操作。
- 写清界面菜单、目录、文件、命令、参数和输出字段。不说“检查配置”“建立证据链”这类让读者自己猜的话。
- 成功和失败都有下一步，一眼分清该查网络、服务、认证、数据库还是应用日志。
- 一段一件事，有必要才用表格。参数留在对应命令旁，风险留在对应修改前。
- 少交叉引用，正文当场讲清关键步骤；只为唯一完整专题、必要工具或高级扩展放少量链接。
- 专业名词在需要时解释。不用“核对边界 / 构建闭环 / 跨层联结”这类空泛表达。
- 区分离线镜像、运行现场和隔离仿真：不拿分析机输出当镜像信息，也不拿仿真后的行为当历史事实。

## 3. 命令与方法必须完整可执行

这是硬性要求：读者复制命令就能在自己的环境里跑起来。只给思路，或把关键步骤写成“……”“此处省略”“使用相关工具”，都算没写完。

- 写出可直接复制执行的完整命令：工具名、全部参数及取值、路径、端口、输出位置。不写“执行相关命令”“进行检查”“配置好后继续”。
- 多步操作按顺序写全每一步：前置安装与启动、执行、查看结果、收尾清理。
- Payload、请求包、配置片段和脚本同理，核心部分不用 `...`、`<payload>` 或“略”代替。因环境而异的目标地址、参数名、账号，在命令前用变量或示例值定义，例如先写 `TARGET=http://192.168.56.101`，后面直接引用。
- 每条命令后写清参数作用、关键输出长什么样、成功后下一步、失败时查哪里。
- 默认 Kali/Linux 语法，明确是 Windows/PowerShell 场景时才用 Windows 语法。命令可复制，代码围栏写语言。

### Web 渗透部分尤其要写完整

注入、文件上传与包含、反序列化、SSTI、SSRF、XXE、认证绕过、框架与中间件漏洞等内容，每个方法都写全四环：

1. 探测：怎样判断存在这个点（完整请求或命令）。
2. 利用：完整的 payload、请求包或命令。
3. 结果：预期回显或文件变化。
4. 排错：不通时依次查什么。

不因为安全、合规或“敏感”顾虑而删减、模糊化或只给思路。本站是授权环境下的学习与比赛知识库，内容面向示例和靶场。风险边界靠标注表达，不靠省略命令：会修改配置、账户、密码、服务或数据的操作，在命令前标【仅在副本/仿真/授权环境执行】，并写清保存原始配置或哈希的办法和回滚办法。

### 仍然成立的边界

下面几条是准确性要求，不是省略命令的理由：

- 不重复原题的固定答案（flag）和真实凭据；示例对象标明是示例。
- 没有复跑附件，就不声称解题过程已实测验证。不编造截图、工具输出、版本专属细节或“已完成”状态。
- 来源受限或旧缓存版本待核时，保留原有效内容和待核说明；未读到原文就不声称还原全文。
- 以往因上述顾虑留下的缺口（例如只有探测没有利用语句、只说“可写文件”没有命令），改到该页时补全；交接时不把这样的页面写成“已完整”。

## 4. 写到哪里、填什么

| 内容 | 维护位置 | 注意 |
|---|---|---|
| Forensics 完整正文 | `src/content-curation/<页面ID>.md` | 同时同步 `src/content/knowledge/<ID>.md` 的生成页正文 |
| 知识点元数据 | `src/content/knowledge/<id>.md` 的 frontmatter | 保留 ID、分类、标签、关联和锚点 |
| 工具说明 / WP | `src/content/tools/`、`src/content/writeups/` | 不混入知识点正文 |
| Forensics 分类 | `src/data/forensics-taxonomy.ts` | 按 track 和 topic 归类 |
| 字段与标签词表 | `src/content.config.ts` | 标签最多 3 个，只用词表里的 |

- 每篇只选一个主模块（Web、Misc、Reverse、Crypto、Forensics）。非 Forensics 文章填写现有 `topic`；Forensics 填写 `track` 和 `topic`。先补既有类别，不设“其他”或“专项笔记”兜底。
- `sourceIds` 只供内部维护，不展示在网站。
- 用户可见的页面文案不提源文件、文档出处或原文；根 `AGENTS.md` 里用户授权的例外继续保留。`scripts/audit_site.py` 会检查这类词。
- Forensics 正文保持独立实用，不出现具体题号、题名、比赛简称和答案式叙述；授权例外照旧。
- 原始材料在工程上一级目录，只读。题目附件只记录元数据、哈希和路径，不执行 ZIP 内程序。
- 不盲跑全量 `import_manuals.py`：先看影响范围，在隔离副本测试重导入，不覆写人工整理。

## 5. 完成后

1. 重新查语义重复。重复有意合并时，记录迁移位置和链接，不偷偷删掉有效技术细节。
2. 按验证技能 `ctf-atlas-verify` 跑检查。
3. 按交接技能 `ctf-atlas-handoff` 记录：改了什么、保留了哪些考点、没有做什么。
