## 主要技术校正

| 易错说法 | 最终采用的解释 |
| --- | --- |
| MFT 属于任何 U盘 | 当前 MFT 属于 NTFS 卷；FAT32/exFAT 使用自己的目录项与分配结构，旧 NTFS 残留单独分析 |
| runlist 中 LCN 是扇区、位移相对上一段末尾 | LCN 是卷内簇；字段长度由首字节拆分，簇数量无符号、位移有符号，相对上一段有物理位置 run 的起始 LCN |
| `n×1024` 总能从卷上的 MFT 起点直接定位 | 这是 MFT 逻辑流中的记录偏移，映射到镜像还需该流 runlist、实际记录大小与分区字节起点 |
| 只看到 FILE 签名就表示结构有效 | 还要检查 USA、尺寸、有效区、属性边界、引用和映射；已 fixup 视图不能再次当原始盘上字节校验 |
| SI/FN 时间不一致必然篡改 | 两组时间语义和更新机制不同，必须结合操作、版本、日志与文件引用；FN 不是永不更新的原始时间 |
| 删除记录头序列号与工具历史键必须直接相同 | 释放时头部可能递增，工具可使用历史身份键；核对原始字节、工具定义与事件，不盲目加减或跨代际配对 |
| 硬件序列号、卷序列号、GUID、盘符互相等价 | 属于不同身份域；LNK 卷序列字段与 NTFS 字段宽度也不同，应说明比较位数和关联依据 |
| 设备属性 Arrival 等于每次物理插入 | 安装、首次安装、到达/重新枚举与移除分别解释；缺记录不证明行为未发生，6416 的 SYSTEM SID 不直接指向操作者 |
| XFW ID、Int. ID 和 MFT FRN 是同一编号 | 分开目录/文件系统身份、快照内部对象编号与记录号/序列号；Details、结构位置与原始字节相互核对 |
| XFW 模板完整处理 USA | 已核对的 20.1 随附模板声明不处理 fixup，推进相邻记录也有错位限制，不能替代结构核验 |
| MFTECmd `--do` 直接照帮助输入字节偏移 | 本机 2026.5.0 实测：`--do 42` 导出槽 42 的 1024 字节；`--do 0xa800` 返回零字节输出，虽显示成功并退出 0 仍是导出失败 |
| `--recover` 是 MFTECmd 恢复参数 | 此版本拒绝该参数，stderr 有错误但退出码仍为 0；用实际输出及字节核对验证，不只检查退出码 |
| CSV ReferenceCount 就是 FILE 头硬链接计数 | 本版来自去重后的非 DOS 名称/父引用组合；保留原始头字段与各名称/流分别复核 |

## 练习与实测

`public/practice/usb-forensics/` 提供 46,080 字节 MFT 记录流、240 字节 USN V2 记录流、README 与 manifest。45 个 MFT 槽中有效记录为 0、5、24、42、43、44。Docs 用普通用户槽 24，根引用为 5-5；头部记录号与实际槽位一致。构造材料与正文中 `evidence.txt` 的孤立字节示例是不同练习，不能混用序列号和名称。

MFTECmd 本机版本 2026.5.0，签名状态 Valid，签名主体 ZimTech LLC；程序 SHA-256 为 `0b6deda2f7b147dc8d1efdfa3ae77f9e6570a91a5d78e5f03d8711bb4273e51b`。17 组正向 CLI 检查与 23 项内容断言通过；另有两种预期失败行为：字节偏移式 `--do` 产生空输出、未知 `--recover` 被拒绝。记录导出与输入槽 42 的 1024 字节逐字节相同。根任务使用正式发布练习重新解析，确认 9 行 MFT CSV、3 行 USN CSV、父目录 24、UTC 偏移和同对象多个名称/流行。

正文的四个 FILETIME、FRN 位拆分、常驻值边界和负位移/稀疏 runlist 有独立计算核对。另核对一个 100ns 精度向量。非驻留映射仅指向虚构簇，构造件不是完整 NTFS 卷，不含可验证的全部索引/位图/磁盘数据；不能用它宣称真实 U盘文件恢复成功。MFTECmd 的 SDS、VSS 和真实镜像恢复未实测。XFW 仅核对文档、此前读取到的 20.1 版本与模板，没有 GUI 复跑。
