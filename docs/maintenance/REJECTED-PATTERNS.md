# 退回写法登记（反例集）

本文件收集**被用户明确退回或项目规范明确不采用**的写法，供动笔前对照。与 `WRITING-STANDARD.md` 的正例配套：正例说明该怎么写，本文件说明哪些写法会被退回。

## 使用方式

1. 动笔前读最近 10 条（编号最大的 10 条），写完按条自检。
2. 用户退回一处写法时，追加一条，写清原文片段、问题、改法、来源批次。
3. 只登记真实发生过的退回，或项目规范里明确写出的“不采用”写法；不要虚构用户意见。
4. 同一问题反复出现时，把结论提炼进 `WRITING-STANDARD.md` 或写作技能，不只留在本文件。

## 条目

### R-001 空泛闭环句

- 反例：`依据技术栈核对部署边界，联结Web配置、后端运行时和数据层，形成环境恢复与证据验证闭环。`
- 问题：读者不知道要看哪个文件、执行什么命令、怎样判断完成。
- 改法：改成“网站打不开，先看源码是什么项目”，然后写清目录、入口文件、判断依据和下一步分支。
- 来源：`WRITING-STANDARD.md`「不采用的写法」。

### R-002 只给思路，不给可执行命令

- 反例：`可以用 sqlmap 检测注入并获取数据。`
- 问题：缺目标、参数、预期输出和失败分支，读者无法复现。
- 改法：定义 `TARGET`，写出带 `--batch --level 2 --risk 2` 的完整命令，并写清预期回显与排错方向。
- 来源：写作技能「对照示例」的不合格样例。

### R-003 用省略号或占位符代替关键步骤

- 反例：`执行相关命令后，修改配置文件，然后继续利用。`
- 问题：命令、参数、路径、payload 全部缺失，等于没写。
- 改法：逐条写出完整命令与参数取值；payload 用完整请求包，不写 `<payload>` 或 `...`。
- 来源：`WRITING-STANDARD.md`「不采用的捷径」与写作技能第 3 节。

### R-004 结构解释句与固定收尾章节

- 反例：`这页把 Web 注入分成原理、利用和防御三部分，最后做训练与记录。`
- 问题：元叙述占篇幅，读者拿不到操作信息；固定“防御/修复/训练与记录”章节是模板残留。
- 改法：直接进入“遇到的问题 → 实际动作 → 看到的结果”；删除防御、修复、训练与记录等固定章节。
- 来源：`WORK-LOG.md` 2026-10-29「Web 模块全量按模板改造」条目。

### R-005 Forensics 正文出现题号、题名或答案式叙述

- 反例：`本题是 2023 年某某杯的 Android 取证题，答案是 /data/data/com.example/。`
- 问题：违反 Forensics 独立实用写法，把内容写成题目解析。
- 改法：写场景、材料、证据位置、操作命令、结果判读、验证与限制；不出现具体赛事与固定答案。
- 来源：`AGENTS.md` Forensics 条目。

### R-006 用批量替换冒充整模块完成

- 反例：`已统一替换为“副本”一词，全部页面完成改写。`
- 问题：只改词不改内容，考点、命令和分支没有核对。
- 改法：按保留清单逐节对照，在 WORK-LOG 写清每页改了什么、保留了哪些考点、没做什么。
- 来源：`WRITING-STANDARD.md`「不采用的捷径」。

### R-007 把构建通过当成内容正确

- 反例：`构建 0 错误，所以这页内容没问题。`
- 问题：构建只证明语法和页面生成，不能证明命令可执行、结论正确、考点齐全。
- 改法：分三层报告：语法检查、合成验证、真实检材复跑；没有复跑就写“未复跑”。
- 来源：`WRITING-STANDARD.md`「始终保留的技术判断」与验证技能第 5 节。

### R-008 编造工具输出、截图或版本细节

- 反例：`执行后输出如下：` 后面跟着没有实际运行过的结果。
- 问题：属于编造证据，违反准确性要求。
- 改法：贴真实运行输出；没跑就写“预期输出”并说明依据；版本不确定就标“待核”。
- 来源：`AGENTS.md` 第 11 条与写作技能第 4 节。
